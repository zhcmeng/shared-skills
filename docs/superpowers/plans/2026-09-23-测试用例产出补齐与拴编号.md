> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `test-case-design` 技能的产出契约补上「重置需求」一栏，并让测试数据、测试环境两份需求与测试用例、测试规程之间靠编号拴起来，自检脚本能查出悬空引用与孤儿。

**Architecture:** 契约的唯一依据是 `references/文档模板.md`，`scripts/check_docs.py` 从它派生要查的栏与校验。所以先改模板（人读的契约），再让脚本跟上并补测试，最后对齐示例与流程说明，收尾做端到端验收并抬版本号。产出本身不回填——用户会基于改好的技能重新生成。

**Tech Stack:** Markdown 文档 + Python 3 标准库（自检脚本只用标准库）。

**Spec:** `docs/superpowers/specs/2026-09-23-测试用例产出补齐与拴编号-design.md`

## Review Focus

以下是本技能的产出与自检脚本最可能咬到人的几种情况。判据是「这么做的人会以为没问题」。每条都在对应的任务里配了测试。

1. **项目按自己的惯例编号（`DBR-1`、`E-1`），而不是 `DATA-1`、`ENV-1`。** 文档模板第二节明说「项目已有编号惯例就跟随惯例」，`文档示例.md` 里那份示范用的就是 `DBR-1`、`E-1`。但 `check_docs.py` 按前缀 `DATA-`／`ENV-` 认定义处，遇到别的编号会报「一个 DATA- 编号都没有」。跟着示例学的人会以为能过，实际过不了。本计划不改编号方案（spec §7 划在范围外），改为：在 `文档示例.md` 的注里点明这份编号是原例自己的惯例、本技能默认用 `DATA-…`／`ENV-…`，并在 Task 2 加一条测试把这个边界固定下来。
2. **产出的数据项确实不需要复位，那一格写什么。** 模板要求「不要复位的写『不需要』」，脚本要求每格非空。写「无」「-」「N/A」也判过（只要不是空字符串），但写空会被逮住。Task 2 的测试覆盖「写『不需要』判过」与「留空报错」两头。
3. **引用写在「预期结果」栏里（如「应输出 DATA-1 的内容」）。** 按 Task 2 的实现，`DATA-` 编号只要出现在用例规格说明或规程规格说明里就算引用，孤儿判定不会误报。这是有意的宽口径——真正的引用位置由模板管，脚本只管「指得到」。Task 2 Step 1f 的「引用的编号写在「预期结果」栏里，也算引用，不误报孤儿」这一例按的就是它（用 `!` 断言那句提示不出现）。
4. **只写了用例规格说明、没写规程规格说明，或反过来。** 这时孤儿判定整块跳过（缺的那份已经有硬错误），不会因为「没人引用」而刷一屏提示。Task 2 Step 1f 的「只写了规程、没写用例规格说明——两份引用文档缺一份，孤儿判定整块跳过，不刷屏」这一例按的就是它。
5. **一条数据项定义了、用例也引了，但引错了对象（写 `DATA-3` 实际想要 `DATA-4`）。** 编号指得到定义处，脚本查不出内容对不对。这是判断项，配不了测试；Task 2 Step 9 在脚本的模块注释里把它点名成「脚本报不了」的那一类，另外四条在 Review Focus 里也各自有一例。

```python
    """一份文档里出现的某个前缀的编号集合——出现过就算，不区分它在哪一栏。"""
    return {int(n) for n in re.findall(re.escape(prefix) + r"(\d+)", text)}


def check_refs(text, rep, name, known):
    """文档里出现的编号都要指得到定义处。

    known：{"DATA-": {编号}, "ENV-": {编号}}。用例与规程这两份都可能引到数据项
    与环境项，所以两个前缀都查。引了却不存在的，模型查不到就会编——算错误。
    """
    for prefix, ids in known.items():
        for n in sorted(referenced(text, prefix) - ids):
            rep.err(name, "引用了没有定义处的 %s%d" % (prefix, n))
```
