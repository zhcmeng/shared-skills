## Review Focus

技能交出去之后，下面五种情况最可能出问题。每条都钉到具体任务的检查步骤里：

1. **用户没给测试完成准则，模型自己编一个**——这是最危险的一种，编出来的准则会让整套覆盖率自检失去意义。钉在 Task 11（自检流程）与 Task 13（第 0 步的措辞与试跑）。
2. **模型顺着引用去找标准原文**——本仓库存着 1.3 万行草案，翻进去既爆上下文又可能跟着转换缺陷走。钉在 Task 13（自包含声明）与 Task 15（全库 grep）。
3. **用户点名要 7 门之外的技术，模型拿 7 门里的一个顶替**——顶替是静默的，用户看不出来。钉在 Task 12（换用告知条目）与 Task 15（试跑第二例）。
4. **覆盖率不到 100% 时，模型下调要求而不是剔除不可行项**——下调要求等于把完成准则改了。钉在 Task 11。
5. **模型自创文档格式而不套模板**——产出跟模板对不上，模板就白写了。钉在 Task 1（模板的强制性措辞）与 Task 15（试跑核对字段）。
