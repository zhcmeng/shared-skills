# skill-up v0.14.0 同步与使用/维护分离 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `test-case-design` 技能里的 skill-up 参考文档同步到 v0.14.0，把全部维护动作搬到 `plugin/` 外的维护者文档，并在 `SKILL.md` 补上「异常处理」一节。

**Architecture:** 只改文档与两个版本号文件。`plugin/skills/test-case-design/` 下只留使用者做得到的事；回写、重核、版本更新、文件地图移到 `docs/maintainers/test-case-design.md`。版本自查写在文档里：使用前跑 `skill-up --version` 与 `usage-notes.md` 顶部的版本行比，不一致就把文档当历史版本用、产出标「待确认」。`checks/` 里不加这段比对。

**Tech Stack:** Markdown、Bash（只用于探针跑测与检查命令）、Python 3（三个脚本不改）。

**Spec:** `docs/superpowers/specs/2026-11-03-skill-up版本升级同步-design.md`

## Global Constraints

- `plugin/` 下不出现这些字样：维护、维护者、回写、重核、已核过、版本更新、文件地图、怎么更新；也不出现 `docs/maintainers/` 路径。
- 不引上游源码文件名、函数名、行号；不引 `C:\Study`、`runs\`、`evals/<批>/`、`xlsx/`、`.claude/evals/`、公网文档站 URL、GitHub 上的 CHANGELOG 与 release。
- 依据只有两类：`~/.claude/skills/skill-upper/references/*.md`（写文件名与小节名）与 CLI 实跑（写 `（YYYY-MM-DD 实测，skill-up vX.Y.Z）`）。
- `usage-notes.md` 顶部版本行固定为 `**对着的版本：skill-up v0.14.0（2026-10-20）**`；本机 `skill-up --version` 输出 `skill-up version 0.14.0`。
- 只支持 `engine.name: claude_code`；其他引擎不在支持范围内。
- 三个脚本要 Python 3，不需要第三方库；这条只在「异常处理」表里讲，**不新设「前置条件」一节**，正常流程不提、不做预检，`python`／`python3` 按机器写法（Windows 上可用 `py -3`）。
- **不在 `checks/` 里加版本比对**：维护者自己发起升级，知道自己装的版本；版本自查只写在文档里（`usage-notes.md` 顶部、`SKILL.md` 两处、`skill-up/README.md`），不一致就按历史版本用、产出标「待确认」。
- 不新增评测；探针只放 `.tmp/skill-up-probe/`，跑完删掉，不入库。
- 改文件一律先 Read 再 Edit／Write，不用 Bash 重写文件。
- 插件版本从 `1.29.1` 抬到 `1.29.2`，`plugin/.claude-plugin/plugin.json` 与 `.claude-plugin/marketplace.json` 两处必须一致。
