# 测试用例指南技能 — 体例基准

**这份文件管什么**：`skills/test-case-design/references/技术/` 下七份技术文件必须一致的那些写法——五节标题、各节首句句式、覆盖率一节怎么起头、算例里编号怎么用、术语口径、零引用检查命令。

**为什么要单独一份**：这七份由七个独立的任务写，每个任务的执行者（子代理）只拿到自己那一段任务文本，读不到计划开头。体例基准写在计划里，执行者就看不到；写成独立文件，每个执行者都能按同一条路径读到。

**谁读它**：
- 写技术文件的执行者——动手前先读这份，再读样板文件
- 独立评审子代理——每次评审都读，用来逐项比对
- 终检时横比七份文件——也按这份基准判

**样板文件**：`references/技术/等价类划分.md`（Task 2 产出，已完成）。七份的第二、三、四节按它的实际写法定型，第一节与第二节已按它的实际写法回填核对。

**定稿进度**：

- 第一节（五节标题）、第二节（各节首句句式）、第三节（覆盖率写法）、第四节（编号用法）、第五节（术语口径）、第六节（检查命令）：**已定稿**，照写
- 第二节那五句已用样板文件的实际首句逐句回填核对：五句完全一致，表未改。另外把各节的骨架细节也按样板的实际写法写进去了（见第二节第 6 条）

## 一、五节标题（固定不移）

七份技术文件都是这五节：

```
# <技术名>

## 一、测试模型
## 二、测试覆盖项
## 三、导出测试用例
## 四、覆盖率
## 五、算例
```

规矩：

- 中文序号「一、二、三、四、五」照写，不用阿拉伯数字，不用「1.」
- 五节缺一不可，也不另加第六节
- 顺序固定：模型 → 覆盖项 → 用例 → 覆盖率 → 算例
- 每份文件只有一个一级标题（`#`），就是技术名本身
- 技术名用标准中文原词：等价类划分、分类树方法、边界值分析、判定表测试、状态转移测试、场景测试、组合测试

自检：`grep -c "^## " 文件` 应当输出 `5`。

---

## 二、各节首句的句式

每节第一句话要说清"这一节讲的是这门技术的什么"。七份的角度必须一致——同一个位置，主语和谓语的形式一样，只换技术名和该技术的具体内容。

### 1. 「一、测试模型」的第一句

用「是」定义这门技术的模型是什么。

| 文件 | 第一句 | 模型的构成 |
|:---|:---|:---|
| 等价类划分 | 等价类划分的测试模型是等价类，分有效等价类与无效等价类两种。 | 等价类；可用图形或纯文本表示 |
| 分类树方法 | 分类树方法的测试模型是分类树，由分类和类别两层构成。 | 根是被测项，下一层是分类，分类下是类别 |
| 边界值分析 | 边界值分析的测试模型是带边界的等价类。 | 先划等价类，再标出每个类的边界 |
| 判定表测试 | 判定表测试的测试模型是判定表，由条件桩与条件项、动作桩与动作项组成。 | 条件桩与条件项、动作桩与动作项构成表格 |
| 状态转移测试 | 状态转移测试的测试模型是状态图或状态表。 | 状态、转移、事件／条件 |
| 场景测试 | 场景测试的测试模型是交互序列。 | 贯穿测试项的工作流，以交互序列表示；含主场景与备选场景 |
| 组合测试 | 组合测试的测试模型是参数取值表。 | 每个参数有哪些取值 |

规矩：

- 句式固定为「〈技术名〉的测试模型是〈模型名〉」再接一句补充
- 动词只用「是」，不用「包括」「可以表示为」「指的是一种」这类说法
- 补充句不长于一行的，接在同一段里，不另起一段

### 2. 「二、测试覆盖项」的第一句

用「是」定义覆盖项是什么，并在本节写清这门技术覆盖到什么程度。

| 文件 | 第一句 | 覆盖程度 |
|:---|:---|:---|
| 等价类划分 | 等价类划分的测试覆盖项是等价类，每个等价类都识别为一个测试覆盖项。 | 没有档位，要求全面覆盖所有等价类 |
| 分类树方法 | 分类树方法的测试覆盖项是类别的组合。 | 两档：最小化／最大化 |
| 边界值分析 | 边界值分析的测试覆盖项是边界值。 | 没有档位，要求全面覆盖所有边界值；识别覆盖项用二值边界测试或三值边界测试两种方法之一 |
| 判定表测试 | 判定表测试的测试覆盖项是规则，即判定表的每一列。 | 没有档位，要求覆盖所有有效（可行）规则 |
| 状态转移测试 | 状态转移测试的测试覆盖项是状态与转移。 | 四档：全状态／0-switch／全转移／N-switch |
| 场景测试 | 场景测试的测试覆盖项是场景，分主场景与备选场景。 | 没有档位，要求覆盖主场景和备选场景 |
| 组合测试 | 组合测试的测试覆盖项是参数的取值组合。 | 四档：完全组合／成对／单一选择／基本选择 |

规矩：

- 句式固定为「〈技术名〉的测试覆盖项是〈覆盖项名〉」
- 覆盖程度有档位的（分类树方法、组合测试、状态转移测试），档位在本节逐一列出并写清各自算什么，档位名照标准原文用词；再加一句：取哪一档由测试完成准则与风险级别决定
- 覆盖程度没有档位的，照上表那一格写，不要另立档位
- 「每个〈覆盖项名〉都应识别为一个测试覆盖项」这类平行句，**只在源文确有此句时才写**（等价类划分那门有，所以样板里有）。源文没有的，别照着样板补一句——补出来就是源文里查不到的一条要求。本节的必写内容只有两项：首句的定义、这门技术的覆盖程度
- 组合测试那份多一处用词要交代：源文定义处（5.2.5／6.2.5）的正式用词是「**P-V 对**」——参数（P）与它的一个取值（V）构成的配对，定义就写在 5.2.5.2；附录算例里又写成「参数-值对」。**产出全份统一用「P-V 对」**，并在第一次出现时就地给一句中文解释，算例里源文写「参数-值对」的地方一并统一过来。首句的〈覆盖项名〉仍照上表写「参数的取值组合」（平白说法），紧接着那句 P-V 对的解释把两者的关系说清
- 同理，源文附录里偶尔残留「测试条件」这类已被这一版弃用的词（组合测试算例里有一处）。**产出里不出现弃用词**，按语义顺成技能已确立的说法，不添新信息
- 这一节只说覆盖项与覆盖程度，导出的步骤是下一节的事

### 3. 「三、导出测试用例」的第一句

固定用这一句起头：

```
导出测试用例应遵循以下步骤：
```

规矩：

- 后面接的步骤按原文写：条数、序号照原文，意思不改
- 源文别处的说法别顺手统一：原话写「宜」的别改成「应」，原话写「可」的别改成「要」，也别反过来。这三个字不是硬要求，是照原文写下来自然就成了
- 源文啰嗦的虚词、重复词可以删，句子拗口（明显是转换出错）可以按语义顺，**不添源文没有的词，不改任何一条的意思**。做了这些不必逐条登记
- 步骤原文里有的注释（「注：」开头的那些）照收，位置不动。注里若指向别的技术（原文写的是章节号），把章节号换成技术名并给相对路径链接，如 `见[组合测试](组合测试.md)`——零引用是硬约束，这一步不能照抄；换了之后注的位置与内容都不动
- 这一节末尾附该技术的选值纪律（如无效用例用「一对一」方式、有效用例用「最小化」方式），只在标准对该技术写了这一条时才写
- **有档位的技术，源文若各档各有自己的一组导出步骤，就按档位分组照抄**（组合测试四档、状态转移测试四档都是这样）：一档一组，不把几档的步骤并成一组，也不拿一档的步骤去顶另一档的。固定首句「导出测试用例应遵循以下步骤：」写在最前面一次，各档的组头用该档的档位名

### 4. 「四、覆盖率」的第一句

固定用这一句起头：

```
覆盖率按 C＝N÷T 计算，三个量在这门技术里各指什么如下：
```

规矩：

- 三个量一个不少，顺序固定为 C、N、T
- 每个量单独一行，用「——」起头
- 写作 `——C` / `——N` / `——T`，不写成「C 为」「其中 C」
- 量名照原文：N 与 T 的定义在这门技术里说的是「测试覆盖项」还是「等价类」「规则」这类，照原文那份说
- **有档位的三门（分类树方法、组合测试、状态转移测试），C／N／T 按档位分组写**：每档先一句引导句再列 C／N／T，一档一组，**不要把几档并成一条**。档位名并进 C 的量名（照源文写法，如「C 分类树_最小化」「C 完全组合」「C 全转移」）。**引导句三门各不相同，照各自的原话写，不拉平、不简写**：
  - 分类树方法：「对于最小化组合覆盖率，应按以下定义计算：」「对于最大化组合覆盖率，应按以下定义计算：」
  - 组合测试：「完全组合测试的覆盖率应按以下定义计算：」「成对测试的覆盖率应按以下定义计算：」「单一选择测试的覆盖率应按以下定义计算：」「基本选择测试的覆盖率应按以下定义计算：」
  - 状态转移测试：「全状态测试的覆盖率应使用以下定义计算：」「单步转移（0-switch 覆盖）的覆盖率应使用以下定义计算：」「全转移的覆盖率应使用以下定义计算：」「N+1 步转移（N-switch 覆盖）的覆盖率应使用以下定义计算：」
  **「取哪一档由测试完成准则与风险级别决定」这句写在第二节**（见上一节第 2 条的规矩），第四节不重复——第四节只列 C／N／T 与各档要求

### 5. 「五、算例」的第一句

句式固定为「下面的算例完整走一遍从〈起点〉到〈终点〉的过程。」——七份的起点终点一样，所以这一句七份相同：

```
下面的算例完整走一遍从测试依据到覆盖率的过程。
```

规矩：

- 这一句之后，算例正文按「测试依据 → 测试模型 → 测试覆盖项 → 测试用例 → 覆盖率」的顺序分段，段的先后不换
- 算例里的数字（覆盖项条数、用例条数、覆盖率百分数）要能算通：数对不上就是抄错了

### 6. 骨架的其他细节（表里没规定的，照样板定型）

这五条由样板文件定型，Task 3–8 照写，不再各自发挥：

- **模型表示法不限**：源材料里如果配了示意图，图未必在这批转换产物里（样板那份就没有）。图缺了就用纯文本表格表示，并在第一节写明"可以用图形表示，也可以用纯文本表示"——两种表示都合规，不因此改动模型内容
- **算例内部用 `###` 分五段**：`### 测试依据`、`### 测试模型（TM-1）`、`### 测试覆盖项`、`### 测试用例`、`### 覆盖率`。一级标题只有技术名一个、`##` 只有五节，`###` 只出现在算例里
- **覆盖项清单**：先一句说明清单从哪来，再一行一条 `- TCOV-n：<覆盖项的描述式写法>`；同一小类下分组时，用源文的小节名当标签
- **用例表**：一例一行（源文的表若是转置的就转回来），列序为 `用例编号｜输入｜测试覆盖项｜被测等价类或对应项｜预期结果`，中间的计算列照源文保留；源表里没有的格子写 `-`，并在表前一句话说明变量含义与 `-` 是什么意思（**`-` 到底指什么按各文件的实际情况写**，别照抄别处的释义——边界值分析那份是「输入或结果无法用 16 位表示」，不是笼统的"没有值"）；**列头用本文件已确立的名**——输入栏照第一节模型里的分类名写（如「输入（膳食偏好）」），不照抄源文表头里的另一个叫法。这条只管我们自己重建的表头；源文的取值与正文里的说法仍各按原处引，不拉平
- **覆盖率段收尾一句**照实算，写法固定为：`已识别的<覆盖项名>总数量 T＝<数>；<用例条数> 条测试用例覆盖到的<覆盖项名>数量 N＝<数>；覆盖率 C <C 的量名>＝N÷T＝<数>÷<数>＝<百分数>。`（有档位的三门按档位各写一句；<覆盖项名>照该技术的原文用词；**C 后面带上第四节那行的量名**，如 `C 等价类`、`C 判定表`、`C 完全组合`——源文各技术的 C 行本来就带量名，写成光秃秃的 `C＝N÷T` 是本技能自己简化出来的，别用）

## 三、覆盖率一节怎么写

「四、覆盖率」这一节内部结构固定为三段，顺序不换：

1. **第一句**——见上一节第 4 条，七个量名照原文。**C 的量名照源文带上**：源文写 `C等价类`、`C 边界值`、`C 判定表`、`C 完全组合`，产出就写 `——C 等价类是等价类的覆盖率；`、`——C 判定表是判定表测试的覆盖率；`，不简写成 `——C 是……`。这个量名同时是算例收尾句里用的那个（见第二节第 6 条）
2. **要求**——这门技术要求覆盖到什么程度。全覆盖的写"要求全面覆盖……"；有档位的先写一句「覆盖率要求有档位，分为以下几档：」再逐档列出，档位名照原文
3. **与算例的衔接**——不另写一段，算例里的覆盖率数字在第五节给出，本节不重复算

规矩：

- 覆盖率公式七份统一写作 `C＝N÷T`（全角等号、除号），不写成 `C = N / T`、`N/T` 这类
- 不复制源文件里那行残缺的公式（源文件的公式本体在转换时丢了，只剩一个 `C=`）
- 有档位的三门（分类树方法、组合测试、状态转移测试），档位名照原文：最小化／最大化、完全组合／成对／单一选择／基本选择、全状态／0-switch／全转移／N-switch，不自造"精简／完整"这类替代说法
- 本节只讲这门技术自己的 C／N／T 与要求，不写"够不够"的判法——那是 `覆盖率与完成准则.md` 的事

## 四、算例里编号怎么用

编号方案来自 `文档模板.md`（Task 1 产出），七份统一：

| 对象 | 编号 | 在算例里怎么用 |
|:---|:---|:---|
| 测试模型 | `TM-1`、`TM-2`… | 算例里有多个模型时逐个编号；只有一个也写 `TM-1` |
| 测试覆盖项 | `TCOV-1`… | 算例的覆盖项清单里逐条编号，连号不断 |
| 测试用例 | `TC-1`… | 算例的用例表里逐条编号，连号不断 |
| 测试规程 | `TP-1`… | **技术文件里不出现**——规程排序不在技术文件范围内 |
| 测试数据项 | `DATA-1`… | 技术文件里一般不出现；算例要提测试数据时用这个写法 |
| 测试环境项 | `ENV-1`… | 同上 |

规矩：

- 编号用半角连字符加阿拉伯数字：`TCOV-1`，不写成 `TCOV_1`、`TCOV1`、`TCOV-01`
- 七份里同一个对象的编号写法必须一致，不出现别的写法
- 算例之外的节（一、二、三节）提到覆盖项或用例时用通用称呼（"每个等价类""每条测试用例"），不带编号——编号只属于算例
- 算例里引用别的对象的编号时照写全，如"覆盖 TCOV-3 的用例是 TC-2"
- **组合测试的算例里另有 `PV-1`…`PV-8` 这类编号**，给模型元素 P-V 对用（源文附录自己也给它们编了号，写成 `PV1`）。`PV-` 不在 `文档模板.md` 的编号方案表里，这不是漏项——那张表管的是五份产出文档里的对象，P-V 对是技术内部的模型元素，只在这份算例里出现。**它算算例内部的记法**，写法照样板的规矩（半角连字符加阿拉伯数字），终检横比七份时不算"另立编号"

## 五、术语口径

不建术语表——通用含义模型已经知道。这里记的是**标准用专有用法、与业界常见说法不同**的那些词：训练数据里更常见的恰恰是错的那个，七个执行者各写各的就会各错各的。

| 标准要求 | 容易写成 | 为什么 |
|:---|:---|:---|
| 测试模型 | 测试条件 | 这一版明确弃用了「测试条件」这个说法，改用它。两个词只差一个字 |
| 测试依据 | 测试的证据、测试数据 | 它是设计用例所依据的信息源（需求、规格说明、模型、用户需求） |
| 测试项 | 测试用例、被测对象 | 指被测的那个东西 |
| 测试覆盖项 | 覆盖点、覆盖目标 | 指模型里要被覆盖的那个元素 |
| 测试规程 | 测试脚本、测试流程 | 指用例的执行顺序，加启动与收尾动作 |
| 测试用例规格说明 | 测试用例文档 | 它是正式的文档名 |
| 应／宜／可 | 统写成"要" | 顺手把这三个字改成"要"，会把原话的语气带偏 |
| 有效测试用例／无效测试用例 | 正确用例／错误用例 | 导出方法那组术语的固定说法 |
| 一对一方式／最小化方式 | 逐条方式／最少用例方式 | 同上，指选择测试覆盖项组合的两种方法 |

规矩：

- 七份都用左列的说法，右列一个都不许出现
- 标准里的中文原词照用；需要解释的地方用一句白话补在后面，不替换原词
- 不造词。不确定某个说法是不是原文时，回源文件核，不自己造一个更通顺的
- 除词之外，「取／值」「覆盖／被覆盖」这类说法也照原文，别顺手换成更常见的用法

### 写法有出入怎么办

删减、顺句这类字符级出入不必登记，也不必回源文逐字核。一条就够：**不添源文没有的词，不改任何一条的意思**。

## 六、零引用检查命令

每份技术文件写完后跑一次，评审时再跑一次。两项都要过。

```bash
cd /c/work/shared-skills/skills/test-case-design && \
grep -nE "38634|29119|GB/T|ISO/IEC|征求意见稿|附录 ?[A-Z]|表 ?[A-Z]\.[0-9]|B\.2\.[0-9]|5\.2\.[0-9]|6\.2\.[0-9]" references/技术/<技术文件名>.md
```

期望：无输出。

再查指路措辞：

```bash
cd /c/work/shared-skills/skills/test-case-design && \
grep -nE "详见|参见|参考标准|原文|该标准|标准中" references/技术/<技术文件名>.md
```

期望：无输出。

规矩：

- 标准名称、章节号、条款号、附表号一概不出现——技能文件零引用
- 也不写「详见」「参见」这类指向标准原文的指路措辞
- 文件之间互相引用不受此限，用相对路径链接：`[文档模板](../文档模板.md)`（技术文件在下级目录，向上一级）
- 唯一的例外在 `SKILL.md` 开头那一句来源说明，技术文件里一处例外都没有

这两条命令是底线，不是全部——命令查不出的（如把章节号写成中文"第 5.2.1 节"、把附表号写成"附表 B"），评审时也要看。
