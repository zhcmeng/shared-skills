# pdf-to-md：用 PaddleOCR 把 PDF 转成 Markdown

日期：2026-09-20
状态：待评审

## 背景

给本仓库加一个 skill：把 PDF 转成 Markdown，落到磁盘上。

解析交给 PaddleOCR 的 AI Studio 接口。`paddleocr-mcp` 这个包有两副面孔——既能当 MCP 服务跑，也能当普通 Python 库直接 import。**本 skill 走库调用那条路。**

这个选择定下了后面大半设计，理由是：

- 走 MCP 协议时，解析结果以工具返回值的形式回到对话里。正文一长就会触发落盘，正文和图片还得再去 `tool-results` 那个目录里捞回来
- 库调用把结果对象直接交到手上：`markdown` 是完整正文，`images_mapping` 是「正文里的图片名 → 图片地址」的对照表。正文和图片一次拿全，不经过对话，也不占上下文
- 单次调用的规模由自己掌握，超长文档可以切段

## 目标

- 输入可以是单个 PDF、一个目录（批量）、或一个网址
- 输出一份干净的 Markdown：正文里出现的图片全部落到本地，引用改成相对路径
- 转换过程不进对话——正文多长都不占上下文
- 落盘的正文就是文档内容本身，不夹带转换过程留下的任何东西——没有说明文字、没有来源标注、没有 frontmatter、没有包裹标签、没有远程图片地址
- 批量时显示进度和预计剩余时间，转过的跳过
- 单个 PDF 超过 100 页时自动切段，转完拼回一份

## 非目标

- 不做领域专属的正文清理（删目录、按标题截断某一类章节）。要这类行为，调用方在转换之后自己处理
- 不做扫描件的识别参数调优，不做版面还原的人工干预
- 不动 `hooks/`、状态栏、常驻规则

## 决策记录

| 决策 | 选了什么 | 为什么 |
|:---|:---|:---|
| 调库还是走 MCP | 直接 import `paddleocr_mcp` | 结果直接到手，正文与图片不经对话，没有返回值上限这回事 |
| 图片从哪来 | 用解析结果附带的地址逐个下载 | 正文与「图片名 → 地址」对照表由同一次解析一起产出，图片不必另外去别处找 |
| 输出布局 | `<输出根>/<名字>/<名字>.md` + `<输出根>/<名字>/images/` | md 与图片同在一个目录，整个目录能单独搬走 |
| 超 100 页 | 按页边界切段，转完拼起来 | 单次调用有 100 页上限，切段对使用者透明 |
| 默认模型 | PaddleOCR-VL | 官方文档里它是新一代，擅长扫描、倾斜与多语言；换模型由调用方显式指定，本 skill 不做自动路由 |
| 清理范围 | 只做通用的（表格、包裹标签、空白、图片引用），不带配置文件 | 通用的才收进本仓库 |
| 依赖缺失时 | 直接报错退出 | `lxml`/`tabulate` 缺了表格会静默退化成原始 HTML，那正是「正文不干净」的来源 |
| 批量并发 | 串行 | 接口按天算页数配额，并发只会更快撞上；进度条也只需要一条 |
| 已转过的 | 默认跳过 | 断点续跑靠它；要重转加 `--force` |
| 落盘正文的形态 | 解析结果经通用清理后的样子，不夹带说明、来源标注、frontmatter | 「正文干净」这条要求 |

## 设计

### 文件清单

```
skills/pdf-to-md/SKILL.md              用法说明：怎么调、两个模型各自的特点、配额与错误码
skills/pdf-to-md/scripts/convert.py    CLI 入口与编排：参数、批量循环、进度条、已转过判断、落盘
skills/pdf-to-md/scripts/engine.py     跟外部打交道：取 token、调库、读页数与切段、下载图片
skills/pdf-to-md/scripts/markdown.py   纯文本：表格、包裹标签、空白、图片引用改写、图片名分配、多段拼装
skills/pdf-to-md/tests/test_markdown.py
```

`markdown.py` 不导入网络和文件相关的库，也不依赖 token——所有能单测的逻辑都集中在这里，包括图片名的分配和多段拼装（它们只是拿字典做事，不碰网络）。`engine.py` 是唯一 import `paddleocr_mcp` 的地方。

`SKILL.md` 的 frontmatter 要有 `name: pdf-to-md` 和一段带触发词的 `description`，照 `download-md-images` 那份的写法——写明什么时候用它，也写明什么时候不用（导出成 PDF 是 `md-export` 的事）。

顺带把 `.claude-plugin/plugin.json`（1.8.3）和 `.claude-plugin/marketplace.json`（1.8.2）的版本号对齐，并在 `README.md` 的 skill 表里补一行。

### 数据流

```
输入（文件 / 目录 / 网址）
  └ 网址先下到临时文件，之后与本地文件同路
读页数
  └ ≤ 100 页：一段
  └ > 100 页：按页边界切成多段
逐段调库，每段拿到 {正文, 图片名→地址 对照表}
收集全部段落引用到的图片
  └ 同一个地址 → 同一个本地文件
  └ 本地文件名取自地址里的文件名；已被别的地址占用就追加 -2、-3
下载图片
改写每段正文里的图片引用为 images/<本地文件名>
按段顺序拼装
落盘
```

图片名要**全局**分配，不能各段各分——同一张图跨段重复出现时要指向同一个文件，不同图恰好同名时要错开。所以先收齐再分配，最后才下载和改写。

### 命令行

```
convert.py <输入…> [--output <输出根目录>] [--model <名字>] [--force] [--max-pages <N>]
```

- `<输入…>`：PDF 文件、目录、网址，可以给多个。给目录就递归找 `*.pdf`
- `--output`：输出根目录。不给时，落在输入所在的目录（目录批量就落在那个目录）；输入是网址时必须给
- `--model`：`paddleocr-vl`（默认）或 `pp-structure-v3`
- `--force`：已转过的也重转
- `--max-pages`：切段阈值，默认 100

批量时一行进度：百分比、第几个/共几个、当前文件名、已用时间、预计剩余时间。单文件时只显示已用时间。

### 依赖与调用

```
uv run --with paddleocr-mcp --with lxml --with tabulate --with pypdf \
  python <skill目录>/scripts/convert.py <输入…>
```

四个依赖各有各的用处：`paddleocr-mcp` 是解析本体，`lxml` 与 `tabulate` 把 HTML 表格转成 Markdown 表格，`pypdf` 只用来读页数和切段。

要 `uv` 在 PATH 上。脚本开头自己检查四个依赖在不在，缺哪个就报哪个的名字——缺 `lxml`/`tabulate` 时后两者不会报错，只是表格悄悄退回原始 HTML，那种坏法看不出来。

### 落盘

```
<输出根>/<PDF 文件名>/<PDF 文件名>.md
<输出根>/<PDF 文件名>/images/<图片>
```

正文里的引用写成 `![](images/xxx.jpg)`。**正文里不出现远程地址**——图片地址带签名，会过期，留在正文里等于埋一批死链。

某张图下载失败时：正文对应位置留一行注释标明这里原本有张图，结束时在屏幕上列出。不留远程地址，因为那个地址过一阵子就打不开了，看起来却像好的。

### 正文清理

无条件跑，按顺序：

1. HTML 表格转 Markdown 表格（`lxml` + `tabulate`）
2. 去掉没有内容的包裹标签：`div`、`span`、`center`、`html`、`body`、`p`
3. 连续空行归一，行尾空白去掉
4. `<img src="…">` 整标签改成 `![](images/…)`

HTML 标签里的 `width`、`style` 这类属性一并丢掉——Markdown 没有对应的写法，留着只是噪音。

### 模型怎么挑

默认 `paddleocr-vl`。换模型由调用方或使用者显式传 `--model`。

**本 skill 不做自动路由。** 要判断该用哪个，得先知道这份文档表格多不多、是不是扫描件——而这件事只有解析完才知道，PDF 里没有标记可看。让模型凭文件名或上下文猜，猜错了整篇都得重来。真正会用到另一个模型的通常是批处理，而批处理自己就知道手里这批是什么文档，直接指定就行。

下表照官方文档整理，供指定时参考——**本仓库没有做过两个模型的横向对比**：

| | PaddleOCR-VL | PP-StructureV3 |
|:---|:---|:---|
| 结构 | 版面分析 + 视觉语言模型 | 版面检测 + OCR + 表格 + 公式 + 印章 + 图表，多个模块串联 |
| 擅长 | 扫描、倾斜、弯折、屏幕拍摄、复杂光照；多语言 | 表格：有线表与无线表分两套模型，能细到单元格 |
| 弱点 | 模型大，推理慢 | 官方自述纯英文识别能力有限（默认是中英模型） |

### token 从哪来

先看环境变量 `PADDLEOCR_MCP_AISTUDIO_ACCESS_TOKEN`；没有就去 `~/.claude.json` 的 `mcpServers` 里找带这个键的那一项。

要这个回退是因为：MCP 的 env 配在 `.claude.json` 里，那是给 MCP 服务进程用的，不会进 shell 环境。只认环境变量的话，在这台机器上每次都得先手动 export。

### 配额与错误

- 单次调用 100 页——本 skill 自动切段，用不着使用者操心
- 每天 20000 页
- 403 token 无效或无权限；413 文件过大；429 超出配额或触发限流；500/503/504 服务端问题

## 测试计划

`tests/test_markdown.py`，只覆盖不需要网络的部分：

- HTML 表格转 Markdown：合并单元格、格子里还嵌着别的标签、表格之外的其他 HTML 原样保留
- 包裹标签拆掉，非包裹标签（`table`、`img`）留着
- 空行归一、行尾空白
- 图片引用改写：`<img>` 与 `![](…)` 两种写法都认
- 重名分配：同名不同图错开、同地址重复出现指向同一文件
- 多段拼装：段序正确、图片名不串
- 下载失败的占位：不留远程地址

跑法：`python skills/pdf-to-md/tests/test_markdown.py`。

端到端（真 PDF、真 token、真配额）不进测试文件，手工跑一次确认。

## 已知局限

- 图片下载失败就找不回来了——地址带签名，过期即失效，重试必须重新解析
- 切段处正好是跨页表格时，那张表会断成两截
- 图片地址的文件名取自页内坐标，跨页同位置的两张不同图本来会同名；已在分配环节错开，但错开后的名字看不出哪张是哪张
- 网址输入只支持直接指向 PDF 的地址，不支持需要登录或有反爬的页面

## 设计取舍

**为什么不带配置文件。** 解析结果里的正文噪声跟文档类型强相关——同一套「删哪些章节」的规则，换个领域就是错的。与其带一份看着能用、实际会误删的默认配置，不如不带，把这件事明确交给调用方。

**为什么切段阈值做成参数。** 100 页这个数是接口给的，不是本 skill 定的。哪天接口放宽了，改一个参数就行，不用翻代码。
