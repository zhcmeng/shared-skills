# pdf-to-md：财报单页模式下把跨页的表格接回去

日期：2026-10-18
状态：已实现；判断规则按「只看页边位置」修订

## 背景

财报改为逐页提交后，每一页单独解析。一张表跨两页时，会得到两张表。

实测分众传媒 2024 年年度报告第 75、76 页（母公司资产负债表）：

- 第 75 页：表头「项目 / 期末余额 / 期初余额」，从「流动资产：」排到「资产总计」；
- 第 76 页：直接从「流动负债：」接着往下，**没有重复表头**；
- 单页转换后是两张表，第二张的第一行「流动负债：」被服务当成了表头，下面还跟了一条表头分隔线；
- 整本提交时，服务自己会把这张表合成一张（`mergeTables`），单页模式失去了这个能力。

同一份报告第 73、74 页（合并资产负债表）还有另一种情形：上一页是 3 列，下一页服务返回的续表每行 4 个 `<td>`，其中第 2 列整列为空。正文数据其实还是 3 列。

需求：同一张表跨页时接成一张，表头只出现一次；重复表头删掉。

**判断原则（2026-10-18 修订）**：只看页边位置。上一版还要求页面尺寸相同、左右边缘对齐、正文里表格数与版面表格块数一致、表格前后没有文字、下一页第一行不像新表头。这些条件都会把本来该合的表挡在外面（漏合），而它们并不说明两张表是不是同一张。现在只保留「上一页的表贴到页底 + 下一页的表贴到页顶」两条；列数和图片只作为「接了会不会错」的底线。

## 目标

- 财报单页模式下，相邻两页的同一张表接成一张；
- 表头只出现一次；下一页重复印的表头删掉；
- 不是表头的第一行（例如「流动负债：」）按数据行保留；
- 判断只看页边位置，不再用页面尺寸、左右对齐、表格计数、表格前后文字、第一行像不像表头来挡。

## 非目标

- 不改普通模式。普通模式是整本提交，服务已经合并过表格，再合一遍没有收益、只有风险。
- 不自己解析 PDF 的线条。服务返回的结果里已经有每个版面块的坐标，够用；不新增 `pdfplumber` 之类的依赖。
- 不校正表格内容，只做「接起来」这一件事。

## 关键决定：在 HTML 上判断和合并

单页结果里的 `Page.text` 是原始 HTML（`<table>`），转成 Markdown 是在 `assemble` 里、由 `_render_table` 最后做的。服务还在 `parsing_res_list` 里给每个表格块一份 `block_content`——同一张表的 HTML，不带样式——以及坐标 `block_bbox`。

实测第 73、74、75、76 页：`Page.text` 里的表和版面块 `block_content` 里的表，行列文字逐格一致，只有样式属性不同。所以：

1. **表的内容**——列数、表头、接哪些行——用 HTML；
2. **表在页面上的位置**——只能用坐标，因为 HTML 里没有位置；
3. 合并本身也在 HTML 上做，最后只渲染一次，`_render_table` 自然只产生一行表头和一条分隔线。

如果先渲染成 Markdown 再合并，要反过来解析管道表格，还得处理转义的竖线、合并单元格展开出来的空格子，容易出错。

## 判断规则：只看两条位置条件

1. **上一页**：这张表是该页正文里最靠下的一块，表的下边缘贴到页底的正文边界（页码或页脚的上沿）。
2. **下一页**：这张表是该页正文里最靠上的一块，表的上边缘贴到页顶的正文边界（页眉的下沿）。

配套说明：

- 「正文块」= 服务给的 `parsing_res_list` 里，去掉 `markdownIgnoreLabels` 那几类（页眉、页脚、页码等）之后剩下的块。
- 「最靠下/最靠上」是位置条件的一部分：表下面还夹着别的正文块，就不算贴到页底；表上面还夹着别的正文块，就不算贴到页顶。
- 有页码/页脚、页眉时，容差是页高的 5%。
- 没有页码/页脚时，以纸张下边缘为准；没有页眉时，以纸张上边缘为准；容差放宽到页高的 10%——纸张边缘外还有空白边距，照 5% 算会把正常的表挡掉。
- 两页各用自己的页高算容差，**不再要求页面尺寸相同**。
- 服务没给页高时不合并——算不了容差。

## 接的时候必须成立的两条

这两条不是「判断是不是同一张表」，而是「接了会不会错」：

3. **列数**：先按展开 `rowspan/colspan` 后的原样宽度比。宽度不同时，允许做两种不丢数据的压缩：
   - **幻影列**：丢掉每一行都为空的列。实测第 74 页的续表每行 4 个 `<td>`，第 2 列整列为空，上一页是 3 列；丢掉后是 3 对 3。
   - **合计溢出**：把最右一列并回左边一列。条件是这两列从不在同一行有值，而且带值的那一行只有「名称 + 合计」两格。实测第 163 页的续表有 5 格，分类行「应收账款」的合计 `199,067,001.44` 单独落在第 5 格；它其实是第 4 列的延续，并回去就是 4 列。
   - 从两张表都放得下的最大列数往下试，第一个两边都能压到的列数就是对齐结果。原样宽度相同时不压，保留小表里整列为空、但确实有意义的金额列。
   - 列数对不上还硬接，接过来的行会整体错位。
4. **两张表都没有图片**：接的过程会把单元格压成纯文字，图片没法跟着行搬过去。只要上一页或下一页那张表里有 `<img>`，就不合并。

## 合并规则

- 把下一页开头那张表的行，接到上一页末尾那张表的后面；下一页那张表整个删掉。
- 下一页表后面还有内容（例如「法定代表人：江南春」那几行）时，原样留在那一页。
- 三页以上按**表链**处理，不按页组：
  - 每一页可能有开头一张表、结尾另一张表，两张也可能是同一张；
  - 相邻两页满足条件时，下一页开头那张表接到上一页结尾那张表后面；
  - 所以一页里可以同时是「上一张表的续页」和「下一张表的开头」，两条链互不影响；
  - 重复表头跟「正在接的那张表」的表头比，不跟上一页的第一行比。这样第二页没有重复表头、第三页又重复了原始表头时，第三页的表头仍能删掉。
  - 开头与根表表头逐行相同的行整段删掉，最多删 5 行。
- 一条表链只用一种列数：相邻两页各自能对齐，整条链仍可能对不齐（中间某页多一列，根表和最后一页都没有）。合并时从链上所有表都放得下的最大列数往下试，第一个全都压得进去的列数作为整条链的表示；一个都没有就不合，免得删了后面的表却没接上。
- 合并后照常走 `clean_markdown`：图片引用改写、空白归一、分页标记清理都不变。

## 数据从哪来

- `parse_jsonl` 从每条结果的 `prunedResult` 取 `width`、`height` 和 `parsing_res_list`：
  - `Page.blocks`：所有版面块的 `(label, (左, 上, 右, 下))`；
  - `Page.page_size`：`(宽, 高)`；
  - `Page.tables`：表格块的 `((左, 上, 右, 下), block_content)`。没有 `block_content` 的表格块只留在 `blocks` 里，不进 `tables`。
- `_edge_table(page, at_bottom)` 取页边那张表：
  - 按坐标选最靠下或最靠上的表格块，不按列表顺序；
  - 再在 `Page.text` 里找行列内容与它一致的 `<table>` 区间；
  - **不数整页有几张表**；别处多一张少一张表不影响判断。
- `_cross_page_table_pair` 用两张页边表的 HTML 网格比较列数（允许幻影列和合计溢出两种压缩），并用 `block_content` 检查图片。
- `_convert_single_pages` 重建 `Page` 时要把 `blocks`、`page_size`、`tables` 一起带上，否则合并拿不到坐标，永远不合。
- 版面块里的标签（`header`、`number`、`table` 等）原样保留，过滤在合并函数里按 `ignore_labels` 做。

## 放在流程的哪一步

- `markdown.py`：`merge_cross_page_tables(pages, ignore_labels)`，纯文本处理，不联网。
  - 入参 `pages` 是 `parse_jsonl` 摊出来的页表；`ignore_labels` 由调用方给，默认空集合。
  - 返回新的页表，不就地改原对象。
- `convert.py`：只在 `--source-type financial` 的路径上调用，位置在 `_convert_single_pages` 拿到页表之后、`_finish_document` 之前。`ignore_labels` 取 `aistudio.FINANCIAL_OPTIONAL_PAYLOAD["markdownIgnoreLabels"]`。
- `markdown.py` 不 import `aistudio`，保持现在的分工。

## 边界与取舍

**会漏合的情形**（保持两张表，不报错）：

- 表格没有贴到页底或页顶；
- 下一页表格上面有「续表」之类的正文块；
- 缺页高、缺版面表格块（或表格块没有 `block_content`）；
- 版面块给出的表格 HTML 与正文里的表格 HTML 行列对不上；
- 两页列数不同，且按幻影列 / 合计溢出压缩后仍对不上；
- 表里有图片。

上一版还会因为下面这些情形漏合，现在不会了：

- 两页页面尺寸不同；
- 左右边缘没有对齐；
- 正文里的表格数与版面表格块数不一致；
- 表格前后还有文字（标题、签名、后记）；
- 下一页第一行看起来像另一张表的表头。

**唯一防不住的误合**：上一页的表正好结束在页底，下一页页顶又开始一张列数相同的新表，而且新表没有标题。这种情况会被接成一张。这是放弃其他条件换来的代价；以后真在报表里遇到，再加针对性的信号（例如新表第一行列名完全不同）。

**重复表头的弱点**：只按逐行逐格相同来删。表头写法有细微差别（空格、标点不同）时删不掉，那一行会留在表中间；但不会误删数据行。

**没有页码/页眉时用 10% 容差**：比有参照时宽，可能多合一点点；但表格仍必须是该页最靠下/最靠上的正文块。

## 测试计划

不发真实请求，用合成的页表覆盖：

- 正常合并：上一页表 + 下一页无表头的数据行 → 一张表，表头一次，第一行数据保留；
- 重复表头：下一页第一行与上一页表头相同 → 删掉，不留空行；
- 三页连续：两对条件都成立 → 合成一张表；
- 列数不同且压不到同一列数 → 不合并；
- 续表有一列整列为空的幻影列 → 仍能合，合出来是有效列数；
- 续表最右多一格分类合计 → 仍能合，合计落回最后一列；
- 最右两列在同一行都有值 → 不合并（是真多出来的一列）；
- 最右一格出现在「名称 + 外币余额 + 合计」三格的行里 → 不合并；
- 幻影列出现在重复表头里 → 表头仍能删掉；
- 小表里整列为空、但原样宽度与上一页相同 → 不丢列；
- 四页表链中间某页多一列、根表和末页列数相同 → 整条链仍能合，统一到共同列数；
- 下一页第一行像新表头 → 仍合并（第一行不再参与判断）；
- 表格后面还有正文块 / 表格前面有正文块 → 不合并（位置条件）；
- 表格前后有文字但没有对应的正文块 → 仍合并；
- 左右边缘不齐 → 仍合并；
- 两页页面尺寸不同 → 仍合并；
- 没有页码/页脚/页眉 → 按纸张边缘回退，仍合并；
- 缺页高、缺版面表格块 → 不合并；
- 正文里表格数与版面表格块数不一致 → 仍合并（只看页边那张表）；
- 合并后 `rowspan/colspan` 仍按网格展开；
- 表头有两行以上、下一页重复了多行表头 → 整段删掉；
- 一页里既有开头一张表、结尾另一张表 → 两条链各接各的；
- 下一页表格后面的签名等内容保留；
- 上一页表格后面、下一页表格前面的文字保留；
- 表内有 `<img>`（上一页或下一页）→ 不合并；
- 合并不修改入参页表。

## 留给实现的人

- 容差的具体数值（5%、10%）可以按实测调；10% 只用于没有页码/页眉、以纸张边缘为准的回退。
- 内部函数怎么拆、是否复用现有的 `_find_table_spans`，由实现决定。
