# pdf-to-md：财报单页模式下把跨页的表格接回去

日期：2026-10-18
状态：已定稿，待确认后实现

## 背景

财报改为逐页提交后，每一页单独解析。一张表跨两页时，会得到两张表。

实测分众传媒 2024 年年度报告第 75、76 页（母公司资产负债表）：

- 第 75 页：表头「项目 / 期末余额 / 期初余额」，从「流动资产：」排到「资产总计」；
- 第 76 页：直接从「流动负债：」接着往下，**没有重复表头**；
- 单页转换后是两张表，第二张的第一行「流动负债：」被服务当成了表头，下面还跟了一条表头分隔线；
- 整本提交时，服务自己会把这张表合成一张（`mergeTables`），单页模式失去了这个能力。

需求：同一张表跨页时接成一张，表头只出现一次；重复表头删掉。**合错了比漏合更不能接受。**

## 目标

- 财报单页模式下，相邻两页的同一张表接成一张；
- 表头只出现一次；下一页重复印的表头删掉；
- 不是表头的第一行（例如「流动负债：」）按数据行保留；
- 判断不确定时不合并，宁可留成两张表。

## 非目标

- 不改普通模式。普通模式是整本提交，服务已经合并过表格，再合一遍没有收益、只有风险。
- 不自己解析 PDF 的线条。服务返回的结果里已经有每个版面块的坐标，够用；不新增 `pdfplumber` 之类的依赖。
- 不校正表格内容，只做「接起来」这一件事。

## 关键决定：在 HTML 上判断和合并

单页结果里的 `Page.text` 还是原始 HTML（`<table>`），转成 Markdown 是在 `assemble` 里、由 `_render_table` 最后做的。所以判断和合并都放在 HTML 上，理由有三条：

1. 行和格的结构完整，`rowspan/colspan` 还没展开；
2. 判断「第一行是不是表头」「是不是和上一页表头相同」可以直接按行、按格比较；
3. 合并完只渲染一次，`_render_table` 自然只产生一行表头和一条分隔线。

如果先渲染成 Markdown 再合并，要反过来解析管道表格，还得处理转义的竖线、合并单元格展开出来的空格子，容易出错。

## 判断规则：四条同时成立才合并

1. **页边界**：上一页最后一个内容块是表格，下一页第一个内容块是表格。
   - 「内容块」= 服务给的 `parsing_res_list` 里，去掉 `markdownIgnoreLabels` 那几类（页眉、页脚、页码等）之后剩下的块。
2. **位置**：两页的表格都贴着页面的正文边缘。
   - 上一页表格的底边，要贴到这一页页码的上方（没有页码时用页脚）；
   - 下一页表格的顶边，要贴到这一页页眉的下方；
   - 「贴近」的容差按第 75、76 页实测来定，只能往严里调；
   - 左右边界对齐：两页表格的左边、右边各相差不超过 2% 页宽；
   - 两页页面尺寸相同（宽、高各相差不超过 2%）；
   - 页眉和页码这两块缺一个，就不合并。没有页眉、没有页码的文档确实存在，但少了这个参照，位置就没法判断，按「不合」处理。
3. **列数**：两张表展开 `rowspan/colspan` 后的网格宽度相同。
4. **下一页第一行不是新表头**（按原始 `<td>` 的格子比较，不按展开后的网格）：
   - 把下一页表开头几行，与「正在接的那张表」开头几行逐行比；相同的行整段删掉，最多删 5 行；
   - 一行都对不上时，看下一页第一行：有空单元格，或者有单元格含数字 → 是数据行，合并时保留；
   - 其余情况（每格都有字、都不含数字，又对不上表头）→ 当成新表的表头，**不合并**。

   比较用原始格子、不用展开后的网格：表头里如果有 `colspan`，展开后会出现一串空格子，会被「有空单元格」这条误判成数据行，正好把一张新表的表头放进来——那是最不能接受的误合。列数比较（第 3 条）才用展开后的网格。

缺版面块或页面尺寸时，按「不合并」处理。

## 合并规则

- 把下一页开头那张表的行，接到上一页末尾那张表的后面；下一页那张表整个删掉。
- 下一页表后面还有内容（例如「法定代表人：江南春」那几行）时，原样留在那一页。
- 三页以上按**表链**处理，不按页组：
  - 每一页可能有开头一张表、结尾另一张表，两张也可能是同一张；
  - 相邻两页满足条件时，下一页开头那张表接到上一页结尾那张表后面；
  - 所以一页里可以同时是「上一张表的续页」和「下一张表的开头」，两条链互不影响；
  - 重复表头跟「正在接的那张表」的表头比，不跟上一页的第一行比。这样第二页没有重复表头、第三页又重复了原始表头时，第三页的表头仍能删掉。
- 下一页要接的那张表里有 `<img>` 时，不合并。图片是按页分配名字的，跨页搬行会把图片引用留在原来那页的映射里，合并后就成了坏图。
- 合并后照常走 `clean_markdown`：图片引用改写、空白归一、分页标记清理都不变。

## 坐标从哪来

- `parse_jsonl` 从每条结果的 `prunedResult` 取 `width`、`height` 和 `parsing_res_list`，装进 `Page.blocks` 与 `Page.page_size`。第 75、76 页实测：坐标和尺寸在同一套坐标系里（bbox 都落在 1191 × 1685 内）。
- `dataInfo.pages` 里也有每页尺寸，和 `prunedResult` 是同一份信息，只用一处。
- `_convert_single_pages` 现在重建 `Page` 时只带 `index`、`text`、`images`，必须把 `blocks` 和 `page_size` 一起带上，否则合并拿不到坐标，永远不合。
- 版面块里的标签（`header`、`number`、`table` 等）原样保留，过滤在合并函数里按 `ignore_labels` 做。

## 放在流程的哪一步

- `markdown.py`：新增 `merge_cross_page_tables(pages, ignore_labels)`，纯文本处理，不联网。
  - 入参 `pages` 是 `parse_jsonl` 摊出来的页表；`ignore_labels` 由调用方给，默认空集合。
  - 返回新的页表，不就地改原对象。
- `convert.py`：只在 `--source-type financial` 的路径上调用，位置在 `_convert_single_pages` 拿到页表之后、`_finish_document` 之前。`ignore_labels` 取 `aistudio.FINANCIAL_OPTIONAL_PAYLOAD["markdownIgnoreLabels"]`。
- `markdown.py` 不 import `aistudio`，保持现在的分工。

## 边界与取舍

**会漏合的情形**（保持两张表，不报错）：

- 下一页表格前面有「续表」之类的标题块；
- 表格没有贴到页底或页顶；
- 两页列数不同、页面尺寸不同；
- 缺版面坐标；
- 第一行看起来像另一张表的表头；
- 表头和上一页只有细微差别（空格、标点不同），逐格比较没过，又不像数据行。

漏合是可见的：正文里还是两张表，用户能看出来。误合是隐蔽的：两张不相干的表被接在一起，数字还在，但归属错了。按「合错了更不能接受」，这些情形一律不合并。

**最可能误合的情形**：上一页以一张表结尾，下一页开头是一张同样列数、没有标题、第一行又是数字的表。四道条件里位置和列数都会通过，只能靠「第一行不像新表头」这一道拦。财报里这种情况通常是同一张表，但没法百分百排除；这是本方案接受的剩余风险。

**上一页表格在页面中间结束、下面留白，下一页开头又是一张同样列数的表**：不合并。块顺序看起来满足，但表格没有贴到页底，按位置条件拦下。这条已和用户确认：宁可留成两张表。

**重复表头的弱点**：表头本身含数字（例如「2024年度」）时，第四条的「含数字」会把它判成数据行。但重复表头通常在「逐格相同」那一步就命中了；只有写法有差异时才会漏，不会误合。

## 测试计划

不发真实请求，用合成的页表覆盖：

- 正常合并：上一页表 + 下一页无表头的数据行 → 一张表，表头一次，第一行数据保留；
- 重复表头：下一页第一行与上一页表头相同 → 删掉，不留空行；
- 三页连续：两对条件都成立 → 合成一张表；
- 列数不同 → 不合并；
- 下一页第一行像新表头 → 不合并；
- 上一页表格后面还有正文 / 下一页表格前面有标题 → 不合并；
- 左右边界或顶底位置不满足 → 不合并；
- 缺坐标、缺页面尺寸 → 不合并；
- 合并后 `rowspan/colspan` 仍按网格展开；
- 表头有两行以上、下一页重复了多行表头 → 整段删掉；
- 表头里带 `colspan` → 不因展开后的空格子把新表头当成数据行；
- 一页里既有开头一张表、结尾另一张表 → 两条链各接各的；
- 下一页表格后面的签名等内容保留；
- 表内有 `<img>` → 不合并。
