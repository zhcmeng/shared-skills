# 说人话，不用黑话，不夹英文

## 用途

面向读者的产物一律用读者一次就能读懂的表达，**禁止需要读者自己解码的黑话，也禁止中英文夹带和只给英文不给中文**。两种用法，产出不同：

- **回答看不懂时（无参数）**：把刚给出的那条回答**整条重说一遍**——平实中文、不夹没必要的英文、不指代上文，读者不用回看前文就能读懂。给的是成品，不是清单
- **审自己的稿子（给文档路径）**：给问题清单——哪一处、什么类型、该怎么改，供你逐条决定改不改

**只读不改**——本 skill 不修改任何文件。

## 参数

- **无参数**（含 Claude 自动触发——用户只说"这段看不懂"、没敲命令时）：重说当前对话中最近产出的那条回答——**整条，不是其中一段**（只重说一段的话，剩下那些又成了读者得自己回看的上文）。用户嫌刚那条回答绕、夹英文、"看不懂"时就用它
- **给文件路径**：审查该文件，出问题清单。

## 适用范围

两类对象，三种问题：

| 对象 | 产出 | 说明 |
|:---|:---|:---|
| **会话中的回答** | 完整重说 | 模型在对话里刚给出的回复 |
| **文档** | 问题清单 | 正文、图注与脚注说明、研究报告 |

三种问题两类对象都要查：**黑话**、**中英文混用**、**英文没给中文翻译**——下面的表给出各自的改法。

**文档审到哪为止**：正文、图注与脚注说明、mermaid 图里的文字都审。不审的是 YAML frontmatter，以及链接清单和引文元数据本身——页末那些区里**给人读的说明文字照样审**（脚注里的口径说明、知识库链接后面的注解都算）。引文元数据指落点里的原文引文与文献条目本身；落在它们之外的口径说明、立场标注、局限说明都算"给人读的说明文字"，照审。

## 判据

**一个不了解该主题的读者，能否一次读懂这句话？读不懂就是没写明白，不是读者的问题。**

两类对象都按这一条判，差别在"读者"是谁：

- **重说会话回答**：读者是提问的人——他关心这个话题（"分众"这类不必解释），但未必懂里面的行话（"点位密度""敏感性分析"要解释），而且**不该被要求回看上文**，所以指代（"它""那个"）和省略都要展开成明确的话
- **审文档**：读者是将来打开这个页面的人，看不到写它时的对话

## 六类黑话与改法

| 类型 | 改法 | 实例 |
|:---|:---|:---|
| 自造压缩黑话 | 展开成一句人话 | "上层认知扩口、下层收割、贴交易截需求"→"上层做认知、下层做转化、在离购买最近的地方接住已有需求" |
| 生造词 | 换平实说法 | "心智物理"→"记忆怎么形成"；"轴位分工"→"按各自的强项分工" |
| 直译黑话 | 换中文说法 | "决策旅程"→"决策过程"；"截胡自然流量"→"本来就会发生的自然流量" |
| 元标注黑话 | 换平实说法 | "对冲句"→"限定句"；"幸存者偏差暴露面"→"幸存者偏差风险" |
| 术语首次出现不解释 | 首次出现按原出处补一句人话 | "信任品"→"保健品这类用过了也难判断好坏的信任品" |
| 术语名与解释对不上 | 遮住括注只看术语名——读者猜的方向和括注对不上，就按原文定义句重译，学科通用译名写进"（原文 X）" | 心理学原则"稀缺"（原文 scarcity）配的例子是"在做下一步之前"：读者读"稀缺"想到东西少，跟时间限制对不上，改叫"紧迫感" |

**表里列的是问题类型，不决定改不改、改多急**——那由"待改／提示"的分档规则定（见"执行步骤"）：同样是"术语首次出现不解释"、同样是一个英文标题，读者卡住就进待改，能靠上下文救回来就进提示。

## 中英文混用与英文没给翻译

中文句子里夹英文、或是给了英文不给中文，读者一样读不懂。两类改法：

| 类型 | 改法 | 实例 |
|:---|:---|:---|
| 无必要的英文夹杂 | 换中文说法 | "我们需要 align 一下这个 approach"→"我们需要对齐一下这个思路"；"这个 feature 的 priority 很高"→"这个功能的优先级很高" |
| 英文内容没给中文 | 首次出现附中文翻译 | "asymmetric information"→"信息不对称（asymmetric information）"；成段英文引用→补中文译文；英文标题→"摩根士丹利：广告业的未来（The Future of Advertising）" |

判据还是同一条：**读者要不要懂英文才读得懂？要，就是问题；不要，就保留。** 这条**两档都适用**——重说档遇到公认缩写（如 GDP、API）同样按判据定，不是一律换中文；读者读不懂的（如文里没解释过的 CPM、ROAS）才换。

**几个容易判岔的地方**：

- **英文词当日常词用就换中文**："注入 context""查 memory"说的是上下文和记忆，该改；指产品机制或目录本身（`.claude/memory/`）则保留。
- **给中文解释和给译名一样算过关**，解释往往比译名更有用：`performance-based` 写成"按点击、销售、线索、收入分成计费"就够，不必强求译名。
- **"公认"按被审页面的读者算，不按行业内部算**：被审的那个页面给某个同类词做了解释，其他同类词就不能例外（该页解释了 CPM，那 ROAS、CTR 也要解释）。
- **保留清单里的词拼成箭头或压缩短语，照样要改**："rules→skill 迁移"每个词都合规，但整串要读者自己解码，改成"把规则搬进技能"。
- **已进入中文商业语汇的直译词不算问题**："护城河""天花板""赛道"这类读者一次就读得懂，保留；生硬的直译才要换（"决策旅程""对齐颗粒度"）。

引文里的英文按下面"引文内部的问题"处理；原文的表号与术语（如 10-K、Upper funnel）按"例外"节保留。

## 表外问题（不在上面两张表里，但一样影响读懂）

| 类型 | 什么算 | 进哪一档 |
|:---|:---|:---|
| 指代不明 | "它""那条""那节"接不上前文 | 读者接不上 → 待改；本段内接得上 → 提示 |
| 同一个东西两种叫法 | 一件事在文里出现了两个名字，读者会当成两件事 | 会让读者读岔 → 待改；否则提示 |
| 标签没说清 | 小标题或标签自己没说清指的是什么 | 一般提示 |

这几类的类型名照写即可，不用硬塞进上面两张表；**归不进任何一类的**（如句子拗口、两条标签紧挨着容易看反），类型名自己起一个，说清是什么问题就行。**重说时不用分档**——这几类直接改掉就是：指代展开、两种叫法统一、标签补明。

## 例外（不算黑话，不要改）

- **确有精确含义、且文中已给出定义的术语**：如"影响机会""心智资产""覆盖×频次"，保留，不降级为啰嗦大白话——**前提是术语名与它的解释对得上**；对不上时按"术语名与解释对不上"处理，换词，而不是再加一句解释
- **引用原文的章节名与报告用语**：保持原样，如研报的"增长抓手节"

## 执行步骤

**无参数（重说）**：

1. 取当前对话中最近产出的那条回答（整条，不是其中一段）
2. 逐句对照上面的表，找出要换表达的地方（含"要不要懂英文才读得懂"这一问）
3. 把整段回答重讲一遍：换掉黑话与英文夹杂，补上英文的中文说法，把指代展开
4. 按下面的"重说"格式输出

**给路径（清单）**：

1. 读文件
2. 逐句判读，对照上面的表归入类型
3. 分待改与提示——会让读者读岔或卡住的进"待改"，靠上下文能自己救回来的进"提示"，分不清时按更轻的处理
4. 写可直接替换的改写句，不写"建议更通俗一些"这类无法执行的评价
5. 按下面的"清单"格式输出

## 输出格式

### 一、重说会话回答（无参数时）

直接给重说后的内容——不加清单档那套标题与摘要，以"重说："开头：

```
重说：

<把刚才那条回答用平实中文整条重讲一遍，信息不增不减，指代展开，不夹没必要的英文>

改动：<原词>→<中文>、<原词>→<中文>；<整句级的改动另用一句话说明>

拿不准：<哪一处没把握、你怎么处理的、为什么>（有才写，没有就省略）
```

- **必须整条重讲**，不能只挑有问题的句子单独翻译——那样读者还得自己拼回原文
- **信息不增不减**：只换表达，不加原文没有的判断，也不漏原文有的内容。术语首次出现补的那句解释算换表达，不算加判断
- `改动`一行让读者把原词和中文对上：单词级替换写 `原词→中文`，**整句级的（指代展开、名称补全、补解释）另用一句话说明**，别因为写不进箭头就漏掉。列的是**读者可能对不上号**的（英文词、黑话、压缩词）；"阈值→一定程度"这类常见中文换词不必列
- `拿不准`一行放没把握的地方——**改过但没把握**的和**看出问题却没动**的都写这里，写明是哪一处、怎么处理的、为什么；没有则省略
- 原文没问题时说"这段没有需要改的地方"，不硬凑

### 二、审文档（给路径时）

```
## 表达审查：<文件名>

**摘要**：X 处待改 / Y 处提示 —— 结论：过关 / 局部改写 / 建议改写
**总体**：<一句话，这个页面整体读起来怎么样>

### 待改
- 行 L：「<原文>」
  - 类型：<表格里的类型名；归不进的自起一个，说清是什么问题>
  - 改写：<可直接替换的句子；引文内部的问题写"引文外补注的那句">
  - 同类位置：L36、L126（**同一处表述**在别处又出现时才写；只出现一次就省略这行）
  - 存疑：<拿不准的地方，写明要核实什么>（有才写）

### 提示（影响一次读懂，但不至于让读者卡住）
- 行 L：「<原文>」
  - 类型：<表格里的类型名；归不进的自起一个>
  - 为什么放提示：<为什么没定为待改>
  - 要改的话：<改法>
  - 同类位置：L36、L126（有才写）
  - 存疑：<拿不准的地方，写明要核实什么>（有才写）
```

条目按**条**算，不按行算——同一行有两处不同问题就算两条，摘要里的数字按条统计，同一行的多条会让"行 L"重复出现，这是正常的。

清单之外若发现**不属于表达问题**的东西（如数字与说明对不上），另起一段写"不计入清单"，说明发现了什么、建议怎么核实；不要混进待改或提示，也不计入摘要数字。

行号一律用**源文件行号**（编辑器打开文件时看到的行号），不用渲染后的行号。

结论三档按**密度**算，不按绝对条数：没有待改项 = 过关；待改零星分布、整体读得下去 = 局部改写；待改成片出现、影响通读 = 建议改写。长文档里 6 处待改仍是局部改写。

## 注意事项

- **只读不改**：本 skill 不修改任何文件。清单里用户确认哪几条后，再逐条落地。
- **重说只换表达**：不加原文没有的判断，不漏原文有的内容，不借机改写观点。
- **禁止编造问题凑数**：不违反判据的句子不算问题；拿不准的说明理由，不要断言是黑话。
- **例外优先**：已定义术语（名字与解释对得上的）、引用原文的章节名一律不动——清单档不列，重说档原样保留。
- **技术标识符不误报**：代码标识符、文件路径、命令名、产品名、公认缩写夹在中文里不算问题——判据是"读者要不要懂英文才读得懂"，不是"出现了英文字母"。
- **引文内部的问题**：引文本身不动（那是原文），在引文外面补一句说明或加注，"改写"栏写的就是这句补注。比如引文里出现了"标的公司"而读者不知道指谁，就在引文后补注它指的是被收购方新潮传媒。引文若是页面自己译的中文、并非原文原话，按正文处理，可以直接改。
- **只审表达，不审事实**：数字与说明对不上、结论对不对，不属本 skill 范围；发现了可以在报告之外提一句，但不计入待改。
- **拿不准含义的词**：看出读者会卡住、但说不准它确切指什么时，写明"需回原文核实"——不编定义，也不漏报（清单档放"提示"，重说档放"拿不准"行）。若换个说法就通顺、读者不必知道它确切指什么，直接改掉，别因为说不准而降级。

**只在清单档（给路径时）**：

- **"提示"收什么**：除拿不准的外，还有"表外问题"里判定进提示的那些，以及通用缩写读者可能不熟（如 2H17、扣非净利润）。
- **改写建议必须能直接替换**：给具体句子，不给评价。
