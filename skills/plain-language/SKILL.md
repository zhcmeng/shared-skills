# 说人话

**动手前先读同目录的 `rules.md`**——判据、要改的、保留全在那里，那是本 skill 仅有的规则。下面只讲怎么用，不重复规则。

## 两种用法

| 收到的 | 做什么 | 产出 |
|:---|:---|:---|
| 无参数（"这段看不懂"） | 把最近产出的那条回答**整条重讲一遍** | 成品，不是清单 |
| 一个文件路径 | 逐句审那个文件 | 问题清单 |

**只读不改**：本 skill 不修改任何文件。

审到哪：正文、图注与脚注说明、mermaid 图里的文字。YAML frontmatter 和引文元数据不审。引文本身一个字不动——引文里的问题在引文外面补一句说明。

## 输出

### 重说（无参数）

```
重说：

<整条重讲：换掉黑话与英文夹杂，补上英文的中文，指代展开，术语首次出现按原出处补一句解释>

改动：<原词>→<中文>、…；整句级的改动（指代展开、名称补全）另用一句话说明

拿不准：<哪一处没把握、怎么处理的、为什么>
```

信息不增不减：不加原文没有的判断，不漏原文有的内容。原文没问题就说"这段没有需要改的地方"，不硬凑。

### 清单（给路径）

```
## 表达审查：<文件名>

**摘要**：X 处待改 / Y 处提示 —— 结论：过关 / 局部改写 / 建议改写
**总体**：<一句话，这个页面整体读起来怎么样>

### 待改（会让读者读岔或卡住）
- 行 L：「<原文>」
  - 类型：<`rules.md` 里那张表的类型名；归不进的自起一个，说清是什么问题>
  - 改写：<可直接替换的句子>
  - 同类位置：L36、L126（同一处表述在别处又出现时才写）
  - 存疑：<拿不准的，写明要核实什么>

### 提示（不至于卡住，但影响一次读懂）
- 行 L：「<原文>」
  - 类型：
  - 为什么放提示：
  - 要改的话：
```

条目按**条**算，不按行算；行号用源文件行号。结论按密度定：没有待改 = 过关，待改零星 = 局部改写，待改成片 = 建议改写。

不属于表达问题的（数字与说明对不上、结论对不对），另起一段写"不计入清单"，说明发现了什么、怎么核实，不计入摘要数字；没有就不写这段。
