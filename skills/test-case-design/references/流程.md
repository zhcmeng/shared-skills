# 流程

本文讲一条链上的四步各该做什么：建测试模型、识别测试覆盖项、导出测试用例、创建测试规程。每一步用哪门测试设计技术、怎么用，由选定的技术文件负责，本文不重复；末尾附一个完整示例，把四步连着走一遍。

## 一、本过程的输入与产出

本过程的目的是导出测试规程；作为本过程的一部分，要对测试依据进行分析，并导出测试模型、测试覆盖项、测试用例和测试规程。

输入：

——测试依据；

——所需的测试覆盖率；

——风险信息。

产出（本过程执行后应生成的信息项）：

a）测试规格说明（测试模型规格说明、测试用例规格说明和测试规程规格说明）和相关的可追溯性信息；

b）测试数据需求；

c）测试环境需求。

a）里的三份规格说明加上 b）、c）两项需求，共五份文档，就是本技能的产出；每份有哪些栏目、各栏怎么填，见[文档模板](文档模板.md)。

注：本过程虽按四步的顺序给出，但在实践中可能迭代进行，其中一些活动允许被重新执行。

## 二、建测试模型（TD1）

本活动包括以下任务：

a）应分析测试依据，以理解测试项的要求；

b）测试策略应用于识别测试项中需要测试的部分和/或特性；

示例1：对于状态转移测试，识别测试项中适用该技术的组成部分。

c）根据所要求的测试覆盖率应确定测试模型的表示方法；

注1：所要求的测试覆盖率通常是测试完成准则的一部分。

示例2：表示法可能包括需求描述（包括自然语言）、等价类、状态转移图、用例描述、决策表、输入语法、源代码、控制流图、键值对、分类树等。

d）应为测试项创建测试模型；

注2：在某些情况下，测试模型可能是开发过程中的输出，例如设计规格说明或源代码。

e）依据相关的风险暴露级别，在测试模型中可添加额外的优先级信息；

f）宜与利益相关方就测试模型达成一致；

**本条不适用**：本技能的场合没有那套组织角色，不必另设确认环节。

g）在测试模型规格说明中应记录测试模型；

h）应记录测试依据与测试模型之间的可追溯性。

本步要记录的可追溯性——测试依据到测试模型：落点是测试模型规格说明末尾的「依据 → 模型」对应表，一段依据一行，写清这段依据的出处、照它建出的模型编号（`TM-1`、`TM-2`……），以及模型取自这段依据的哪一部分。表的列定义见[文档模板](文档模板.md)。

## 三、识别测试覆盖项（TD2）

本活动包括以下任务：

a）应通过对测试模型应用测试设计技术，导出测试覆盖项，以达到所要求的测试覆盖率完成准则；

注1：如果测试项的测试完成准则规定的测试覆盖率小于 100%，则需要从达到 100% 覆盖率所需的测试覆盖项中选择一个子集进行测试。

注2：有一些标准可辅助进行选择（例如，放弃与低风险暴露相关的测试覆盖项）；有时需要根据后续活动的结果重新进行选择。

b）应使用风险信息中记录的风险暴露级别来确定测试覆盖项的优先级；

c）在测试用例规格说明中应记录测试覆盖项；

d）应记录测试依据、测试模型和测试覆盖项之间的可追溯性。

本步要记录的可追溯性——测试模型到测试覆盖项：落点是测试覆盖项清单里的「可追溯性」栏，每条覆盖项写它出自哪个模型，至少填模型编号，必要时写到模型里的哪个元素（哪条状态、哪条转换、哪条规则、哪个类别）。测试依据那一头已由「依据 → 模型」对应表接上，这一段只管模型到覆盖项。

## 四、导出测试用例（TD3）

本活动包括以下任务：

a）应通过确定前置条件、选择输入值、必要时还包括执行选定测试覆盖项时所需的操作，并确定相应的预期结果，以导出一个或多个测试用例；

注1：在导出测试用例时，一个测试用例可能覆盖多个测试覆盖项，因此有机会在一个测试用例中实现对多个测试覆盖项的组合覆盖。这可能缩短测试执行时间，但也可能会增加调试时间。

注2：对于风险暴露级别较高的测试覆盖项，可能导出更多的测试用例，以提高测试覆盖项的测试充分性。

b）应使用风险信息中记录的风险暴露级别来确定测试用例的优先级；

c）在测试用例规格说明中应记录测试用例；

d）应记录测试依据、测试模型、测试覆盖项和测试用例之间的可追溯性；

e）测试用例规格说明应得到利益相关方的同意。

**本条不适用**：本技能的场合没有那套组织角色，不必另设确认环节。

本步要记录的可追溯性——测试覆盖项到测试用例：落点是测试用例规格说明末尾的「覆盖项 ↔ 用例」对应表，一条覆盖项一行，把覆盖它的用例编号（`TC-1`、`TC-2`……）都写上；还没有用例覆盖的覆盖项，那一栏留空，空行一眼看得出缺哪些。

## 五、创建测试规程（TD4）

本活动包括以下任务：

a）应根据前置条件和后置条件描述的依赖关系以及其他测试要求，对测试用例进行排序，来导出测试规程；

示例：风险优先级用于对测试用例进行排序。

注1：测试规程中可能包括任何其他必要的操作，例如为设置测试用例前提条件所必需的操作。

b）应识别测试数据和测试环境需求；

注2：虽然该任务可能要在导出测试规程后才能完成，但它通常可以在过程的初期就开始。

c）应根据风险信息中记录的风险暴露级别确定测试规程的优先顺序；

d）在测试规格说明中应记录测试规程；

e）应记录测试依据、测试模型、测试覆盖项、测试用例和测试规程之间的可追溯性；

f）测试规格说明应得到利益相关方的同意。

**本条不适用**：本技能的场合没有那套组织角色，不必另设确认环节。

本步要记录的可追溯性——测试用例到测试规程：每条测试规程一个编号（`TP-1`、`TP-2`……）；追溯的落点是测试规程的「有序执行测试用例」栏，它本身就是测试用例编号的有序列表，规程这份文档不另出对应表。

任务 b）识别出的测试数据和测试环境需求，分别记入测试数据需求与测试环境需求两份文档：一条数据项一行，编号 `DATA-1`、`DATA-2`……；一项环境项一行，编号 `ENV-1`、`ENV-2`……。两份文档各有哪几栏、怎么填，见[文档模板](文档模板.md)。

## 六、完整示例

下面的示例完整走一遍从测试依据到测试规程的过程，每一步都点明根据什么。

### 测试依据

保险报价系统应生成接受信息、拒绝信息或附加超额警告信息的接受信息。

系统将根据申请人在申请当日的整岁年龄，接受 18 周岁以上（含 18 周岁）、80 周岁以下（含 80 周岁）范围内的保险申请人；其他所有输入均应被拒绝。

年龄不低于 70 周岁的受理申请人应通过投保审核，但系统需给出提示：后续发生理赔时，申请人需承担超额免赔费用。

### 测试完成准则

测试完成准则为：等价类划分覆盖率达到 100%，且所有测试用例执行结果均为「通过」。

### 测试模型（TM-1）

根据测试完成准则，构建等价类划分测试模型。测试模型可以用图形表示，也可以用纯文本表示；下面用纯文本把它列出来：

- 范围内的有效输入：18 ≤ 年龄 ≤ 80（PART-1）
- 数值过低的无效输入：年龄 < 18（PART-2）
- 数值过高的无效输入：年龄 > 80（PART-3）
- 实数形式的无效输入：年龄 = 实数（PART-4）
- 字母形式的无效输入：年龄 = 字母（PART-5）
- 特殊字符形式的无效输入：年龄 = 特殊字符（PART-6）
- 满足「接受」消息的条件：18 ≤ 年龄 ≤ 80（PART-7）
- 满足「拒绝」消息的条件：（年龄 < 18）或（年龄 > 80）（PART-8）
- 满足「超额警告」消息的条件：70 ≤ 年龄 ≤ 80（PART-9）
- 满足「优惠提示」消息的条件：40 ≤ 年龄 ≤ 55（PART-10）
- 生成有效输出：任何输入（PART-11）

未规定功能指测试依据中未予以明确的全部功能。识别未规定功能存在一定难度，但测试过程应予以考量：若系统可执行某一未规定功能，则说明在测试项、测试依据或二者中存在缺陷。本案例仅识别出一项未规定功能（系统出现向 40~55 周岁投保人推送优惠提示的非预期需求）。需注意，不同测试人员可识别出完全不同的无效功能。

### 测试覆盖项（TD2）

采用等价类划分方法，可导出以下 8 个测试覆盖项，这些测试覆盖项能够覆盖所有已识别出的等价类：

- TCOV-1：18 ≤ 年龄 ≤ 80（覆盖 PART-1/PART-7/PART-11）
- TCOV-2：年龄 < 18（覆盖 PART-2/PART-8/PART-11）
- TCOV-3：年龄 > 80（覆盖 PART-3/PART-8/PART-11）
- TCOV-4：年龄 = 实数（覆盖 PART-4/PART-11）
- TCOV-5：年龄 = 字母（覆盖 PART-5/PART-11）
- TCOV-6：年龄 = 特殊字符（覆盖 PART-6/PART-11）
- TCOV-7：70 ≤ 年龄 ≤ 80（覆盖 PART-9/PART-1/PART-7/PART-11）
- TCOV-8：40 ≤ 年龄 ≤ 55（覆盖 PART-10/PART-1/PART-7/PART-11）

### 测试用例（TD3）

只要生成可覆盖全部 8 个测试覆盖项的测试用例，即可实现 100% 等价类划分覆盖率。

在生成测试用例时，可能发现单个测试用例有时能够覆盖多个测试覆盖项。尽可能精简测试用例数量具备显著优势，能够缩短测试执行时长；但该优势有时能被以下代价所抵消：一方面确定最小用例集需要额外耗时，另一方面当单个用例覆盖多个覆盖项时，调试工作复杂度可能会大幅提升。

在本例中，有两个测试用例覆盖了多个测试覆盖项，如下所示：

- TC-1：输入「年龄 = 53」，预期结果「接受」（覆盖 TCOV-1 和 TCOV-8）
- TC-2：输入「年龄 = 15」，预期结果「拒绝」（覆盖 TCOV-2）
- TC-3：输入「年龄 = 89」，预期结果「拒绝」（覆盖 TCOV-3）
- TC-4：输入「年龄 = 36.7」，预期结果「拒绝」（覆盖 TCOV-4）
- TC-5：输入「年龄 = w」，预期结果「拒绝」（覆盖 TCOV-5）
- TC-6：输入「年龄 = "」，预期结果「拒绝」（覆盖 TCOV-6）
- TC-7：输入「年龄 = 77」，预期结果「超额警告」（覆盖 TCOV-7 和 TCOV-1）

这 7 个测试用例将证明所有测试覆盖项都已被覆盖，从而达到了测试完成准则中的覆盖率要求。

### 测试规程（TD4）

测试规程只需将测试用例按逻辑顺序排列即可。由于测试用例之间不存在依赖关系，因此可按任意顺序执行。

假设 TCOV-1 因执行频次最高，判定为高风险；TCOV-6 同样判定为高风险，因为开发团队既往经验表明，其对特殊字符的处理存在缺陷。因此，需针对 TCOV-1 和 TCOV-6 设计更多测试用例。

据此能生成一个包含 14 个步骤的简易测试规程 TP-1，该规程既覆盖全部等价类划分，又充分考虑了上述风险因素，具体如下：

1. 建立测试环境
2. 执行 TC-8（「年龄 = 53」）
3. 执行 TC-9（「年龄 = 27」）
4. 执行 TC-10（「年龄 = 66」）
5. 执行 TC-11（「年龄 = 38」）
6. 执行 TC-2
7. 执行 TC-3
8. 执行 TC-4
9. 执行 TC-5
10. 执行 TC-12（「年龄 = &」）
11. 执行 TC-13（「年龄 = #」）
12. 执行 TC-14（「年龄 = ！」）
13. 执行 TC-7
14. 清理并关闭测试环境
