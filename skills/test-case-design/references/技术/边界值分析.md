# 边界值分析

## 一、测试模型

边界值分析的测试模型是带边界的等价类。先划等价类，再标出每个类的边界。这个模型可以用图形表示，也可以用纯文本表示。

边界值分析的目的是根据选择的边界值覆盖率级别（这里要定的是取二值边界测试还是三值边界测试，那是识别测试覆盖项时用的方法，不是覆盖档位——边界值分析没有覆盖档位可选，见第二节），导出能够覆盖测试项每个输入和输出等价类边界的一组测试用例。该方法有如下前提要求：第一，根据测试项的测试依据，可以将测试项的输入和输出划分为若干等价类，测试项对等价类中的所有值的处理方式相似；第二，某些等价类的元素可以从最低到最高无间断地排序；第三，根据经验，有序的连续区间的边界是软件开发中容易出错的地方。导出测试用例是为了对这些边界进行测试。

边界值分析应使用测试项的一个模型，该模型将测试项的输入和输出划分为若干个具有可识别边界的有序集和子集（划分类和子划分），然后使用每个边界来识别测试覆盖项。这些等价类与有序集的等价类对应，这些有序集将构成等价类的测试模型（见[等价类划分](等价类划分.md)）。

示例：一个等价类的定义是从 1 到 10 的整数，该等价类有两个边界，下边界是 1，上边界是 10，这两个输入值将被测试覆盖。

注：对于输出分界，可根据测试项规格说明中描述的过程导出相应的输入等价类。然后从输入等价类中选择测试输入，这些输入等价类可引起测试过程中出现输出等价类。

## 二、测试覆盖项

边界值分析的测试覆盖项是边界值。

边界值分析没有覆盖档位可选，要求全面覆盖所有边界值。

应采用以下两种方法之一识别测试覆盖项：

——二值边界测试；或

——三值边界测试。

对于二值边界测试，应为每个边界识别两个测试覆盖项，分别对应边界上的值以及等价类划分边界外一个增量距离的值。该增量距离应定义为所考虑的数据类型的最小有效值。

对于三值边界测试，应为每个边界识别三个测试覆盖项，分别对应边界上的值，以及等价类划分边界两侧各一个增量距离的值。该增量距离应定义为所考虑的数据类型的最小有效值。

取二值还是三值，见注 2。

注1：某些划分在测试依据中只能识别一条边界。例如，数值型等价类“年龄≥70岁”有一个指定的下边界，但没有明显的上边界。在某些情况下，可使用实际实现中所施加的边界作为边界值，比如输入字段可接受的最大值（此类决策需进行记录，例如，记录在测试规格说明文档中）。

注2：在大多数情况下二值边界测试通常已足够；但是，在某些情况下可能需要进行三值边界值测试（例如，测试人员和开发人员在严格测试中查看到测试项在变量的边界外没有错误发生时）。

注3：在进行二值边界或三值边界测试时，相邻的划分（共享边界的划分）将导致重复的测试覆盖项。在这种情况下，典型的做法是仅执行一次这些重复值。

## 三、导出测试用例

导出测试用例应遵循以下步骤：

应导出测试用例以执行测试覆盖项。

a）确定选择测试用例所实现测试覆盖项的组合方法。两种常见的方法是：

1）一对一，即每个测试用例导出用于执行一个特定测试覆盖项；

2）最小化，即在测试用例中包含测试覆盖项，从而得出最少数量的测试用例，通过导出最小数量的测试用例将所有测试覆盖项至少覆盖一次。

注：选择测试覆盖项组合的其他方法，见[组合测试](组合测试.md)。

b）根据步骤a)中选择的方法，选择纳入当前测试用例的测试覆盖项。

c）确定该测试用例所需的其他输入变量，取任意有效值。

d）将输入应用于测试依据，确定测试用例的预期结果。

重复步骤 b) 至 d)，直到达到所要求的测试覆盖率级别。

## 四、覆盖率

覆盖率按 C＝N÷T 计算，三个量在这门技术里各指什么如下：

——C 边界值是边界值的覆盖率；

——N 是执行的测试用例覆盖的不同边界值的数量；

——T 是边界值的总数量。

要求全面覆盖所有边界值。

宜记录使用二值还是三值边界测试的决策。

## 五、算例

下面的算例完整走一遍从测试依据到覆盖率的过程。

### 测试依据

考虑一个测试项 generate_grading，测试依据如下：

该组件接收一个考试成绩（满分 75 分）和一个课程作业（C/W）成绩（满分 25 分）作为输入，并据此输出该课程的等级，范围为“A”至“D”。等级是通过计算总成绩（即考试成绩与课程作业成绩之和）得到的，规则如下：

| 总成绩 | 等级 |
|:---|:---|
| 大于或等于 70 | “A” |
| 大于或等于 50，但小于 70 | “B” |
| 大于或等于 30，但小于 50 | “C” |
| 不到 30 | “D” |

当检测到无效输入时（例如，分数超出预期范围），则生成错误消息（“FM”）。所有输入均使用整数。

本算例采用二值边界测试，并用一对一的方法导出测试用例。

### 测试模型（TM-1）

对于边界值分析，测试模型由定义有序集合的测试项等价类组成。等价类是根据其边界定义的。根据测试项的有效和无效的输入和输出，确定等价类。

可为输入识别出以下有效等价类（EP）：

| 等价类 | 取值范围 |
|:---|:---|
| EP1 | 0 ≤ 考试成绩 ≤ 75 |
| EP2 | 0 ≤ 课程作业成绩 ≤ 25 |

基于输入最明显的无效等价类如下：

| 等价类 | 取值范围 |
|:---|:---|
| EP3 | 考试成绩 > 75 |
| EP4 | 考试成绩 < 0 |
| EP5 | 课程作业成绩 > 25 |
| EP6 | 课程作业成绩 < 0 |

尽管等价类 EP3 至 EP6 看起来仅在一侧有界，但实际上这些等价类受限于实现相关的最小值和最大值。对于 16 位的整数，这两个值分别为 -32768 和 32767。因此，EP3 至 EP6 可以更加完整地定义，如下（所有成绩都是整数）：

| 等价类 | 取值范围 |
|:---|:---|
| EP3 | 76 ≤ 考试成绩 ≤ 32767（或 75 < 考试成绩 ≤ 32767） |
| EP4 | -32768 ≤ 考试成绩 ≤ -1（或 -32768 ≤ 考试成绩 < 0） |
| EP5 | 26 ≤ 课程作业成绩 ≤ 32767（或 25 < 课程作业成绩 ≤ 32767） |
| EP6 | -32768 ≤ 课程作业成绩 ≤ -1（或 -32768 ≤ 课程作业成绩 < 0） |

接下来，识别输出的等价类。考虑测试项的每个有效输出，导出有效等价类如下：

| 等价类 | 条件 | 取值范围 |
|:---|:---|:---|
| EP7 | “A”的条件 | 70 ≤ 总成绩 ≤ 100 |
| EP8 | “B”的条件 | 50 ≤ 总成绩 ≤ 69 |
| EP9 | “C”的条件 | 30 ≤ 总成绩 ≤ 49 |
| EP10 | “D”的条件 | 0 ≤ 总成绩 ≤ 29 |
| EP11 | “错误信息”（FM）的条件 | 总成绩 > 100 |
| EP12 | “错误信息”（FM）的条件 | 总成绩 < 0 |

其中，总成绩 = 考试成绩 + 课程作业成绩。

和输入相似，输出的边界也受限于与实现相关的最小值和最大值。假设输出使用了 16 位整数存储，其最小值和最大值分别是 -32768 和 32767，则 EP11 和 EP12 需重新定义为：

| 等价类 | 取值范围 |
|:---|:---|
| EP11 | 101 ≤ 总成绩 ≤ 32767（或 100 < 总成绩 ≤ 32767） |
| EP12 | -32768 ≤ 总成绩 ≤ -1（或 -32768 ≤ 总成绩 < 0） |

这里考虑“出错信息”，因为它是一个指定输出。

请注意，上述 12 个等价类都定义了有序集合（这是边界值分析所要求的）。还可以为无序集合确定更多的等价类，但在边界值分析中这些是不需要的（本例测试依据的全部等价类，见[等价类划分](等价类划分.md)）。

### 覆盖率

上述测试套件能够实现二值边界值分析的 100% 边界值覆盖，因为它使所有已识别且可行的测试覆盖项均至少由一个测试用例执行。如果某些识别出的可行边界未得到运行，则只能达到较低级别的覆盖率。

已识别的边界值总数量 T＝24；24 条测试用例覆盖到的边界值数量 N＝24；覆盖率 C 边界值＝N÷T＝24÷24＝100%。
