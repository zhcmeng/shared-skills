# 覆盖率与完成准则

本文讲覆盖率怎么算、算到什么程度算够。每门技术自己的覆盖率定义与各档要求，技术文件的第四节里各自有一份；本文把它们汇在一起做成速查，逐门的细节与算例仍在各技术文件里。主流程第 6 步（自检）按本文判。

## 一、通则

在计算任何测试设计技术的覆盖率时，应使用以下公式：C 等于 N 除以 T，写作 C＝N÷T。三个量是：

——C：特定测试设计技术所达到的覆盖率；

——N：已执行测试用例所覆盖的测试覆盖项的数量；

——T：由测试设计技术识别的测试覆盖项总数量。

不同测试设计技术可达到的覆盖程度不同，覆盖率的范围从 0% 到 100% 不等。

在每项覆盖率的计算中，可能存在若干不可行的测试覆盖项。如果能证明一个测试覆盖项无法被执行，或无法被测试用例覆盖，则应将其定义为不可行。在定义测试覆盖率计算方法时，应明确是计入还是剔除这些不可行项；该选择通常记录在测试计划中。

若对某测试覆盖项做剔除处理，通常需记录其不可行的原因。本技能不含测试执行，这条原因落在产出文档上——写进测试覆盖项清单的「描述」栏（见[文档模板](文档模板.md)第四节），那一栏本来就收附带的信息。

## 二、分母速查

每门技术里 N 和 T 各指什么，见下表；有档位的三门，N 和 T 按档位分别算，表里逐档列出。组合测试一门里的 P-V 对，是参数（P）与它的一个取值（V）构成的配对。各档的 C 另有自己的量名（如 C 等价类、C 分类树_最小化、C 完全组合），完整定义见各技术文件的第四节。

| 技术 | N 是什么 | T 是什么 | 细节 |
|:---|:---|:---|:---|
| 等价类划分 | 已执行测试用例所覆盖的等价类数量 | 已识别的等价类总数量 | [等价类划分](技术/等价类划分.md)第四节 |
| 分类树方法 | 最小化档：执行的测试用例所覆盖的类数量；最大化档：执行测试用例覆盖的唯一组合类的数量 | 最小化档：类的总数量；最大化档：类的唯一组合的总数量 | [分类树方法](技术/分类树方法.md)第四节 |
| 边界值分析 | 执行的测试用例覆盖的不同边界值的数量 | 边界值的总数量 | [边界值分析](技术/边界值分析.md)第四节 |
| 组合测试 | 完全组合档：执行测试用例覆盖的 P-V 对的唯一组合的数量；成对档：执行的测试用例所覆盖的 P-V 对的唯一对的数量；单一选择档：执行的测试用例所覆盖的 P-V 对的数量；基本选择档：已执行的测试用例所覆盖的基本选择组合的数量（即：除了一个测试项参数设置为基本值外，其他的测试项参数设置为有效值），如果全基本值组合已执行则加上 1 | 完全组合档：唯一的 P-V 对的组合的总数（即：每个测试项参数的 P-V 对数的乘积）；成对档：P-V 对的唯一对的总数量；单一选择档：P-V 对的总数量；基本选择档：基本选择组合的总数量（即：除了一个测试项参数设置为基本值外，其他的测试项参数设置为有效值）加上 1（即：当所有被测对象参数设置为基本值时） | [组合测试](技术/组合测试.md)第四节 |
| 判定表测试 | 已执行的测试用例所覆盖的可行判定规则的数量 | 可行判定规则的总数量 | [判定表测试](技术/判定表测试.md)第四节 |
| 状态转移测试 | 全状态档：执行的测试用例所覆盖的状态数量；0-switch 档：执行的测试用例所覆盖的单步有效转移的数量；全转移档：执行的测试用例试图覆盖的有效和无效转移数量；N-switch 档：执行的测试用例所覆盖的 N+1 步有效转移的数量 | 全状态档：状态的总数量；0-switch 档：单步有效转移的总数量；全转移档：有效事件引起的已知状态之间的有效和无效转移总数量；N-switch 档：N+1 步有效转移序列的总数量 | [状态转移测试](技术/状态转移测试.md)第四节 |
| 场景测试（包括用例测试） | 执行的测试用例所覆盖的场景数量 | 场景的总数量 | [场景测试](技术/场景测试.md)第四节 |

## 三、各技术的覆盖率要求

各门技术默认要求覆盖到什么程度，见下表。有档位的三门要先定取哪一档，取哪一档由测试完成准则与风险级别决定。

| 技术 | 覆盖率要求 | 档位 |
|:---|:---|:---|
| 等价类划分 | 全面覆盖所有等价类 | 没有覆盖档位可选 |
| 分类树方法 | 最小化：每个类需至少在一个测试用例中包含；最大化：需对所有类别组合进行测试 | 两档：最小化／最大化 |
| 边界值分析 | 全面覆盖所有边界值（使用二值边界测试） | 没有覆盖档位可选 |
| 组合测试 | 完全组合：要求覆盖所有唯一的 P-V 对组合；成对：要求覆盖所有唯一的 P-V 对的成对组合；单一选择：要求覆盖所有 P-V 对，即每个参数值至少包含一次；基本选择：要求覆盖所有基本选择组合，并包含全基本值组合 | 四档：完全组合／成对／单一选择／基本选择 |
| 判定表测试 | 全面覆盖判定表中的所有有效（可行）规则 | 没有覆盖档位可选 |
| 状态转移测试 | 全状态：要求覆盖状态模型中的所有状态；0-switch：要求覆盖状态模型中的有效单步转移；全转移：要求覆盖状态模型中的有效转移和无效转移；N-switch：要求覆盖状态模型中 N+1 步转移的有效序列 | 四档：全状态／0-switch／全转移／N-switch |
| 场景测试（包括用例测试） | 覆盖主场景和备选场景 | 没有覆盖档位可选 |

边界值分析那一行括号里的二值边界测试，是识别覆盖项时用的方法；取二值还是取三值，宜把决策记下来，见[边界值分析](技术/边界值分析.md)第四节。

上表这些要求出自各门技术的算例，属资料性内容，不是强制规定：一个项目实际要求到什么覆盖率，由测试计划定。不能拿这张表当硬性要求，去否掉测试计划里写的完成准则。

## 四、够不够的自检

**完成准则从哪里取**：测试完成准则（要求的测试覆盖率）是开工输入之一，与测试依据、风险信息一样，从被测项目的测试计划里取（见[流程](流程.md)第一节）；取不到就问用户，不自己编一个。完成准则里除覆盖率之外还可能有别的条件（例如所有测试用例执行结果均为通过），那些要执行之后才能判，本技能不含测试执行，本文只管覆盖率这一部分。

**覆盖率怎么算**：按第一节的式子，用第二节里该技术那一行的 N、T 定义算。先数出这门技术（这一档）识别出的测试覆盖项总数，作 T；再数出其中已被测试用例覆盖到的数量，作 N；两者相除得 C。

**够不够怎么判**：拿 C 与完成准则里要求的覆盖率比。低于要求时，缺哪些覆盖项，看测试用例规格说明末尾「覆盖项 ↔ 用例」对应表里留空的行——空着的行就是还没有用例覆盖的覆盖项（见[文档模板](文档模板.md)第八节）；这些覆盖项要么补上覆盖它们的用例，要么按第一节的规矩当不可行项处理。

**100% 的立场**：默认按 100% 要求。只要条件允许，选定作为测试完成准则的覆盖率水平就设成 100%；有的覆盖率定义严苛，100% 不容易落地，而覆盖率计算允许把无法实现的覆盖项剔除掉，剔完之后 100% 就是可达成的目标。所以覆盖率不满时，正确的做法是剔除不可行覆盖项、记下原因，不是把要求本身降下来。

**完成准则本身低于 100% 时**：从达到 100% 覆盖率所需的测试覆盖项里挑一个子集来测（见[流程](流程.md)第三节）。挑选按风险暴露级别来，放弃与低风险暴露相关的覆盖项；放弃哪几条、为什么放弃，要写出来——理由写进覆盖项清单的「描述」栏，与剔除原因是同一个落点。

**不要求 100% 的情况**：只有一种——完成准则本身定的就低于 100%。覆盖不满不算理由：不可行项按第一节剔除并记原因，可行却没有用例覆盖的，补上用例。
