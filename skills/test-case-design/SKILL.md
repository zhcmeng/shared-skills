# 测试用例设计

本技能内容基于 GB/T 38634 系列标准整理。

本技能自包含：不要联网去搜这份标准，也不要翻本仓库里的标准存档。现行版没有免费公开渠道，搜到的多是二手转述，与标准正文对不上；本地存档一万三千行，翻进去只会把上下文撑爆。技能里没覆盖到的细节，直接问用户，不猜也不翻。

产出五份 Markdown，写入调用时指定的目录：`测试模型规格说明.md`、`测试用例规格说明.md`、`测试规程规格说明.md`、`测试数据需求.md`、`测试环境需求.md`。目录调用时给；没给就先问，不猜默认路径；目录不存在就建。管到用例与规程产完为止——不含测试执行，也不含事件报告。

## 主流程

八步照顺序走。表里的「选中的技术文件」，指第 1 步选定的那几门技术各自在 `references/技术/` 下的那一份。

| 步 | 做什么 | 读哪份文件 |
|:---|:---|:---|
| 0 | 开工前先要到三样东西：测试依据、测试完成准则（要求的覆盖率）、风险信息 | — |
| 1 | 定技术方案：选哪几门技术、怎么组合、各建什么模型、做到什么程度。四个决定每个都要写出依据 | `references/技术选型与组合.md` ＋ `references/流程.md` |
| 2 | TD1 建测试模型：分析依据，按选定技术确定模型表示方法，建模型，记录依据与模型的可追溯性 | `references/流程.md` ＋ 选中的技术文件 |
| 3 | TD2 定测试覆盖项：对模型套用技术导出覆盖项，按风险定优先级，记录可追溯性 | 同上 |
| 4 | TD3 导出测试用例：定前置条件、选输入值、定预期结果，记录可追溯性 | 同上 |
| 5 | TD4 编测试规程：给用例排序，识别测试数据和环境需求，记录可追溯性 | `references/流程.md` |
| 6 | 自检：算覆盖率，判断是否达到完成准则 | `references/覆盖率与完成准则.md` |
| 7 | 按文档模板写出五份规格说明到指定目录 | `references/文档模板.md` ＋ `references/文档示例.md` |

第 0 步是硬要求：三样缺一不可，缺哪样就说缺哪样，不硬开工——后面每一步「做到什么程度」都由这三样定。尤其不要自己编一个完成准则：没有它，模型建多细、覆盖项取全还是取子集、用例导多少条，全都没有依据。

第 7 步写产出时照 `references/文档模板.md` 的栏目填，一个栏目不缺、也不多造；产出文档里只写测试内容，不把技能文件里的节号与出处带出去。

第 6 步算下来覆盖率不够，先回第 4 步补用例——只要覆盖项还能被执行、还能被用例覆盖，就得补上。确实覆盖不了的，要能证明它无法被执行或无法被测试用例覆盖，才按 `references/覆盖率与完成准则.md` 的规矩当不可行项剔除，并把原因记下来。流程允许回走，不是一次过。

## 第 1 步：四个决定，各自要有依据

第 1 步要定四件事，每件都得说得出依据：

| 决定 | 依据从哪来 |
|:---|:---|
| 选哪几门技术 | 三类技术的分工（规格说明类擅长检出遗漏型缺陷、结构类仅能检出多余型缺陷）、质量特性到技术的映射表、依据本身的形状。**这一项标准明确不给方案**——业界对哪门技术有效性最高没有共识，只给了上面这些材料。材料不够就如实说，不编规则 |
| 怎么组合 | 标准的几组搭配：一门技术的产出喂给另一门（等价类划分的覆盖项作场景测试的输入参数等）；以及规格说明类与结构类互补，补各自漏掉的那类缺陷 |
| 各建什么模型 | 技术决定模型形态——状态转移测试建状态图、判定表测试建判定表。选定技术后模型形态就定了；形态由技术反推，不自由发挥 |
| 做到什么程度 | 测试完成准则（要求的覆盖率）和风险级别。模型建到多细、边界取二值还是三值、分类树取最小化还是最大化、组合测试取哪一档、状态转移取哪一档、覆盖项取全还是取子集、高风险处要不要多导用例，都由这两样定 |

依据只有两个来源，每一步、每个字段都要能归到其中之一；归不到的就是设计漏了：

| 来源 | 有哪些 | 技能能不能自己给 |
|:---|:---|:---|
| ① 技能自己给的 | 模型形态由技术决定、覆盖项怎么导出、输入值怎么选、预期结果从测试依据推、规程按前后置依赖排序、环境项的类型清单、编号方案 | 能，写进 references |
| ② 开工输入 | 测试完成准则（要求的覆盖率）、风险信息 | 用法技能给，内容得先从用户或测试计划拿到 |

- 原本还有第三类依据——编号规则、责任人、需要的周期、重置与归档这类取决于被测项目组织安排的字段，已全部砍掉：编号改由本技能给一套建议方案，责任与周期等字段从产出里移除。**所以本技能没有需要「合理默认」的地方**：凡是技能给不出的，都是 ② 那两样开工输入，直接问用户。
- **依据要落进产出，不是心里想过就算**：技术选型与完成准则写进测试模型规格说明的「测试策略摘要」字段；风险决定的优先级写进「优先级」字段——五份产出里有这一栏的是测试模型规格说明、测试用例规格说明、测试规程规格说明这三份，测试数据需求与测试环境需求没有，不另设。写不进产出的依据等于没有依据。
- **四个决定里任何一个写不出依据，就停下来问用户**，不硬选。

## 用词差异

产出文档里，这几个词照左列写，不要换成右列。它们与本领域更常见的说法只差一点，不单列出来最容易写错，写错了就跟技能其余部分对不上。

| 标准要求 | 容易写成 | 为什么 |
|:---|:---|:---|
| 测试模型 | 测试条件 | 本技能统一用前者，不用「测试条件」。两个词只差一个字 |
| 测试依据 | 测试的证据、测试数据 | 它是设计用例所依据的信息源 |
| 测试项 | 测试用例、被测对象 | 指被测的那个东西 |
| 测试覆盖项 | 覆盖点、覆盖目标 | 指模型里要被覆盖的那个元素 |
| 测试规程 | 测试脚本、测试流程 | 指用例的执行顺序，加启动与收尾动作 |
| 测试用例规格说明 | 测试用例文档 | 它是正式的文档名 |
| 应／宜／可 | 统写成「要」 | 顺手把这三个字改成「要」，会把原话的语气带偏 |
| 有效测试用例／无效测试用例 | 正确用例／错误用例 | 导出方法那组术语的固定说法 |
| 一对一方式／最小化方式 | 逐条方式／最少用例方式 | 同上，指选择测试覆盖项组合的两种方法 |
| 测试完成准则 | 测试完备性准则、测试充分性准则 | 后两个名指的是同一件事；本技能全库统一用「测试完成准则」，不跟着换 |
| 未规定功能 | 未定义行为、未指定功能 | 指测试依据中未予以明确的那些功能——测试项若执行了依据里没写的功能，缺陷在测试项或依据那一侧 |

不建术语表：这几个词的意思模型本来就知道，逐条解释只占地方；上面收的是本领域里用法特殊的专有词，照左列写。

## 几处边界

**技术文件只覆盖 TD1–TD3，不覆盖 TD4。** 七份技术文件讲的是建模型、定覆盖项、导出用例这三步；规程怎么排序、怎么编，只在 `references/流程.md` 里讲，技术文件里不出现。走到 TD4 时不必再翻技术文件。

**管理级只作接口。** 测试完成准则与风险等级从被测项目已有的测试计划里取；取不到就问用户，不自己编一个。测试方针、测试计划的编写、测试执行、事件报告都不在本技能范围内。

**七门之外的技术：只告知，不代做。** 看出某处更适合七门之外的技术时，明确告诉用户「这里更适合 X」，并说明 X 管什么，但不替用户做。七门之外还有哪些、各自管什么，见 `references/技术选型与组合.md` 的末节。

**本技能自包含**：不联网找标准，也不翻本仓库的标准存档（理由写在文首）。技能里没覆盖到的细节，直接问用户，不猜也不翻。

## 什么时候读哪份文件

每次都用得上的五份：

- `references/流程.md`：走到 TD1–TD4 每一步时读——四步各要做什么、每步该记录哪一段可追溯性（依据 → 模型 → 覆盖项 → 用例 → 规程）都在这里；末尾有一个从测试依据走到测试规程的完整示例。
- `references/技术选型与组合.md`：第 1 步定技术方案时读——选哪几门技术、怎么组合、各建什么模型、做到什么程度，以及七门之外技术的换用告知。
- `references/文档模板.md`：第 7 步写产出时读——五份规格说明各有哪些栏目、各栏怎么填、编号方案、两张对应表的格式。
- `references/文档示例.md`：第 7 步对着模板拿不准该填成什么样时读——五份文档各收了两个项目的填写示例。
- `references/覆盖率与完成准则.md`：第 6 步自检时读——覆盖率怎么算、算到什么程度算够、缺的覆盖项与不可行项怎么处理。

第 1 步定完技术方案后，选中的哪几门就读哪几门，没选中的不必读：

- `references/技术/等价类划分.md`：选等价类划分时读——模型是等价类，覆盖项就是等价类；有效用例用最小化方式导出、无效用例用一对一方式导出。
- `references/技术/分类树方法.md`：选分类树方法时读——模型是分类树，覆盖项是类别的组合，分最小化与最大化两档。
- `references/技术/边界值分析.md`：选边界值分析时读——模型是带边界的等价类，覆盖项是边界值，取二值还是三值边界测试在这里定。
- `references/技术/组合测试.md`：选组合测试时读——模型是参数取值表，覆盖项是参数的取值组合，分完全组合、成对、单一选择、基本选择四档。
- `references/技术/判定表测试.md`：选判定表测试时读——模型是判定表，覆盖项是判定表的规则（每一列），要求覆盖所有有效（可行）规则。
- `references/技术/状态转移测试.md`：选状态转移测试时读——模型是状态图或状态表，覆盖项是状态与转移，分全状态、0-switch、全转移、N-switch 四档。
- `references/技术/场景测试.md`：选场景测试时读——模型是交互序列，覆盖项是场景，分主场景与备选场景两路；用例测试归在这门里。

七份技术文件各自自包含：给出测试依据，照着就能建模型、定覆盖项、导出用例、算覆盖率，读其中一份不必再翻别的技术文件。
