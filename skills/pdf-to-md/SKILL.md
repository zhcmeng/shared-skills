# PDF 转 Markdown

把 PDF 解析成 Markdown 落到磁盘。解析交给 PaddleOCR 在 AI Studio 上的接口——**云端服务，整份 PDF 会上传到对方服务器**。

正文里引用到的图片会一并下载到本地，引用改写成相对路径。**转换过程不进对话**，正文多长都不占上下文。

## 前置：配一次 token

脚本只从环境变量 `PADDLEOCR_MCP_AISTUDIO_ACCESS_TOKEN` 读 token——名字里那个 `MCP` 是历史原因，与这个 skill 无关，别去改它。

在 `~/.claude/settings.json` 的 `env` 段里设一次：

```json
{
  "env": {
    "PADDLEOCR_MCP_AISTUDIO_ACCESS_TOKEN": "<你的 AI Studio token>"
  }
}
```

没配就直接报错退出，并提示这一处。

## 怎么调

```bash
uv run --with requests --with lxml --with tabulate \
  python <skill目录>/scripts/convert.py <输入…> --output <输出根目录>
```

`<skill目录>` 就是本文件所在目录。参数：

| 参数 | 说明 |
|:---|:---|
| `<输入…>` | PDF 文件、装着 PDF 的目录（递归找 `*.pdf`）、或 PDF 的公网网址，可以给多个 |
| `--output` | 输出根目录，**必填**。不给就报错退出，不猜 |
| `--model` | 接口认的模型名，默认 `PaddleOCR-VL-1.6` |
| `--force` | 已转过的也重转 |
| `--jobs` | 同时最多几个文件在转，默认 4 |

落到磁盘的样子：

```
<输出根>/<PDF 文件名>/<PDF 文件名>.md
<输出根>/<PDF 文件名>/images/<图片>
```

**已经转过的默认跳过**（判据是输出目录里有那份 md）。源 PDF 后来更新过的话，得加 `--force`。

## 两个模型怎么挑

默认 `PaddleOCR-VL-1.6`。要换就显式传 `--model PP-StructureV3`——**两个名字的写法不一样，照抄，别自己统一**。

| | `PaddleOCR-VL-1.6` | `PP-StructureV3` |
|:---|:---|:---|
| 结构 | 版面分析 + 视觉语言模型 | 版面检测 + OCR + 表格 + 公式 + 印章 + 图表，多个模块串联 |
| 擅长 | 扫描、倾斜、弯折、屏幕拍摄、复杂光照；多语言 | 表格：有线表与无线表分两套模型，能细到单元格 |
| 弱点 | 模型大，推理慢 | 官方自述纯英文识别能力有限（默认是中英模型） |

本仓库**没有做过这两个模型的横向对比**，上表照官方文档整理，供指定时参考。

**这个 skill 不做自动路由**：要判断该用哪个，得先知道这份文档表格多不多、是不是扫描件，而这件事只有解析完才知道。

## 配额与错误

- 每天 20000 页（官方文档口径）
- 服务拒了提交时，报错里会带上状态码和它自己写的中文原因——**直接转述给使用者，别自己编解释**
- 网络类错误会自动重试；重试还是不行，报错会说清是「连不上」而不是「服务说不行」

## 已知局限

- 跨页的表格会断成两截（结果是一页一项，服务就是这么返回的）
- 表头的合并单元格（`colspan`）在 Markdown 的管道表格里没法表达，会渲染成前面多出一个空格子
- 正文里的分页标记只在**整行只有一个页码**时才删；「详见第 3 页」这类句子里的页码是正文，留着
- 图片取不回来时，正文里那张就是坏图——地址带签名会过期，重试也没用
- 大文档整份一次提交，中途失败就得整份重来
- 网址输入只支持直接指向 PDF 的公网地址：要登录、要 referer、有反爬的站点，服务那边取不到
