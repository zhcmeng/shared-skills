## 分支：主目录始终停在主分支

**本机每个仓库的主工作目录（平时直接打开、用来拉取主分支的那个目录）始终停在主分支上，
不许用 `git switch` 或 `git checkout` 让它切到别的分支或别的提交。**

要做别的分支，用 `git worktree add <目录> <分支>` 另开一个工作目录，或者另开一份克隆；
用完把另开的目录删掉。`git switch -c <新分支>` 也会把主目录切走，同样不行。

只读操作不受限：`git status`、`git log`、`git diff`、`git show`、`git fetch`、
`git pull --ff-only` 照常用。恢复文件用的 `git checkout -- <文件>` 也不受限，这条规则管的是
让 HEAD 离开主分支的操作。

理由：主目录被切走以后，别的会话、脚本和同步都以为它还在主分支上。忘了切回来，改动就落到错的
分支上，或者主分支长期收不到更新。另开一个目录没有这个问题，也不打断主目录里正在做的事。

用户明确要求在主目录上切分支时，按用户说的做。
