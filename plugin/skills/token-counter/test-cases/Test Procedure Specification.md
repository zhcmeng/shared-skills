# 测试规程规格说明

测试项：`skills/token-counter/scripts/count_tokens.py`（DeepSeek token 精确计数脚本）。

四条规程按风险从高到低排：先跑与计数准确性直接相关的 TP-1，再跑输入来源与报错的 TP-2，然后是与线上口径核对的 TP-4，最后是只有换环境才用得上的 TP-3。

## TP-1 计数正确性主干

**唯一标识符**：TP-1

**目标**：在引擎已装的常规环境里，把各来源、各内容形态、各 BOM 形态的 token 数与字符数逐条核一遍——本任务最要紧的一件事。

**优先级**：高。

**启动**：

1. 确认测试环境符合 ENV-1、ENV-2，引擎 `tokenizers` 已装且版本为 0.22.2。
2. 核 `skills/token-counter/tokenizer.json` 的 sha256 是否为 `89085f12ef79460ac5f66d1119325ddfc694b4ab209d80bbd81d35f081dc9614`（6 367 096 字节）。对不上就先换回官方离线包里的那份，别往下跑。
3. 按测试数据需求备好 DATA-1 至 DATA-11 的各项文本、带 U+FEFF 前缀的变体、带 BOM 字节前缀的变体，以及对应的文件。
4. 建一个临时目录放这些文件，记下路径。

**有序执行测试用例**：

1. 执行 TC-26（中文开头、含空格——文档点名的易错形态）
2. 执行 TC-27（字符数报的是码点个数，不是字节数）
3. 执行 TC-5（文件 + 纯中文 + 带 BOM）
4. 执行 TC-4（`--text` + 纯中文 + U+FEFF 前缀）
5. 执行 TC-6（标准输入 + 纯中文）
6. 执行 TC-30（同一段文本换三种来源，结果应一致）
7. 执行 TC-8（文件 + 中英混排）
8. 执行 TC-7（`--text` + 中英混排）
9. 执行 TC-9（标准输入 + 中英混排 + 带 BOM）
10. 执行 TC-13（`--text` + 特殊 token 字面量）
11. 执行 TC-14（文件 + 特殊 token 字面量）
12. 执行 TC-15（标准输入 + 特殊 token 字面量 + 带 BOM）
13. 执行 TC-16（`--text` 传空字符串）
14. 执行 TC-17（只含 BOM 的文件）
15. 执行 TC-18（标准输入只有 BOM）
16. 执行 TC-29（单个空格、换行、制表符）
17. 执行 TC-28（36 万字符的长文本）
18. 执行 TC-2（文件 + 纯 ASCII + 带 BOM）
19. 执行 TC-1（`--text` + 纯 ASCII）
20. 执行 TC-3（标准输入 + 纯 ASCII）
21. 执行 TC-11（文件 + emoji + 带 BOM）
22. 执行 TC-12（标准输入 + emoji）
23. 执行 TC-10（`--text` + emoji + U+FEFF 前缀）

这个顺序允许变动的程度：第 3 至 15 步（中文、混排、特殊 token、空文本这几组，都是高风险覆盖项）内部可以互换位置；第 16 至 23 步（空白字符、长文本、ASCII、emoji 几组）内部也可以互换位置。两组之间的先后宜保持——高风险那组先跑，出问题时能早看到。第 6 步 TC-30 用到第 3 至 5 步同一段文本，宜排在这三步之后。

**与其他规程的关系**：无前置规程。TP-2、TP-4 在本规程之后执行；TP-4 复用本规程第 19 步 TC-1 的调用方式。TP-3 与本规程无依赖，但要用一个单独的环境，不可与本规程在同一环境里同时跑。

**停止与结束**：

- 出现下列情形应停止：`tokenizer.json` 的 sha256 对不上且拿不到官方那份；脚本本身读不到（路径或权限问题）。这两种都属于环境没备好，不是测试项的问题，停止后先修环境。
- 执行完毕的收尾：删掉临时目录里的测试文件与目录；把本规程各条用例的实际输出与覆盖率自检结果一并记下，尤其记下 TC-25 之外各条与预期值不符的地方。

## TP-2 输入来源选定与报错

**唯一标识符**：TP-2

**目标**：核「文本从哪儿取」「取不到时给什么」这两件事，包括两处依据未规定的组合。

**优先级**：中。

**启动**：

1. 确认引擎已装（同 TP-1 第 1 步）。
2. 按测试数据需求备好 DATA-12（不是合法 UTF-8 的两份字节串）与 DATA-13（一个不存在的路径、一个目录的路径），各写成文件。

**有序执行测试用例**：

1. 执行 TC-31（文件不是合法 UTF-8——两种字节串各跑一次）
2. 执行 TC-32（标准输入不是合法 UTF-8）
3. 执行 TC-20（位置参数指向不可读的路径——不存在的路径与目录各跑一次）
4. 执行 TC-19（`--text` 与位置参数同时给出）
5. 执行 TC-21（两个位置参数、未知选项各跑一次）

这个顺序允许变动的程度：五步之间无依赖，可任意换序。

**与其他规程的关系**：宜在 TP-1 之后执行——TP-1 已把环境摆好，本规程不必重复启动步骤。与 TP-4 无依赖。

**停止与结束**：

- 出现下列情形应停止：环境未备好（同上）。
- 执行完毕的收尾：删掉临时文件；把 TC-19、TC-20 两条的实际观察到的行为单独记出来——这两条对应依据未规定的两处，结论是要在用法说明里补写这两段，不是判测试项通过或不通过。

## TP-3 引擎未装时的自动安装

**唯一标识符**：TP-3

**目标**：核目标机没装计数引擎时，三条兜底路径各自走不走得通。

**优先级**：低。风险信息没有把引擎安装列为风险点，本规程排在最后。

**启动**：

1. 建一个干净虚拟环境，确认里面没有 `tokenizers`（用 `find_spec` 检查，不要只看 `pip list`）。
2. 备三份环境状态：一份全程断网、`wheels/` 可读（给 TC-22）；一份 `wheels/` 下没有可用 wheel、能访问 PyPI（给 TC-23）；一份 `wheels/` 下没有可用 wheel、网络也不通（给 TC-24）。
3. **不要改动测试项目录里的 `wheels/` 与脚本**——制造「wheel 用不上」要靠改环境的可见性（例如换一份不含 wheel 的目录副本），不要删测试项自带的文件。

**有序执行测试用例**：

1. 执行 TC-22（干净环境 + 断网 + 打包 wheel 可用）
2. 执行 TC-23（打包 wheel 用不上 + 能访问 PyPI）
3. 执行 TC-24（打包 wheel 用不上 + 断网）

三步之间必须换环境，不能连着在同一个环境里跑：第 1 步跑完环境里已经装上引擎了，第 2、3 步就测不到安装路径。

**与其他规程的关系**：与 TP-1、TP-2、TP-4 都无依赖，但不可与它们在同一环境里同时执行——本规程会改动环境里装了什么。

**停止与结束**：

- 出现下列情形应停止：干净环境建不起来、或网络状态无法按需要的三份摆好。这时本规程只能记为未执行，不能记为通过。
- 执行完毕的收尾：逐个删掉建立的虚拟环境；记下每次安装后环境里 `tokenizers` 的版本号。

## TP-4 与线上口径核对

**唯一标识符**：TP-4

**目标**：拿官方 API 返回的用量做一次外部核对——本任务里唯一不依赖本机词表、能独立验证 token 数的手段。

**优先级**：高。

**启动**：

1. 确认网络可达 DeepSeek API，且持有具备调用权限的凭据（ENV-5、ENV-6）。
2. 确认本地引擎已装（同 TP-1 第 1 步）。
3. 记下核对用的文本：DATA-2 的 `你好，世界`。

**有序执行测试用例**：

1. 执行 TC-25（把同一段文本发给 API，取回 `usage` 里的输入 token 数，再跑一次本脚本比对）

**与其他规程的关系**：宜在 TP-1 之后执行——TP-1 已确认本机计数在自洽的口径下没出偏差，本规程再引入外部口径；两步结果不一致时，先怀疑本机词表是否为官方那份（回到 TP-1 的启动第 2 步）。

**停止与结束**：

- 出现下列情形应停止：网络不通或凭据不可用。这时本规程只能记为未执行，不能记为通过——缺了它，风险信息点名的那条风险就没有被任何用例独立验证过。
- 执行完毕的收尾：记下 API 返回的用量数值与本脚本的 `tokens` 数值；两者不一致时，按测试依据的计费口径以线上 `usage` 为准，判本脚本的计数为不符。
