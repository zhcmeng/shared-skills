# VS Code 里可见的会话交接

做的是 claude-handoff 的事（把当前工作交给一个新会话），区别只在一个保证：**新会话要出现在 VS Code 的 Claude Code 扩展会话列表里**，用户能在插件界面点开、看历史、接着聊。

## 原理

扩展的会话列表按**当前工作区目录**读取会话文件：`~/.claude/projects/<工作区路径转义>/<会话 id>.jsonl`。`claude --bg` 启动的后台会话会写同样的会话文件。所以只要在 VS Code 打开的工作区根目录启动后台会话，它就会归到那个工作区的列表里。

路径转义的规则：路径里所有不是英文字母、数字的字符（`:`、`\`、`/`、`_`、`.`、空格等）各换成一个连字符，如 `C:\investment` → `C--investment`；转义后超过 200 个字符时截断，末尾再加一段由原路径算出的哈希。比对目录名时不区分大小写。

**列表不会自动刷新**（2026-11-23 实测，扩展 2.1.330）：扩展只在面板挂载时读一次会话文件，之后不监听 `~/.claude/projects/`。窗口开着的时候新建的后台会话不会进列表——那次等了六分钟也没有，重开 VS Code 之后才出现。所以派发后要主动告诉用户：先重开 VS Code 窗口（或 Developer: Reload Window），再去列表里找，别在已经开着的列表里等。

## 步骤

1. **写交接摘要**：任务目标、已经做完什么、下一步做什么、关键文件路径、注意事项；末尾加一段「suggested skills」，列出接手会话该先调用哪些 skill。摘要里不要重复已有文档的内容，给路径。
2. **存摘要文件**：写到工作区根目录下的 `.tmp/vscode-handoff-<名称>/handoff.md`（临时文件统一放 `.tmp/`，不入库）。用文件传给命令，避免反引号和 `$` 被 shell 展开。摘要控制在 8000 字符以内（`wc -c` 看大小）：内容最后作为一条命令行参数传进去，太长会触到 Windows 的命令行长度上限。交接结束后这个目录可以删掉。
3. **确认工作区目录**：后台会话按启动时的工作目录归档成会话文件；扩展按当前工作区目录读会话列表，两者一致才能在窗口里看到。`pwd` 看当前目录（Git Bash 里可能是 `/c/...` 形式，也可能是 `C:/...` 形式，都可以），它应该就是 VS Code 打开的工作区根目录。不是的话先 `cd` 到工作区根目录再派发——从别的目录派发，会话会归到别的项目，当前窗口的插件列表看不到。拿不准用户 VS Code 里打开的是哪个文件夹时，先问一句，不要猜。
4. **派发**（切目录与启动放进同一条命令）：

   ```bash
   cd "<工作区根目录>" && claude --bg --name "<描述性名称>" -- "$(cat "<工作区根目录>/.tmp/vscode-handoff-<名称>/handoff.md")"
   ```

   输出形如 `backgrounded · 18d48325 · <名称>`，记下 8 位 id。
5. **确认会话文件已生成**（轮询到出现，带超时）：

   ```bash
   ID=<8 位 id>
   f=""
   for i in $(seq 1 40); do
     f=$(find ~/.claude/projects -maxdepth 2 -type f -name "$ID*.jsonl" 2>/dev/null | head -1)
     [ -n "$f" ] && echo "$f" && break
     sleep 1
   done
   if [ -z "$f" ]; then echo "40 秒内没找到会话文件"; ls ~/.claude/projects; exit 1; fi
   ```

   只找文件（`-type f`）并限定 `.jsonl`：同名目录（如子代理的目录）也算命中时，拿到的会是目录路径，判定就错了。输出路径里应包含工作区对应的项目目录名（如 `C--investment`，比对不区分大小写）。不含就是第 3 步的目录不对，停下列出来问用户。
6. **告诉用户这几件事**：会话名称；**列表不会自动出现这个新会话——要重开 VS Code 窗口（或 Developer: Reload Window）再去 Claude Code 的会话列表里找**，别在已经开着的列表里等；运行中想看实况，用 `claude logs <id>`（终端画面快照，带控制字符）或 `claude attach <id>`（在这个终端里接上后台会话，它照常运行，Ctrl+Z 退回）；要读最终答复或完整历史，读第 5 步找出的 jsonl 文件。后台会话还在跑的时候，不要在扩展里打开（resume）同一会话——会冲突；跑完再点开接着聊。

## 边界

- **列表里看到的是会话历史。** 打开它等于接续（resume）。后台会话还在跑的时候，不要在扩展里打开同一会话——会冲突；运行中看进展用 `claude logs`、`claude attach` 或只读会话 jsonl 文件，这三个不会冲突（`claude attach` 是官方支持的后台会话查看方式，接上后它会照常运行）。
- **VS Code 打开的是子目录或多根工作区时，以扩展实际使用的工作目录为准。** 拿不准就先问用户 VS Code 里打开的文件夹路径，不要猜。
- 后台任务结束后，job 记录可以用 `claude rm <id>` 清掉；会话文件不受影响，插件列表里照样能看到、能接续。
