# VS Code 里可见的会话交接

做的是 claude-handoff 的事（把当前工作交给一个新会话），区别只在一个保证：**新会话要出现在 VS Code 的 Claude Code 扩展会话列表里**，用户能在插件界面点开、看历史、接着聊。

## 原理

扩展的会话列表按**当前工作区目录**读取会话文件：`~/.claude/projects/<工作区路径转义>/<会话 id>.jsonl`。`claude --bg` 启动的后台会话会写同样的会话文件。所以只要在 VS Code 打开的工作区根目录启动后台会话，它就会出现在那个窗口的会话列表里。

路径转义的样子：`C:\investment` → `C--investment`（冒号和反斜杠各变成一个连字符；路径大小写以实际目录为准，比对时不区分大小写）。

## 步骤

1. **写交接摘要**：任务目标、已经做完什么、下一步做什么、关键文件路径、注意事项；末尾加一段「suggested skills」，列出接手会话该先调用哪些 skill。摘要里不要重复已有文档的内容，给路径。
2. **存临时文件**：写到 `$TEMP/vscode-handoff-<名称>.md`（Git Bash / Windows 环境）。用文件传给命令，避免反引号和 `$` 被 shell 展开。摘要控制在几千字以内：内容最后是作为一条命令行参数传进去的，太长可能触到 Windows 的命令行长度上限（未实测，超长时先精简摘要）。
3. **确认工作区目录**：后台会话按启动时的工作目录归档成会话文件；扩展按当前工作区目录读会话列表，两者一致才能在窗口里看到。`pwd` 看当前目录，它应该就是 VS Code 打开的工作区根目录（如 `/c/investment`）。不是的话先 `cd` 到工作区根目录再派发——从别的目录派发，会话会归到别的项目，当前窗口的插件列表看不到。拿不准用户 VS Code 里打开的是哪个文件夹时，先问一句，不要猜。
4. **派发**（切目录与启动放进同一条命令）：

   ```bash
   cd "<工作区根目录>" && claude --bg --name "<描述性名称>" -- "$(cat "$TEMP/vscode-handoff-<名称>.md")"
   ```

   输出形如 `backgrounded · 18d48325 · <名称>`，记下 8 位 id。
5. **确认会话文件已生成**（轮询到出现，带超时）：

   ```bash
   ID=<8 位 id>
   for i in $(seq 1 40); do
     f=$(find ~/.claude/projects -maxdepth 2 -name "$ID*" 2>/dev/null | head -1)
     [ -n "$f" ] && echo "$f" && break
     sleep 1
   done
   ```

   输出路径里应包含工作区对应的项目目录名（如 `C--investment`，比对不区分大小写）。不含就是第 3 步的目录不对，停下列出来问用户。
6. **告诉用户三件事**：会话名称；去 VS Code 的 Claude Code 会话列表里找它（列表没刷新就切走再切回）；运行中看实况用 `claude logs <id>`——输出是终端画面快照，带控制字符，适合看进展；要读最终答复或完整历史，读第 5 步找出的会话 jsonl 文件。不要同时打开同一会话，跑完再在插件里接着聊。

## 边界

- **列表里看到的是会话历史。** 打开它等于接续（resume）。后台会话还在跑的时候，不要用插件或 `claude attach` 打开同一会话——会冲突；运行中看进展用 `claude logs` 或只读会话 jsonl 文件，这两个不会冲突。
- **VS Code 打开的是子目录或多根工作区时，以扩展实际使用的工作目录为准。** 拿不准就先问用户 VS Code 里打开的文件夹路径，不要猜。
- 后台任务结束后，job 记录可以用 `claude rm <id>` 清掉；会话文件不受影响，插件列表里照样能看到、能接续。
