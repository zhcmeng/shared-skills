# PDF 转 Markdown

把 PDF 解析成 Markdown 写到磁盘。默认走 **AI Studio 官网的网页解析**：脚本打开一个浏览器窗口，把 PDF 上传到官网，等官网解析完，下载官网生成的 JSON，再在本机转成 Markdown。

官网结果是目前最完整的一份。实测分众传媒 2024 年年度报告：第 81 页的权益变动表，官网拿回 16 列，原来的接口只拿回 13 列；第 162～165 页的外币表，官网合并成一张 99 行 × 4 列的表，原来的接口没有合并。

原来的接口还能用，加 `--backend api`。两条路都是**云端服务，整份 PDF 会上传到 AI Studio 的服务器**。

正文里引用到的图片会一并下载到本地，引用改写成相对路径。**转换过程不进对话**，正文多长都不占上下文。

## 前置：官网方式第一次要登录

官网方式要一个能登录 AI Studio 的浏览器。脚本用固定的浏览器配置目录保存登录状态：

- Windows：`%LOCALAPPDATA%\pdf-to-md\browser-profile`
- 其他系统：`$XDG_CONFIG_HOME/pdf-to-md/browser-profile`，没设 `XDG_CONFIG_HOME` 时是 `~/.config/pdf-to-md/browser-profile`

第一次跑转换时，浏览器会停在上传页等你登录（有验证码就在这里完成），登录完脚本自己继续。登录状态留在上面那个目录里，后面不用再登。

**这个目录里是登录 cookie：不要提交到 git，不要外传。** 要换位置就用 `--browser-profile`。

默认用 Edge（Windows）或 Chrome（其他系统）。机器上没有这个浏览器时，用 `--browser-channel` 换一个；也可以先跑 `uv run --with playwright playwright install chromium`，再指定 `--browser-channel chromium`。同一个配置目录只能被一个浏览器占用；脚本报「配置目录已被占用」时，先把开着同一目录的浏览器窗口关掉。

### 本地凭据文件（可选）

不想每次手动登录，可以把账号密码写在仓库外的这个文件里：

- Windows：`%LOCALAPPDATA%\pdf-to-md\credentials.json`
- 其他系统：`$XDG_CONFIG_HOME/pdf-to-md/credentials.json`（没设时是 `~/.config/pdf-to-md/credentials.json`）

格式：

```json
{"username": "你的账号", "password": "你的密码"}
```

脚本在需要登录时自动填表；**有验证码仍然要在浏览器里手动完成**。文件不存在，或者两个字段都留空，就走手动登录。这个文件**不要提交、不要外传**；报错只提文件路径，不会把账号密码写进日志。

`--no-wait-login` 让脚本在没登录时立刻报错，不打开页面等人。体检用它；平常别用。

### 本地 API 的 token

只有 `--backend api` 需要。脚本从环境变量 `PADDLEOCR_MCP_AISTUDIO_ACCESS_TOKEN` 读 token——名字里那个 `MCP` 是历史原因，与这个 skill 无关，别去改它。

在 `~/.claude/settings.json` 的 `env` 段里设一次：

```json
{
  "env": {
    "PADDLEOCR_MCP_AISTUDIO_ACCESS_TOKEN": "<你的 AI Studio token>"
  }
}
```

没配就直接报错退出，并提示这一处。

## 怎么调

### 官网方式（默认）

```bash
uv run --with requests --with lxml --with tabulate --with playwright \
  python <skill目录>/scripts/convert.py <输入…> --output <输出根目录>
```

### 本地 API（`--backend api`）

```bash
uv run --with requests --with lxml --with tabulate --with pypdf \
  python <skill目录>/scripts/convert.py <输入…> --output <输出根目录> --backend api
```

`<skill目录>` 就是本文件所在目录。参数：

| 参数 | 说明 | 哪种方式 |
|:---|:---|:---|
| `<输入…>` | PDF 文件、装着 PDF 的目录（递归找 `*.pdf`）、或 PDF 的公网网址，可以给多个 | 都行 |
| `--output` | 输出根目录，**必填**。不给就报错退出，不猜 | 都行 |
| `--backend` | `official-web`（默认，官网网页）或 `api`（原来的接口） | 都行 |
| `--model` | 接口认的模型名，默认 `PaddleOCR-VL-1.6`。官网方式只能用它；本地 API 可以换 `PP-StructureV3`；财报模式固定用它 | 主要本地 API |
| `--source-type` | `general`（默认）或 `financial`。`financial` 是财报：逐页切分、逐页提交，见下面「财报：逐页提交」 | 只本地 API |
| `--page-jobs` | 财报单页模式下，一份 PDF 里同时最多几页在转，默认 4 | 只本地 API |
| `--debug` | 保留完整过程：官网 JSON、任务详情、网页截图、图片对照和失败原因，见下面「调试：保留完整过程」 | 都行 |
| `--force` | 已转过的也重转 | 都行 |
| `--jobs` | 同时最多几个文件在转。官网方式只有一个浏览器窗口，固定一次一份，默认 1；本地 API 默认 4 | 都行 |
| `--browser-profile` | 浏览器配置目录，默认见上面「前置」 | 只官网 |
| `--browser-channel` | 用哪个浏览器，默认 Edge（Windows）或 Chrome（其他系统） | 只官网 |
| `--web-timeout` | 等在官网上解析完最多多少秒，默认 3600 | 只官网 |
| `--login-timeout` | 等手动登录最多多少秒，默认 600 | 只官网 |
| `--no-wait-login` | 没登录就立刻报错，不等人 | 只官网 |

落到磁盘的样子：

```
<输出根>/<PDF 文件名>/<PDF 文件名>.md
<输出根>/<PDF 文件名>/images/<图片>
```

**已经转过的默认跳过**（判据是输出目录里有那份 md）。源 PDF 后来更新过的话，得加 `--force`。

## 官网方式怎么跑

1. 本地文件直接上传；网址先在本地下载到临时文件。只支持直接指向 PDF 的公网地址（要登录、要 referer、有反爬的站点取不到），下载下来超过 200MB 会在本机就拦下。
2. 上传后跳到任务页。脚本每 2 秒问一次任务详情：状态 `4` 是解析中，`5` 是完成，`-5` 是失败。失败时官网页面上写的是「发生解析错误，请重试」。
3. 完成后优先从任务页的下载菜单取 JSON；菜单取不到时，改用任务详情接口里的同一份结果，并在终端打一行提示。
4. JSON 在本机转成 Markdown；正文里的图片从官网地址逐个下载。
5. 官网结果已经是服务端合并过的跨页表，**不再跑本机的跨页合并**。实测 197 页的分众年报，本机那套合并对官网结果一处都不改。

等解析的时间上限是 `--web-timeout`（默认 3600 秒）。超时或失败时，报错会带上任务页地址和最后看到的状态，可以打开那个页面看一眼。

**官网自述的上传上限是 200MB、1000 页**，超了要在提交前自己拆分。

## 财报：逐页提交（只属于 `--backend api`）

加 `--source-type financial` 后，转换方式会变：

1. 先用 pypdf 把 PDF 切成单页文件；
2. 每一页单独提交给服务；
3. 结果按原页序合起来，图片下载、正文清理、写文件都和普通模式一样。

**为什么要这样**：整本多页提交时，服务会把宽表少读几列。实测分众 2024 年报第 81 页的权益变动表，整本提交只拿回 13 列（缺「减：库存股」「其他」「所有者权益合计」）；同一页切成单页再提交，能拿回完整的 16 列。接口的 `pageRanges` 只是过滤结果，不改变多页解析的这个行为。

财报模式固定用 `PaddleOCR-VL-1.6`，并附带一组实测过的参数：页眉、页脚、页码先剔掉，表格合并，标题重排。这时 `--model` 不能再指定别的模型，给了会报错退出。

跨页的表格只看页边位置：上一页的表贴到页底、下一页的表贴到页顶，就接成一张、表头只留一次。续页多出整列为空的格子，或者把分类行的合计金额单独放到最右一格，会先归位再比列数；归位后仍对不上、或者表里有图片时不接——那两种情况下接起来会错位或丢图。

**官网方式没有这个模式**：官网上传后由服务端整本解析并合并，`--backend official-web` 配 `--source-type financial` 会直接报错。官网的宽表结果本来就更完整，普通模式就够了。

**限制**：财报模式只收本地 PDF，网址要先下载成文件；页数多时总耗时比整本提交长。某一页重试 3 次仍失败时，整份报错并写明是第几页，不会静默少一页。

## 调试：保留完整过程

加 `--debug` 后，转换过程中的东西不只留在内存里：

```
<输出根>/<PDF 文件名>/debug/<时间戳>/
├── task.json              输入、模型、参数（不含 token）
├── result.json            成功时的页数、耗时、缺图
├── error.txt              失败时的异常与栈
├── raw/                   服务原始结果
│   ├── official.json               官网：下载到的完整 JSON
│   ├── task-detail.json            官网：任务详情接口的返回
│   ├── page-0001-attempt-1.jsonl   财报：每页每次尝试一份
│   ├── page-0001-attempt-1.json    这一页的任务号、结果地址或错误
│   ├── result.jsonl                本地 API 普通模式：整份结果
│   └── job.json                    本地 API 普通模式：任务号与结果地址
├── web/                   官网：任务页现场
│   ├── task.json          任务号、任务页网址、用的浏览器配置目录
│   ├── task-page.png      结果区截图
│   └── task-page.html     结果区 HTML
├── pages/                 财报：切出来的单页 PDF
├── parsed/
│   ├── before-merge.jsonl 财报：合并前的页表
│   ├── after-merge.jsonl  财报：合并后的页表
│   └── pages.jsonl        官网与本地 API 普通模式：解析后的页表
└── images.json            图片网址、本地文件名、取没取到
```

`parsed/` 里的 `text` 是原始 HTML，带版面坐标和页面尺寸。跨页表格为什么没合、是不是合错了，可以拿它重新跑判断，不用再提交一次、再花配额。

**调试目录里不保存 cookie、账号、密码。** `task.json` 里只有输入、模型和参数；`web/task.json` 里只有任务号、任务页网址和配置目录的路径。

调试目录按运行时间分开：同一份 PDF 重跑几次就留几份，后一次不覆盖前一次。失败的运行也会留下已经拿到的部分和 `error.txt`；官网方式还会在失败时截一张任务页。

已经转过的文件照旧跳过，不会为了补调试信息再跑一遍；要看它的过程，加 `--force` 重转（会再花配额）。

## 出问题先体检

转换报错、换了台机器、或者第一次用，先跑一次体检：

```bash
python <skill目录>/scripts/doctor.py [--backend api] [--output <输出根目录>]
```

**用系统 python 直接跑，别套 uv。** 体检要查的正是 uv、依赖、token 这几样，套在 `uv run` 里等于先修好了再体检。脚本只用 Python 标准库，环境再坏它自己也起得来，能把缺什么说出来。

默认查的是官网方式：

| 查什么 | 为什么它要紧 |
|:---|:---|
| `uv` 在不在 PATH 上 | 转换命令是 `uv run` 起的，没有它什么都跑不了 |
| 浏览器配置目录写不写得进去 | 登录状态要存在这里；写不进去时第一次登录就白登 |
| 本地凭据文件格式对不对 | 文件坏了会导致自动登录失败；没有文件、或者两个字段都留空，只提示第一次要手动登录，不算不通过 |
| `--output` 给的目录写不写得进去 | 不查的话，要等整份解析完才发现写不进去，只能重跑；不给这个参数就跳过这项 |
| **真转一份自带的 1 页样例** | 要开浏览器；没登录时用 `--no-wait-login` 立刻报错，并提示先跑一次转换完成登录 |

加 `--backend api` 时，第二、三项换成「token 环境变量在不在」，其余一样，最后一项改用本地 API 真转。

本机那几项一次全查完，把毛病一次说清——不用修一个跑一次。**最后一项要花配额（官网配额以页面提示为准；本地 API 是每天 20000 页里扣 1 页）、要等十几秒到几十秒，只有前面全部通过才跑**。

**它认的是产物，不是「命令没报错」。** 它通过了就说明这台机器现在真能转出东西来，不是「看起来能跑」。

报告是一行一项的中文，不通过的那行下面写着怎么修。全部通过退出码 0，有不通过退出码 2。样例转出来的东西落在临时目录里，跑完就删，不会进你的输出目录。

## 两个模型怎么挑（只对 `--backend api` 有效）

官网方式固定按 `PaddleOCR-VL-1.6` 解析，不能换模型。

本地 API 默认也是 `PaddleOCR-VL-1.6`。财报模式固定用它；普通模式要换就显式传 `--model PP-StructureV3`——**两个名字的写法不一样，照抄，别自己统一**。

| | `PaddleOCR-VL-1.6` | `PP-StructureV3` |
|:---|:---|:---|
| 结构 | 版面分析 + 视觉语言模型 | 版面检测 + OCR + 表格 + 公式 + 印章 + 图表，多个模块串联 |
| 擅长 | 扫描、倾斜、弯折、屏幕拍摄、复杂光照；多语言 | 表格：有线表与无线表分两套模型，能细到单元格 |
| 弱点 | 模型大，推理慢 | 官方自述纯英文识别能力有限（默认是中英模型） |

**没有做过这两个模型的横向对比**，上表照官方文档整理，供指定时参考。

**这个 skill 不做自动路由**：要判断该用哪个，得先知道这份文档表格多不多、是不是扫描件，而这件事只有解析完才知道。

## 配额与错误

- **官网方式**：配额以官网页面上的提示为准。状态 `4` 是解析中、`5` 是完成、`-5` 是失败；失败时直接转述官网的原话。
- **本地 API**：每天 20000 页（官方文档口径）。
- 服务拒了提交时，报错里会带上状态码和它自己写的中文原因——**直接转述给使用者，别自己编解释**。
- 网络类错误会自动重试；重试还是不行，报错会说清是「连不上」而不是「服务说不行」。
- 官网方式下载菜单取不到 JSON 时，会自动改用任务详情里的同一份结果；两边都没有才报错。

## 已知局限

- 官网方式要开一个**可见的浏览器窗口**，一次只能处理一份 PDF；批量时按顺序一份一份来，不能并发。
- 官网方式第一次要登录；浏览器配置目录被别的窗口占用时打不开，要先关掉。
- 官网方式不能换模型，也没有财报逐页模式。
- 官网结果是服务端合并的，本机不再做跨页合并；服务端仍没合并的表会保持分开。
- 本地 API 普通模式下跨页的表格会断成两截（结果是一页一项，服务就是这么返回的）；财报模式在上一页的表贴着页底、下一页的表贴着页顶时接回去，其余情况仍保持两张。
- 合并单元格会展开成完整的表格：文字留在合并区的左上格，其余格子留空，列数与原表一致；Markdown 的管道表格本身没有合并单元格的写法。
- 正文里的分页标记只在**整行只有一个页码**时才删；「详见第 3 页」这类句子里的页码是正文，留着。
- 图片取不回来时，正文里那张就是坏图——地址带签名会过期，重试也没用。
- 本地 API 普通模式大文档整份一次提交，中途失败就得整份重来；财报模式逐页提交，一页失败会重试 3 次，仍失败则整份报错并指出页码。
- 财报模式只收本地 PDF；网址要先下载成文件。
- 网址输入只支持直接指向 PDF 的公网地址：要登录、要 referer、有反爬的站点，服务那边取不到。官网方式也一样，只是先在本地把网址下载成文件。
