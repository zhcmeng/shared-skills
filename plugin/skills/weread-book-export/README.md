# weread-book-export

把微信读书里的一整本书导成 Markdown：一章一个文件，另出一份带目录的 `README.md`，插图存到本地。

另外能只搜索，不导出：按完整书名精确找、按标题关键词模糊找、按一组相关词做语义扩展，或按「系列名 + 年份」列全某杂志各期。

这份 README 是给人看的：Claude 跑这个技能时不读它，读的是 [SKILL.md](./SKILL.md)。

## 它怎么拿到正文

微信读书的阅读器把正文画在 `canvas` 上，页面上看得见的 DOM 里一个字都没有——所以「复制页面文本」这类办法在这里不管用。

但它在画之前，会先把整章解密好的 HTML 塞进一个隐藏的容器，画完再把这个容器删掉。技能钩住 `Element.prototype.innerHTML` 的赋值，把这份 HTML 截下来，按段落、标题、插图的先后顺序整理成 Markdown，**一个字不差**，也没有 OCR 的识别错误。它是完整的一章，不受「滚动模式只画两块画布」的限制。

没有预渲染步骤的格式（PDF、导入书可能是这类，尚未实测），退回往 `CanvasRenderingContext2D.prototype.fillText` 上挂钩子：每次绘字都把「字、x、y、字体」记下来，同一基线的字 y 相同、从左往右 x 递增，按 y 归行、行内按 x 排序拼起来，就是屏幕上那一行。

章节边界、目录、插图位置都是从页面上读的；翻页、切模式、点目录都用真实鼠标点击，节奏带随机停顿，不做定时器式的连续请求。

## 装法

跟着 `shared-skills` 插件装好后自动注册，不用单独安装。

只想在这个目录里单独用，把这个目录拷到 `~/.agents/skills/weread-book-export/` 或某个工程的 `.claude/skills/` 下。

跑之前机器上要有 [uv](https://docs.astral.sh/uv/)——脚本靠 `uv run --with playwright` 现装依赖，不用你自己建虚拟环境。

## 第一次跑

**会弹出一个浏览器窗口要你扫码登录微信读书。** 登录态存在：

```
%LOCALAPPDATA%\weread-book-export\browser-profile
```

同一个目录只留一份，之后跑不用再扫。要换账号、或者登录态坏了，删掉这个目录重跑即可。

脚本默认用 Edge。要换 `--browser-channel chrome`。

## 搜书与列各期

搜索用另一个脚本，默认无头，不需要真浏览器：

```bash
# 精确：知道完整书名
uv run --with playwright python "<skill目录>/scripts/weread_search.py" --exact "财经（2026年第5期）"

# 模糊：标题含任意一个关键词
uv run --with playwright python "<skill目录>/scripts/weread_search.py" --fuzzy "估值 价值投资"

# 语义：概念 + 相关词，逐个搜、合并去重
uv run --with playwright python "<skill目录>/scripts/weread_search.py" --semantic "AI" --terms "人工智能,大模型,机器学习"

# 列全某杂志某年的各期：逐期精确搜索，按编号排好
uv run --with playwright python "<skill目录>/scripts/weread_search.py" --series "财经" --year 2026
```

三种搜法的区别：

- **精确**：书名全等才算命中（全角半角、空白、大小写不影响）；同名多本全部列出，不替你挑。
- **模糊**：按标题里的关键词找；给多个词时，标题含**任意一个**就算命中，范围变宽。
- **语义**：给一个概念和一组相关词，逐个词搜、按书合并去重，命中词数多的排前面。相关词由模型生成，不内置词表；不传 `--terms` 时只搜概念本身，并提示补词。它不是向量语义——标题里一个相关词都没有的书找不到。

搜索页一页最多 40 条，所以按「系列名 年份」搜一次列不全。逐期用完整标题搜，每期结果都很少，才拿得到完整名单；命中按标题完全一致来认，《第一财经》这类名字里带相同字样的会被挡掉。

- `--template` 改标题写法，占位符 `{series}`、`{year}`、`{n}`
- `--max` 改搜到第几期（默认 60）
- `--out <文件>` 把清单另写成 Markdown，每期带阅读器地址（只和 `--series` 一起用）

搜索和导出共用登录配置，同一时刻只能开一个浏览器：导出跑着的时候，搜索要么等它跑完，要么加 `--profile <空目录>` 另开一份（搜索不登录也能用）。要登录时加 `--show`。

## 产物

```
<输出目录>/
├── README.md                  # 书名、作者、来源、导出日期、目录
├── 01-版权信息.md
├── 02-推荐序-我们向江南春学什么.md
├── ...
└── images/
    ├── 05-001.jpg             # 第 5 章第 1 张图
    └── 05-002.jpg
```

- 章名里的 `\ / : * ? " < > |` 换成 `-`，超过 40 字截断，序号按目录顺序补零
- 输出目录用书名本身（如 `books/抢占心智`），不要用拼音或英文缩写
- 每章开头是 `# 章名`，小节标题按字号大小映射成 `##`、`###`
- `README.md` 每写完一章就重写一次，中途断了目录也是全的

## 中断与重来

每导完一章就记一次进度，存在 `%LOCALAPPDATA%\weread-book-export\state\<输出目录名>.json`。

- **接着跑**：重跑同一条命令，从没导完的那一章继续
- **从头再来**：加 `--fresh`，或者直接把那个状态文件删掉
- 状态文件在，但你想导到另一个目录：换个 `--out` 就等于开了一份新进度

## 要注意的

- **需要会员**。碰到付费墙会停下报告停在哪一章，不会把半章写进文件。
- **不导笔记和划线**，导的是正文全文。
- **不还原排版**：字号、颜色、分栏都不管，只保留段落与标题层级
- 导出来的内容**只供自己学习用**，别再分发
- 平台要求验证、限流时脚本会停下，不会换 IP、不会反复重试

## 脚本分工

`scripts/` 下每个文件各管一段：

| 文件 | 管什么 |
|:---|:---|
| `weread_export.py` | 导出命令行入口，把下面这些串成一趟导出 |
| `weread_search.py` | 搜索命令行入口：精确、模糊、语义、按系列逐期列全 |
| `weread.py` | 页面上的动作：登录判定、搜书、目录、切滚动模式、装钩子、截预渲染 HTML 与字形、翻章、取图 |
| `issues.py` | 期刊各期的纯逻辑：标题模板、缺号、清单渲染 |
| `matches.py` | 搜书的纯逻辑：标题归一化、精确/模糊匹配、相关词合并排序、文字输出 |
| `content.py` | 预渲染 HTML 拆出的块整理成段落与图片：空白归一、标题层级、图与段的先后 |
| `layout.py` | 字形还原成行、剔噪声、拼段落、切掉翻章时重画的上一屏 |
| `catalog.py` | 目录扁平化成章节列表、生成合法的文件名 |
| `markdown.py` | 渲染章节页与目录页 |
| `state.py` | 断点续跑的状态读写 |
| `browser.py` | 启动浏览器、像人的点击与滚动、随机停顿 |

`layout.py`、`catalog.py`、`markdown.py`、`state.py`、`issues.py`、`matches.py` 有单元测试——它们是不碰浏览器的纯逻辑；`weread_search.py` 的参数检查也有测试，浏览器用替身。浏览器那几层靠实跑验证：每个行为都要连真站点才有意义，拿假对象测等于在测自己写的假对象。

测试在仓库根的 `tests/weread-book-export/` 下：

```bash
bash tests/run.sh weread-book-export
```
