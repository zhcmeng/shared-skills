# 微信读书整本导出

在浏览器里打开微信读书，把一本书从头导到尾：一章一个 `.md`，另出一份带目录的 `README.md`，插图存进 `images/`。正文与屏幕上逐字一致。

正文是画在 `canvas` 上的，DOM 里一个字都没有，所以脚本往 `CanvasRenderingContext2D.prototype.fillText` 上挂钩子逐字截取，不靠 OCR，也没有识别误差。

## 跑之前

- **必须真浏览器**，不能无头：字是画出来的，靠窗口里真绘一遍才截得到。`--headless` 只留给排错。
- 第一次跑会开一个浏览器窗口要扫码登录。登录态存在 `%LOCALAPPDATA%\weread-book-export\browser-profile`，之后不用再扫；退出登录、换账号时删掉这个目录。
- 默认用 Edge（Windows）。要换浏览器加 `--browser-channel <名字>`（`chrome`、`msedge`）。
- 跑一本中等的书要几十分钟。中途可以随时打断，重跑同一条命令会接着走。

## 命令

脚本在本 skill 目录的 `scripts/` 下，路径写全：

```bash
uv run --with playwright python "<skill目录>/scripts/weread_export.py" \
    --title "<书名>" --out "<输出目录>"
```

三种进书方式，按手上的信息挑一个：

| 手上有什么 | 怎么给 |
|:---|:---|
| 只有书名 | `--title "<书名>"`：搜到一条就直接进；**搜到多条会列出来，等用户在窗口里点开那一本**（最多等 5 分钟） |
| 用户已经打开着某本书 | 什么都不用给，`--title` 省掉，脚本从当前这一页接着走 |
| 有阅读器地址 | `--url "https://weread.qq.com/web/reader/<book_id>"`，直接进，不搜索也不等人 |

- **搜到多条时不要替用户挑**：同名书、不同版本、不同作者都会混在结果里，挑错了整本导的都是别的书。
- 断点续跑靠一份状态文件，默认在 `%LOCALAPPDATA%\weread-book-export\state\<输出目录名>.json`；`--state` 可改路径，`--fresh` 删掉它从头再来。
- 已经导过的章不会重做，但**文件存在不算导过**——以状态文件为准。

## 退出码

| 码 | 意思 | 怎么办 |
|:---|:---|:---|
| `0` | 跑完了 | 报产物目录、导了多少章多少图 |
| `2` | 要人来操作：没登录，或者等着用户点开一本书 | 让用户在浏览器窗口里登录或点开书，然后**重跑同一条命令** |
| `3` | 中途停了 | **不要当成跑完了**。把停在哪一章、为什么停原样转告用户 |
| `1` | 其它错误（浏览器起不来等） | 把错误原文贴给用户，别自己改脚本 |

退出码 `2` 重跑同一条命令即可。退出码 `3` 要看停的原因：碰上付费墙、画布撑破渲染上限这类，重跑也是同一个结果，照实告诉用户；「点了下一章没反应」可以重跑一次试试，还停在原处就停下报给用户。

## 排错三条

- **一个字都截不到**：钩子没装上。`install_glyph_hook` 末尾那次 `reload` 不能跳——已经渲染好的章节滚动不会重绘，钩子装晚了整章都是空的。
- **只跑到一半就停**：先看是不是「点了下一章没反应」。脚本滚到章末才点，按钮不在视野里就找不到；报 `stuck` 时把当前章名告诉用户，别重试到被封。
- **某一章没有字**：摄影集、绘本、图册这类整章都是图的书，正文为空是正常的，图片照存。连续三章都空才算钩子失效。

## 产物

```
<输出目录>/
├── README.md            # 书名、作者、来源、导出日期、目录
├── 01-版权信息.md
├── 02-......md
└── images/              # 插图，按章编号：04-001.jpg
```

文件名里的序号按目录顺序补零，章名里的 `\ / : * ? " < > |` 换成 `-`，超过 40 字截断。
