# 微信读书导出与搜索

在浏览器里打开微信读书，把一本书从头导到尾：一章一个 `.md`（章下面的节写成文件里的 `##` 小标题），另出一份带目录的 `README.md`，插图存进 `images/`。正文与屏幕上逐字一致。只搜索、不导出时看「搜索与列全各期」那一节。

正文是画在 `canvas` 上的，但阅读器画之前会先把自己解密好的整章 HTML 塞进一个隐藏的预渲染容器，画完就把容器删掉。脚本在 `Element.prototype.innerHTML` 的赋值上挂钩子，把那份 HTML 截下来，按段落、标题、图片的先后顺序整理；不靠 OCR，也没有识别误差。没有预渲染步骤的格式（PDF、导入书可能是这类，尚未实测），退回往 `CanvasRenderingContext2D.prototype.fillText` 上挂钩子逐字截取。

## 跑之前

- **导出必须真浏览器**，不能无头：字是画出来的，靠窗口里真绘一遍才截得到。`--headless` 只留给排错。搜索页不用真浏览器，搜索脚本默认无头。
- 第一次跑会开一个浏览器窗口要扫码登录。登录态存在 `%LOCALAPPDATA%\weread-book-export\browser-profile`，之后不用再扫；退出登录、换账号时删掉这个目录。
- 默认用 Edge（Windows）。要换浏览器加 `--browser-channel <名字>`（`chrome`、`msedge`）。
- 跑一本中等的书要几十分钟。中途可以随时打断，重跑同一条命令会接着走。

## 命令

脚本在本 skill 目录的 `scripts/` 下，路径写全：

```bash
uv run --with playwright python "<skill目录>/scripts/weread_export.py" \
    --title "<书名>" --out "<输出目录>"
```

三种进书方式，按手上的信息挑一个：

| 手上有什么 | 怎么给 |
|:---|:---|
| 只有书名 | `--title "<书名>"`：搜到一条就直接进；**搜到多条会列出来，等用户在窗口里点开那一本**（最多等 5 分钟） |
| 用户已经打开着某本书 | 什么都不用给，`--title` 省掉，脚本从当前这一页接着走 |
| 有阅读器地址 | `--url "https://weread.qq.com/web/reader/<book_id>"`，直接进，不搜索也不等人 |

- **搜到多条时不要替用户挑**：同名书、不同版本、不同作者都会混在结果里，挑错了整本导的都是别的书。
- 断点续跑靠一份状态文件，默认在 `%LOCALAPPDATA%\weread-book-export\state\<输出目录名>.json`；`--state` 可改路径，`--fresh` 删掉它从头再来。
- 已经导过的章不会重做，但**文件存在不算导过**——以状态文件为准。

## 搜索与列全各期

搜索另有脚本 `scripts/weread_search.py`，默认无头（搜索页不用真浏览器）。按手上的信息挑一种：

```bash
# 精确：知道完整书名
uv run --with playwright python "<skill目录>/scripts/weread_search.py" \
    --exact "财经（2026年第5期）"

# 模糊：标题含任意一个关键词
uv run --with playwright python "<skill目录>/scripts/weread_search.py" \
    --fuzzy "估值 价值投资"

# 语义：概念 + 相关词，逐个搜、合并去重
uv run --with playwright python "<skill目录>/scripts/weread_search.py" \
    --semantic "AI" --terms "人工智能,大模型,机器学习,AIGC,ChatGPT"

# 列全某杂志某年的各期：逐期用完整标题精确搜，按期号排好
uv run --with playwright python "<skill目录>/scripts/weread_search.py" \
    --series "财经" --year 2026
```

- **精确档**：按书名全等比对（全角半角、空白、大小写不影响）；同名多本全部列出，不替你挑；一本都没对上时，把搜索页返回的最多 5 条非同名结果列出来供核对。
- **模糊档**：给多个词时，标题含**任意一个**就算命中，范围变宽，不是变窄。标题里一个词都没有的书不会出现。
- **语义档**：相关词由模型生成并先打印出来，用 `--terms` 可以覆盖。脚本不内置词表——不传 `--terms` 时只搜概念本身，并提示补一组相关词。它是相关词展开，不是向量语义：标题里一个相关词都没有的书找不到。
- **搜索页一页最多 40 条**：模糊档满页会提示；要更多就用语义档给一组相关词，逐个词各搜一页。
- **为什么要逐期搜**：搜索页一次最多回约 40 条、顺序不规则，按「财经 2026」搜一次会漏期，还会混进《第一财经》。逐期搜 `财经（2026年第N期）` 再按标题**完全一致**比对，两个问题一起解决。
- 默认从第 1 期搜到第 60 期（周刊一年 52 期），`--max` 改上限。最大期号以上没搜到不算缺号，那是还没出的期。
- 标题不是 `系列（年份第N期）` 这种写法时，用 `--template` 改。占位符是 `{series}`、`{year}`、`{n}`，`{n}` 必须有；例如 `--template "{series} {year}年第{n}期"`。
- 加 `--out <文件>` 另写一份 Markdown 清单，每期带阅读器地址，可直接拿去跑 `weread_export.py --url`。`--out` 只和 `--series` 一起用。
- **批量导出按 `--series` 的清单逐条跑**，别拿模糊或语义结果凑——搜索页一次最多约 40 条，会漏。同一时刻只能开一个浏览器，所以一条跑完再下一条。
- 清单里的「另见」是标题带系列名和年份、但不是按期号排的条目（年刊、专刊）。它来自一次普通搜索，受 40 条上限影响，可能不全。
- 跑完把共几期、缺哪几期、清单写到哪报给用户。三种搜索档跑完报：共几条、有没有满页、命中词数最多的前几条；语义档还要报哪些词 0 条。
- 搜索和导出共用登录配置，**同一时刻只能开一个浏览器**：导出在跑时，等它跑完，或者给搜索加 `--profile <空目录>`（搜索不登录也能用）。要登录时加 `--show`。

## 退出码

| 码 | 意思 | 怎么办 |
|:---|:---|:---|
| `0` | 跑完了 | 报产物目录、导了多少章多少图 |
| `2` | 要人来操作：没登录，或者等着用户点开一本书 | 让用户在浏览器窗口里登录或点开书，然后**重跑同一条命令** |
| `3` | 中途停了 | **不要当成跑完了**。把停在哪一章、为什么停原样转告用户 |
| `1` | 其它错误（浏览器起不来等） | 把错误原文贴给用户，别自己改脚本 |

退出码 `2` 重跑同一条命令即可。退出码 `3` 要看停的原因：碰上付费墙这类，重跑也是同一个结果，照实告诉用户；报「没能跳到《…》」时可以重跑一次试试，还停在原处就停下报给用户。

搜索三种模式与系列模式共用同一套码：`0` 列完了；`2` 一条也没匹配上，而且现在没登录（加 `--show` 登录后重跑）；`3` 一条也没匹配上，但不是登录问题（检查书名、关键词、`--series` 是否写全、`--template` 是否对）；`1` 其它错误。

## 排错三条

- **一个字都截不到**：钩子没装上。`install_capture_hooks` 末尾那次 `reload` 不能跳——已经渲染好的章节滚动不会重绘，钩子装晚了整章都是空的。
- **只跑到一半，报「没能跳到《…》」**：脚本每章都从目录直接点目标章，点完等章名出现在屏幕第一行；没出现就先跳到第 1 章再跳回来（点当前所在的那一章不会重画），两次都不行才停。停下时把当前章名告诉用户，别反复重试到被封。
- **某一章没有字**：摄影集、绘本、图册这类整章都是图的书，正文为空是正常的，图片照存。连续三章都空才算钩子失效。
- **某一节特别长**：脚本优先从阅读器预渲染的整章 HTML 取正文，那是完整的一章，不受画布画了多少的限制，正常不会截断。只有没有预渲染步骤的格式（PDF、导入书可能是这类，尚未实测）才退回截画布，这时一个单元最多画两块画布（约 7970 像素），脚本发现画满会切到翻页模式逐屏取全，日志里先出现「画到了画布上限，改翻页取全」，属正常，不用管。翻页中途报「翻页后没有新内容」才说明这一屏连字带图都没画出来，停下把节名转告用户。

## 产物

```
<输出目录>/
├── README.md            # 书名、作者、来源、导出日期、目录
├── 01-版权信息.md
├── 02-......md
└── images/              # 插图，按章编号：04-001.jpg
```

文件名里的序号按目录顺序补零，章名里的 `\ / : * ? " < > |` 换成 `-`，超过 40 字截断。

输出目录用**书名本身**（如 `books/抢占心智`），不要用拼音或英文缩写；书名里的 `\ / : * ? " < > |` 换成 `-`。
