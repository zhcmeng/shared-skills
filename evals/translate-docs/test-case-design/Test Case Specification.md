# 测试用例规格说明

测试项：`plugin/skills/translate-docs/` 整门技能。它没有脚本，一份 `SKILL.md` 就是全部——既是技能正文，也是这次测试的依据。对外契约有两条：翻译规则（一比一规范，十条）与工作流（定位目标、确定待译文件、并行派发子代理、校验并汇报）。

三门选定的技术共导出 43 个测试覆盖项：等价类划分 28 个（TM-1 的五组等价类）、判定表测试 8 个（TM-2 的七条可行规则，外加依据未规定的一条）、场景测试 7 个（TM-3 的主场景与六个备选场景），导出 10 条测试用例。

风险等级照开工输入的风险信息判：用户点名的四处——「一比一没守住」「代码与图表被误译」「文件写入的副作用」「边界输入与目标定位」——落在哪几条覆盖项上，那几条判高；其余判中。逐条看：内容侧要译的那八类与要原样保留的那八类（TCOV-1 至 TCOV-16）、产出侧的四条里除说明句以外的三条（TCOV-25、TCOV-26、TCOV-28），以及目标形态那七条规则（TCOV-29 至 TCOV-35），判高——这四处风险的具体判点都在其中；术语那两条、依据未规定的那几条、说明句、以及 TM-3 的七条场景，判中。TM-3 判中，是因为这一层把 TM-1 与 TM-2 已经判过的判定放回完整链里再走一遍，不引入新的判点。

判定看三样：盘上产出的中文版与原文的逐项对照、agent 当轮的回复、以及少数几条要读执行过程的地方（派没派子代理、做没做校验这一步）。措辞不限，判的是那几件事有没有做到。

——TC-1 一条覆盖 29 条覆盖项（TCOV-1 至 TCOV-21、TCOV-23 至 TCOV-28、TCOV-31、TCOV-37）。这是有意合到一次执行里的：该译的与该留的必须在同一份文档里同时在场，「一比一」才判得出来——判「代码块没动」时得同时看到「段落译了」，否则分不清是守住了规则还是整份没动过；拆成几条只是把同一份文档跑几遍，而本体层跑一次就是几分钟、有花费。

——TC-2 是给高风险处多导的一条：代码块与图内 label 是用户点名的第二处风险（「代码与图表被误译」），样本 A 里那几处形态较简单，这一条专门用一份代码与图表密集的文档再走一遍。它重复覆盖 TCOV-9 至 TCOV-11、TCOV-14、TCOV-25、TCOV-26。

——TC-3 覆盖 TCOV-22（原文没有 frontmatter 这一处依据未规定），它同时再验一遍 TCOV-26 与 TCOV-27。

——TCOV-33 那条规则（目录里没有待译的 `.md`）有两种情形：里面都译过了、或者里面根本没有 `.md`。两种情形落到同一个动作上（说「没有可译的文件」、不派子代理），判据是同一条，所以按判定表的规则算一条覆盖项，由 TC-5 覆盖；TC-5 走的是前一种（DATA-6 那个目录里每份 .md 都有中文版），后一种不另立用例，理由记在决策依据那份里。

——「有没有动到不该动的」按盘上文件跑前跑后的差别判，不按 agent 自己在回复里怎么说判。回复里写「原文一字未动」不算数，要拿跑前跑后的字节说话。
