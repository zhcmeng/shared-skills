# 测试环境需求

执行这批测试规程所需的环境要素，逐项列出。头两项是测试运行环境——测试规程在哪儿跑、被测那侧在哪儿执行，两项都是本机；其余各项按用例与规程的需要往外补。每项的来源记在描述里。

| 唯一标识符 | 英文名 | 测试环境项 | 描述 |
|:---|:---|:---|:---|
| ENV-1 | test_runner_host | 测试规程在哪跑 | 本机。规程一条一条跑，每条自己起一轮执行；上一轮的残留（产出的中文版、被动过的文件）不带进下一轮，复位动作见各条数据项的重置需求。这样每轮判「产出了什么、动了什么」时，盘上只有这一轮留下的东西。来源：技能定的（第 0 步判下的测试运行环境） |
| ENV-2 | system_under_test_host | 被测那侧在哪执行 | 本机。被测的那侧就是唤起这门技能的那个 agent——它在本机上读样本、派子代理写产出。两处同在本机，样本与产出走的是同一套文件路径。来源：技能定的（同上） |
| ENV-3 | evidence_capture | 取哪几样凭据 | 每轮执行留下并取走三样：一是 agent 当轮的完整会话记录——它的回复正文、它执行的命令与读写的文件、它派出的子代理（几个、在不在同一条消息里派出去、各自被交代了什么）；二是工作区里每一份相关文件跑前与跑后的完整内容（按字节取，供逐字节比对）；三是产出的中文版全文。判「要读执行过程」那几条的判据（派没派子代理、做没做校验）从第一样里读；其余判据从后两样比出来 |
| ENV-4 | writable_workspace | 可写工作区 | 一处本机上的可写目录，整套规程共用。每一轮开始前，按该条用例的样本（DATA-1 至 DATA-6 里的相应各条）在这里摆一份**可写的副本**，各轮用各的副本，互不串；技能产出的中文版也落在这里。样本的原始件另存一处不动，每轮从它复制，跑完照各条数据项的重置需求收场 |
| ENV-5 | skill_delivery | 技能怎么交到被测那侧 | 把 `plugin/skills/translate-docs/` 整套（`SKILL.md` 一份）当作使用者机器上已经装好的这门技能：落成时按所评测环境的常规装法装一份，被测那侧按平时的调用方式唤起它（按技能名调用，或按技能描述里的触发语触发）。跑 TC-1 至 TC-7、TC-9、TC-10 都走这一套 |
| ENV-6 | locatable_skill_for_name_target | 一个能被按名字定位到的技能 | 使用者机器上另装好的、能在技能名与它的 `SKILL.md` 位置之间对应起来的一个技能（TC-8 的目标就是这样一个名字）。技能名照跑测机器上实际装着的取，落成时在用例配置里写死；这个技能的 `SKILL.md` 与它所在目录要有写权限，好让产出落在它旁边 |

两条说明：

——ENV-1 与 ENV-2 两项是技能在第 0 步判下的测试运行环境，来源记 `技能定的`；其余四项是这一步按用例与规程的需要识别出来的。这六项都不是某一种具体环境的名称，落在哪种机器、哪种装法上由落成那一步照所评测的环境定。

——ENV-3 里「会话记录」这一样，是那些要读执行过程的判据的唯一来源；取不到它，TC-1 与 TC-4 里那几条判据就没法判。落成时先确认这个环境的记录能取到，再落这两条。
