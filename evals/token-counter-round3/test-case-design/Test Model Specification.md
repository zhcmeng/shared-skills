# 测试模型规格说明

## TM-1 三种输入来路与两行输出的等价类划分模型

- **唯一标识符**：TM-1
- **英文名**：input_paths_and_output_partitions
- **目标**：脚本收什么样的来路、认什么样的输入、吐什么样的输出。测试项是 `token-counter` 这个技能（以它自己的 `SKILL.md` 为测试依据）。技能被调用之后模型怎么回话，不在这个模型里，归 TM-4。
- **风险等级**：中。取值分组划错了，导出的用例会漏掉一条来路，但脚本本身不会因此算错数。等级取自开工输入的风险信息。
- **测试策略摘要**：等价类划分。没有与别的技术组合——这一层管的是「收不收、吐什么」，一组组列清即可。测试完成准则是等价类划分覆盖率 100%。
- **测试模型**：等价类清单如下，类别编号沿用 `PART-`。

**输入来路**

| 编号 | 类 | 取值 |
|:---|:---|:---|
| PART-1 | 有效 | 用 `--text` 直接给一段文本 |
| PART-2 | 有效 | 用一个位置参数给一个文件的路径 |
| PART-3 | 有效 | 从标准输入读（管道） |
| PART-4 | 未规定 | 三种来路都不给，标准输入也为空 |

**文件编码**

| 编号 | 类 | 取值 |
|:---|:---|:---|
| PART-5 | 有效 | 不带字节顺序标记的 UTF-8 文件 |
| PART-6 | 有效 | 带字节顺序标记的 UTF-8 文件 |
| PART-7 | 未规定 | 文件不是 UTF-8 的字节序列 |

**文本内容**

| 编号 | 类 | 取值 |
|:---|:---|:---|
| PART-8 | 有效 | 纯 ASCII 字符 |
| PART-9 | 有效 | 纯中文 |
| PART-10 | 有效 | 含基本平面之外的字符（emoji 这类） |
| PART-11 | 有效 | 含 DeepSeek 特殊 token 的字面量 |
| PART-12 | 有效 | 只由空白字符组成 |
| PART-13 | 有效 | 零字符的空文本 |

**输出**

| 编号 | 类 | 取值 |
|:---|:---|:---|
| PART-14 | 有效 | 标准输出打印 `tokens:` 与 `chars:` 两行，两个前缀各在一行的行首 |
| PART-15 | 未规定 | 不打印这两行时，标准输出与退出码各是什么样 |

「未规定」那三类记的是依据里没写到的情形：来路一个都不给时该怎么办、文件不是 UTF-8 时该怎么办、报错时输出成什么样——依据都没写。它们照样要有用例，判据按「依据未规定这一处」记，不自己编一个预期值。

## TM-2 两处长度边界上的边界值分析模型

- **唯一标识符**：TM-2
- **英文名**：length_boundaries
- **目标**：两处「从最低到最高能无间断排开」的量，在边界上取什么值、边界两侧怎么分。这两处是计数最容易出岔子的地方。
- **风险等级**：高。计数边界错一位，报出去的数就是错的，而用户拿它当预算依据。等级取自开工输入的风险信息（用户点名「输入边界与异常」是高风险那两处之一）。
- **测试策略摘要**：边界值分析，取二值边界测试（边界上的值与紧挨边界另一侧的值各取一个）。与等价类划分组合：这两处边界标在 TM-1 划出的有序等价类上。测试完成准则是每处边界的两个取值都被用例覆盖。
- **测试模型**：两个带边界的等价类，编号沿用 `BVA-`。

| 编号 | 有序量 | 边界 | 边界上的取值 | 边界另一侧的取值 |
|:---|:---|:---|:---|:---|
| BVA-1 | 文件字节数 | 0 字节与 1 字节之间 | 0 字节（空文件） | 1 字节 |
| BVA-2 | 文本字符数 | 0 字符与 1 字符之间 | 0 字符（空文本） | 1 字符 |

**解释器版本那一处不建**：依据里那句「仅当平台不符（非 Windows x64 / CPython <3.9）才联网兜底」读得出一个有序量，但它和 TM-3 的 C2 是同一件事的两面——写成边界只会让同一条覆盖项有两个出处。它归 TM-3 的 R3。

两处都取二值不取三值：依据里没有「边界外不许出错」这类要求，取三值要多导两条用例，多出来的判据在依据里找不到出处。

## TM-3 引擎获取的判定表测试模型

- **唯一标识符**：TM-3
- **英文名**：engine_acquisition_decisions
- **目标**：目标机上没装 tokenizers 时，脚本按哪几条规则把引擎弄到手。三处条件怎么组合、各走到哪一步，是这一层要覆盖的。
- **风险等级**：高。这一步走不通，脚本整个跑不起来；它又是首次运行时自动做的，用户看不见过程。等级取自开工输入的风险信息（用户点名「首次运行自动装依赖」是高风险那两处之一）。
- **测试策略摘要**：判定表测试。每条判定规则导一条用例。判定表只有一张，条件三项——依据里「首次运行无需联网」那一句把三条路径写全了，不多不少。测试完成准则是判定规则覆盖率 100%，三条规则各有用例。
- **测试模型**：判定表如下，条件桩 `C`、动作桩 `A`、规则 `R`。

| 条件 ＼ 规则 | R1 | R2 | R3 |
|:---|:---|:---|:---|
| C1 目标解释器里已装 `tokenizers` | 是 | 否 | 否 |
| C2 随包的 wheel 在，且平台相符（Windows x64 且 CPython ≥ 3.9） | — | 是 | 否 |
| A1 直接跑，不装 | ✓ |  |  |
| A2 离线装打包 wheel（`--no-deps`） |  | ✓ |  |
| A3 联网 `pip install tokenizers==0.22.2` |  |  | ✓ |

C2 在 R1 那一列写「—」：引擎已经装好了，走不到看 wheel 那一步，它取什么值都影响不了动作。

## TM-4 技能被调用时的交互序列模型

- **唯一标识符**：TM-4
- **英文名**：invocation_scenarios
- **目标**：用户说一句话到技能给出回话这一段。脚本那一层的取值与边界不进这个模型——那些归 TM-1 与 TM-2；这里只看回话里说了什么、有没有不该说的。
- **风险等级**：高。技能是给模型跑的，回话里的口径错了（比如拿别的模型的数顶替、把算不出来的部分说成能算），用户看不出来。
- **测试策略摘要**：场景测试。输入值从前三个模型导出的覆盖项里取——取值照 TM-1 那几组，条件组合照 TM-3 那三条规则，边界照 TM-2。测试完成准则是场景覆盖率 100%——一条主场景加八条备选场景，各有用例。
- **测试模型**：场景清单如下，编号沿用 `S`。

| 编号 | 场景 | 序列 |
|:---|:---|:---|
| S0 | 主场景：算一段文本或一个文件的 token 量 | 用户给出文本或文件路径并问 token 数 → 技能跑脚本 → 回话里报出那个数 |
| S1 | 只问 token 量 | 用户只问 token 数 → 技能把 token 数报出来（依据说「报告 `N` 即可」，只要求这个数报出来，没说不许附带别的） |
| S2 | 问别的模型的 token 数 | 用户点名 Claude 这类别的模型 → 技能说明本技能不覆盖，不给近似数、不拿别的数顶替 |
| S3 | 要估算调用成本 | 用户问「这段大概多少钱」 → 技能给出数，并说明缓存命中那部分离线算不出来 |
| S4 | 文本里带特殊标记 | 用户给的文本含 `<｜end▁of▁sentence｜>` → 技能按官方词表把它计进去 |
| S5 | 算一整轮对话请求 | 用户要给一整轮对话估 token → 技能说明光算消息正文不够，得先按对话模板拼装成请求再计数 |
| S6 | 输入没法解码 | 用户给的文件含非 UTF-8 字节 → 技能把这一情况报出来、指认是哪个文件 |
| S7 | 一次给多个文件 | 用户给多个文件问合计 → 技能逐个报出并给合计 |
| S8 | 首次运行（引擎还没装） | 用户在没装引擎的机器上直接问 → 脚本自行装好引擎，技能不要求用户额外动手 |

## 依据 → 模型

| 依据的出处 | 模型编号 | 说明 |
|:---|:---|:---|
| `SKILL.md` 用法一节的三种调用方式与两行输出 | TM-1 | `--text`、文件参数、管道三条来路，以及 `tokens:` 与 `chars:` 两行 |
| `SKILL.md` 用法一节「支持两种输入」那句括注的 UTF-8 文本 | TM-1 | 文件编码那三个类的依据 |
| `SKILL.md` 用法一节「首次运行无需联网」与两种安装 | TM-3 | 打包 wheel 优先、联网兜底；行得通与否是条件组合，不是状态迁移 |
| `SKILL.md` 描述栏与口径与边界一节的四条 | TM-4 | 用户会怎么问、技能该怎么答 |
| 用户点名的两处高风险：输入边界与异常、首次运行自动装依赖 | TM-2、TM-3 | 前者落在三个有序集上，后者落在三条规则上 |
