# 测试环境需求

| 唯一标识符 | 英文名 | 测试环境项 | 描述 |
|:---|:---|:---|:---|
| ENV-1 | procedure_host | 测试规程的运行环境 | 本机。要能起子进程、读得回子进程的标准输出与标准错误。这一条管的是「测试规程在哪儿跑」。 |
| ENV-2 | subject_host | 被测那侧的执行环境 | 本机，与 ENV-1 是同一台机器。技能装在这一侧的技能目录下，`scripts/count_tokens.py` 与 `tokenizer.json` 都在；脚本要读的文件样本放在这一侧读得到的工作目录里。这一条管的是「被测那侧在哪儿执行」。 |
| ENV-3 | python_interpreter | CPython 解释器 | 3.9 及以上版本的 CPython，跑在 Windows x64 上——依据里那句「平台相符（Windows x64 且 CPython ≥ 3.9）」指的就是这一档。ENV-1 与 ENV-2 上的命令都用它跑。 |
| ENV-4 | interpreter_with_engine | 装了引擎的解释器 | ENV-3 那一个解释器，且里面已经装好 `tokenizers`。TC-14 用它跑——那一条要的是「已装引擎，直接跑」这个情形。 |
| ENV-5 | clean_interpreter | 干净解释器 | 现建一个 CPython 解释器，里面没有装 `tokenizers`，也没有装别的能顶替它的东西。TC-15、TC-16、TC-25 用它跑——那三条要的是「引擎还没装」这个情形。每跑完一批就删掉重建，不要留着接着用。 |
| ENV-6 | network_egress | 网络出口 | 从本机能连到 PyPI。只有 TC-16 用得到——那一条走的是联网兜底装引擎。TC-25 用不到它：那个解释器里虽然没装引擎，可技能自带随包的 wheel，脚本会走离线那一步装上。 |
| ENV-7 | execution_trace_readback | 执行过程的读回 | 一轮被测那侧跑完之后，读得回它这一轮跑了哪些命令、每一条命令给的是什么入参。TC-17～TC-25 九条的判据都落在「要读执行过程」那一层，靠这一条兑现；读不回来，那九条只能判回话里说了什么，「是不是真去跑了脚本」就判不了。 |

注：ENV-1 与 ENV-2 是第 0 步判下来的两条，默认都是本机，两条指的是同一台机器。依据里提到的「（非 Windows x64 / CPython <3.9）才联网兜底」那一档平台，本机造不出来——要验它得另找一台机器；这一档在本套产出里的落法见测试规程规格说明的 TP-2 与决策依据。
