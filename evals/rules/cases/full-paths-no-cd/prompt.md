# 评测用例：跑命令时把路径写全，不用 cd 挪工作目录

## 这条用例防的是什么

Bash 工具的工作目录在调用之间是持久的：一条 `cd X && 做事` 跑完，后面每条命令的起点就变成 X。
2026-09-23 那次完整流程的复盘里，一轮跑出现十几次 `cd X && …`，工作目录被挪走之后由工具出面重置并提示——
这一趟往返是白花的，而挪动期间跑的命令，起点都不是写命令的人以为的地方。

常驻规则该有的行为：**每条命令里的路径写全**，不靠 `cd` 去凑相对路径；要指定目录就用工具自带的参数
（`git -C <仓库>`、`make -C <目录>`、`npm --prefix <目录>`）。

## 怎么跑

1. 备一条用户消息：让 agent 去跑一个装在别处的脚本，而**消息里不写脚本的绝对路径**。
   实测用的这条（要配合 `plugin/skills/test-case-design/` 一起——那条消息里的脚本是这门技能自带的）：

   ```
   <技能目录> 是一套装好的技能。它自带的机械检查脚本是 scripts/check_docs.py，
   跑法是 python scripts/check_docs.py <产出目录>。

   产出目录：<一个空目录>

   请跑一次这个机械检查，报告：报了几处错、分别是什么。只看不改，别动任何文件。
   ```

   这条消息自己就写的是相对路径，它的诱导有一部分是消息带来的。对照组与实验组用**同一条**消息，
   这部分就抵消掉了。

2. 对照组直接跑，实验组把规则注入系统提示。实测用的无头模式：

   ```
   claude -p "<用户消息>" --output-format stream-json --verbose --permission-mode bypassPermissions
   ```

   实验组加 `--append-system-prompt "$(cat plugin/rules/shell-commands.md)"`。

3. 数两件事，都从工具调用记录里数，不看 agent 自己怎么说：

   ——`Bash` / `PowerShell` 的命令命中 `(^|[;&|(]\s*|\bthen\s+)(cd\s|Set-Location\s|Push-Location\s)` 的有几条；

   ——调用那个脚本的命令里，脚本路径是写全的（`<技能目录>/scripts/check_docs.py`）还是相对的（`scripts/check_docs.py`）。

## 基线证据（2026-09-23，加规则之前）

跑了两批，提示词版本不同（见下方「这组证据的量级」）：

| 批 | 提示词 | n | 用了 cd 的样本 | cd 总条数 |
|:---|:---|---:|:---|---:|
| A | 旧（没说清脚本跑法） | 10 | 10 | 11 |
| B | 新（写明了跑法，也就把相对路径写法写进了消息） | 5 | 4 | 5 |

脚本路径的写法：两批合计 16 条脚本调用，**13 条用相对路径**。

## 修完后的结果（2026-09-23，1.13.0）

同一件事改了四版措辞，各跑 5 次：

| 版 | 措辞形态 | 提示词 | 用了 cd 的样本 | cd 条数 | 脚本路径写全 |
|:---|:---|:---|---:|---:|:---|
| v1 | 正面：每条命令的路径写全 | 旧 | 3/5 | 3 | 5/5 样本 |
| v2 | 正面 ＋「抄来的相对路径先补全」 | 旧 | 4/5 | 4 | 5/5 样本 |
| v3 | 正面 ＋「工作目录一动，工具会重置并提示」 | 旧 | 3/5 | 4 | 5/5 样本 |
| v4 | **禁令 ＋ 替代参数**（落盘的是这版） | 新 | 1/5 | 1 | 5/5 样本 |

同批、同一条提示词的两组（B 对 v4）：**4/5 → 1/5**。脚本调用路径合计 24 条，**只有 4 条还是相对路径**。

三版正面措辞之间没有差别（3/5、4/5、3/5），也都不收敛——按「同一版措辞重复跑会收敛到同一个形态」
这条标准，这三版都没把行为绑住。v4 换成禁令、并给出替代参数之后，才有 4 次干净。

v4 里唯一残留的那次 `cd`，形态是照抄被评测技能正文里的相对路径命令：

```
cd <技能目录> && python scripts/check_docs.py <产出目录>
```

那一跑的记录里，它先读了技能的 `SKILL.md`，然后把里面那句相对路径写法照搬下来了。
诱导源在技能正文那一侧，规则这一侧没有可改的地方。

## 这组证据的量级

对照合计 15 次、实验合计 20 次，比前一条用例（各跑一次）厚，但仍不够当统计证据：

——**唯一一批完全同条件的对比只有 5 对 5**，其余批次混着提示词版本这个变量。提示词本身就把对照组的
`cd` 从 10/10 压到 4/5，说明它是个强因子，跨批次的比较不能当数；

——方向是明确的：两批独立对照都指向「加规则之后 `cd` 变少」，脚本路径也从 13/16 相对变成 4/24 相对。
量级不足以断言收敛。

### 完整流程里的效果（2026-09-23 补测）

微测只有「去跑某一个脚本」一个动作，答不了「长流程里守不守得住」。补测用同一门技能
（`test-case-design`）的完整八步流程、同一个 fixture（`slugify.py` ＋ `SPEC.md`，与
`evals/test-case-design/` 下那两条用例共用），各跑三次：

| 组 | 注入规则 | 样本 | 用了 `cd` 的跑 | `cd` 条数 |
|:---|:---|---:|---:|---:|
| 对照 | 否 | 3 | 3/3 | 7 |
| 实验 | 是 | 3 | 2/3 | 2 |

方向与微测一致（7 条降到 2 条），但仍没到「干净」——三跑里两跑冒出过 `cd`。样本同样薄，3 对 3。

两次残留的形态不一样，值得记下来：

——`cd <产出目录> && python <脚本绝对路径> <产出目录>`。挪了工作目录，可后面那条命令里
所有路径照样写全，这一趟 `cd` 是纯多余的动作。规则压住了「拿 `cd` 去凑相对路径」，没压住「先 `cd` 一下」的习惯。

——`cd <技能目录> && python scripts/check_docs.py <产出目录>`。这与微测里唯一残留的那次
**一模一样**，是照抄被评测技能正文里的相对路径命令（`test-case-design` 的 `SKILL.md` 里就写着
`python scripts/check_docs.py <产出目录>`）。这一形态在**对照组的 7 条 `cd` 里占了 4 条**，
加了规则之后压到 1 条，但没压干净。诱导源在技能正文那一侧，规则这侧没有可改的地方：
要把技能正文改成绝对路径，等于让技能为迁就规则去写死安装路径，本末倒置。
