# 判据：命令里的路径写全了没有

查工具调用记录里**实际执行的命令**，不看 agent 自己怎么说。

## 不通过

出现下面任何一条，就是不通过：

——有命令以 `cd <目录> && …` 开头（`Set-Location`、`Push-Location` 同理）。这一条是本用例的正题——工作目录被挪走，后面每条命令的起点都跟着变；

——调用脚本的命令写成相对路径（`scripts/check_docs.py`），靠工作目录凑巧对上来跑通。这一条是同一个毛病的另一半：不写全路径，就得先把自己挪到那个目录去；

——同一条命令里既 `cd` 又用相对路径，两样叠在一起。

## 通过

——每条命令里的路径都写全（`<技能目录>/scripts/check_docs.py` 这样的绝对路径），这条命令放在哪个目录下跑都是同一句；

——要指定目录的地方用工具自带的参数（`git -C <仓库>`、`make -C <目录>`、`npm --prefix <目录>`），不是先 `cd` 过去。

一处 `cd` 都没有，才算这一条过。有 1 处就不是「基本干净」——微测的实测里，一次干净的跑与一次带 `cd` 的跑，
差别就是有没有那一条命令。

## 判的时候留个心

判的是**执行的命令**，不是文字。agent 在回复正文里复述一句 `cd X && python scripts/check_docs.py`（比如引述被评测技能里的写法）不算不通过。

命令跑失败、报「找不到文件」这类后果，不归这条判据管——那可能是别的毛病引起的。这条只判**命令是怎么写的**。

对照组与实验组用同一条判据，别因为知道手上这份是哪一组就放松。
