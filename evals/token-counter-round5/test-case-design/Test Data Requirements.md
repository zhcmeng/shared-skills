# 测试数据需求

一条数据项一行，写这四栏。表下是几条「正文见下面」的数据项的正文，段首标出编号。

| 唯一标识符 | 英文名 | 描述 | 重置需求 |
|:---|:---|:---|:---|
| DATA-1 | text_samples | 几段直接交过去的文本，共 4 段：第 1 段纯 ASCII；第 2 段纯中文开头；第 3 段中英混排、含空格与换行；第 4 段只有一个 ASCII 字符。四段的正文见下面。**第 3 段这一轮没有哪条用例单独取用**——它那一类取值（中英混排、含空格与换行）由 TC-3 用 DATA-5 那一段兑现，两段同属一类，不必再为第 3 段摆一份。 | 不需要 |
| DATA-2 | empty_text | 空的文本，0 个字符，一个字节都不带。交过去时要写成显式的空串——不写成这样就与「什么可数的东西都没给」在消息上分不开。 | 不需要 |
| DATA-3 | special_token_literal | 含特殊 token 字面形的文本，正文见下面。那个字面形照原样用，不转义、不拆开。 | 不需要 |
| DATA-4 | markdown_sample | 那份 .md 样本，正文见下面。字节按不带字节顺序标记的 UTF-8、末尾一个换行，整份 65 个字节。 | 不需要 |
| DATA-5 | stdin_sample | 走管道那份样本的正文，见下面。 | 不需要 |
| DATA-6 | dead_end_inputs | 走不通的三样：一个不存在的文件路径名 `no-such-file.md`；一个目录 `a-directory/`，里面摆一个占位文件，好让这一层目录进得了版本库；一份按 GBK 写的文件 `gbk-sample.txt`，25 个字节，字节见下面——有意不存成 UTF-8。 | 不需要 |
| DATA-7 | bom_sample | 开头带字节顺序标记的文件：开头 3 个字节是 `EF BB BF`，后面接正文，正文见下面；整份 37 个字节——正文那 34 个（含末尾那个换行）加开头标记的 3 个。 | 不需要 |
| DATA-8 | two_byte_leading_sample | 以两字节宽度的字符开头的文件，正文见下面。开头那 2 个字节就是那个字符本身，不是字节顺序标记的前半截。末尾不带换行——整份 33 个字节，字符数 12；末尾补上换行就成了 34 个字节、13 个字符，TC-12 那两个数就对不上了。 | 不需要 |
| DATA-9 | four_byte_char_sample | 以四字节宽度的字符开头的文本，正文见下面。 | 不需要 |
| DATA-10 | full_dialogue_sample | 要当成一次完整对话请求来估的那段用户消息，正文见下面。 | 不需要 |
