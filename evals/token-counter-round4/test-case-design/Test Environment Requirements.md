# 测试环境需求

执行这批测试规程所需的环境要素，一项一行。头两项是测试运行环境——一条写测试规程在哪儿跑、一条写被测那侧在哪儿执行，两条都是本机。

| 唯一标识符 | 英文名 | 测试环境项 | 描述 |
|:---|:---|:---|:---|
| ENV-1 | procedure_host | 测试规程运行位置：本机 | 规程在本机跑，不另起机器也不进容器。判据全部落在本机的命令输出与盘上文件上。来源：技能定的 |
| ENV-2 | subject_host | 被测那侧执行位置：本机 | 被测那侧在本机执行，与 ENV-1 同一台机器。来源：技能定的 |
| ENV-3 | python_interpreter | 软件：Python 解释器 | 64 位 Windows 上的 CPython，版本不低于 3.9。这一条是引擎包那条道能走通的前提——随技能打包的那份引擎包是按这一档平台编的；平台落到这一档之外时，走的是联网安装那条道（那一条判为不可行，见覆盖项清单） |
| ENV-4 | bundled_vocab_and_wheel | 随技能分发的两份文件：词表 `tokenizer.json` 与 `wheels/` 目录下的引擎包 | 两份都在技能目录里，随技能一起到位，不另外去取。词表的文件名里带官方版本号；引擎包是按 CPython 3.9 及以上、64 位 Windows 编的那一份。这两份齐不齐，决定首次运行能不能离线走通 |
| ENV-5 | clean_interpreter | 软件：没装引擎的解释器 | 一个按 ENV-3 装好的解释器，里面没有装引擎。这一条只给首批那一条用例用：引擎没装，脚本才走得到先装引擎那一步。与 ENV-6 是同一档解释器的两种状态，不是两台机器 |
| ENV-6 | interpreter_with_engine | 软件：已装引擎的解释器 | 一个按 ENV-3 装好的解释器，里面已经装好引擎。除首批那一条之外，其余用例都在这一档解释器上跑；跑之前确认引擎在位，跑的时候不该再出现安装动作 |
| ENV-7 | per_case_workspace | 每条用例各起一个的空工作区 | 每条用例开跑前新起一个空目录当工作区，跑完删掉；上一条留下的东西不进下一条。凡是样本文件（DATA-3、DATA-6）都按编号摆进这个工作区，摆进去之后原始样本不动 |
