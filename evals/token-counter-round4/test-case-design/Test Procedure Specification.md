# 测试规程规格说明

一条规程把一组测试用例按执行顺序串起来，带启动动作与收尾动作。末尾一节把这套规程按落点分批。

## TP-1 三条调用方式与文本取值

| 唯一标识符 | TP-1 |
|:---|:---|
| 英文名 | three_call_routes_and_text_values |
| 目标 | 把三条调用方式与几种文本取值按顺序跑一遍，先拿到正向路径上的基线。 |
| 风险等级 | 高 |
| 执行器 | 子代理（每条用例各起一轮会话真去执行，会话里再派不派由被测那边自己定） |
| 改动文件 | 只读 |
| 启动 | 按 ENV-6 备好装有引擎的解释器，并按 DATA-7 确认引擎在位；按 ENV-7 给每条用例各起一个空工作区。DATA-1 那四段与 DATA-2 那段按编号接进各自的请求；DATA-3 那份文件在跑 TC-4 之前摆进它的工作区，DATA-4 那段在跑 TC-5 之前存成它工作区里的一个文件。 |
| 有序执行测试用例 | TC-1、TC-2、TC-3、TC-4、TC-5、TC-6、TC-7 |
| 与其他规程的关系 | 与 TP-2、TP-3 没有前后依赖，每条用例各起一个工作区。这一条排在最前跑，图的是先看正向路径。 |
| 停止与结束 | 删掉每条用例建的工作区；确认技能目录里那两份随技能分发的文件一个字节都没变。 |

## TP-2 报数口径与回答口径

| 唯一标识符 | TP-2 |
|:---|:---|
| 英文名 | reporting_and_answer_scope |
| 目标 | 把这几种问法各跑一遍，看该报哪几样、哪几样必须点明。 |
| 风险等级 | 中 |
| 执行器 | 子代理（每条用例各起一轮会话真去执行） |
| 改动文件 | 只读 |
| 启动 | 按 ENV-6 备好装有引擎的解释器，并按 DATA-7 确认引擎在位；按 ENV-7 给每条用例各起一个空工作区。DATA-1 第 1 段与 DATA-5 按编号接进各自的请求。 |
| 有序执行测试用例 | TC-8、TC-9、TC-10、TC-11 |
| 与其他规程的关系 | 排在 TP-1 之后、TP-3 之前；与两条都没有前后依赖。 |
| 停止与结束 | 删掉每条用例建的工作区。 |

## TP-3 走不通的路径

| 唯一标识符 | TP-3 |
|:---|:---|
| 英文名 | unusable_paths |
| 目标 | 把三条走不通的路径跑一遍，照实记下被测那边各自怎么处理——依据没写这些情形该怎么办。 |
| 风险等级 | 高 |
| 执行器 | 子代理（每条用例各起一轮会话真去执行） |
| 改动文件 | 只读 |
| 启动 | 按 ENV-6 备好装有引擎的解释器，并按 DATA-7 确认引擎在位；按 ENV-7 给每条用例各起一个空工作区。DATA-6 里那个不存在的路径确认仍然不存在，那个目录建出来，那份 GBK 文件按它的字节放进去。 |
| 有序执行测试用例 | TC-12、TC-13、TC-14、TC-15 |
| 与其他规程的关系 | 排在 TP-2 之后；与其余三条都没有前后依赖。 |
| 停止与结束 | 删掉每条用例建的工作区，连着里面那几条走不通的路径一起清掉。 |

## TP-4 首次运行自动装依赖

| 唯一标识符 | TP-4 |
|:---|:---|
| 英文名 | first_run_installs_bundled_engine |
| 目标 | 在没装引擎的解释器上跑一次，看首次运行那一步走的是不是随技能打包的那一份。 |
| 风险等级 | 高 |
| 执行器 | 子代理（一条用例一轮会话，会话里再派不派由被测那边自己定） |
| 改动文件 | 只读 |
| 启动 | 按 ENV-5 备好没装引擎的解释器，并按 DATA-7 确认里面确实没有引擎；按 ENV-7 起一个空工作区。DATA-1 第 2 段按编号接进请求。 |
| 有序执行测试用例 | TC-16 |
| 与其他规程的关系 | 与其余三条都没有前后依赖——它跑在另一个解释器上。这一条排在最前跑，跑完按 DATA-7 把那个解释器整个丢掉，其余三条不受影响。 |
| 停止与结束 | 删掉工作区；把那个干净解释器整个丢掉（DATA-7 的复位动作），下次再跑这一批之前重新建一个空的。 |

## 各批落到哪

| 批次 | 规程 | 执行器 | 落到哪 | 用例目录名 | 说明 |
|:---|:---|:---|:---|:---|:---|
| 常规批 | TP-1 | 子代理 | `evals/token-counter-round4/` 那一层的批次配置，与同层 `cases/` 下的用例配置 | tp01-01-TC-1-text_ascii_tokens_only、tp01-02-TC-2-text_chinese_both_counts、tp01-03-TC-3-text_mixed_with_spaces、tp01-04-TC-4-file_markdown_path、tp01-05-TC-5-stdin_route、tp01-06-TC-6-empty_text、tp01-07-TC-7-special_token_literal | 三条调用方式与几种文本取值，先跑出正向路径的基线 |
| 常规批 | TP-2 | 子代理 | 同上一层，同一份批次配置 | tp02-01-TC-8-text_for_full_dialogue、tp02-02-TC-9-naming_other_model、tp02-03-TC-10-asks_api_cost、tp02-04-TC-11-asks_cost_and_chars | 报数口径与回答口径，跟着 TP-1 在同一批里跑 |
| 常规批 | TP-3 | 子代理 | 同上一层，同一份批次配置 | tp03-01-TC-12-no_route_given、tp03-02-TC-13-file_missing、tp03-03-TC-14-path_is_directory、tp03-04-TC-15-file_not_utf8 | 三条走不通的路径，照实记录被测那边的实际回应 |
| 干净解释器批 | TP-4 | 子代理 | `evals/token-counter-round4/` 那一层另起一份批次配置，用例配置并进同层 `cases/` | tp04-01-TC-16-first_run_installs_bundled_engine | 只有一条用例；这一批的解释器里不装引擎，靠首次运行那一步自己装上 |

两批的判据都落在「要读执行过程」那一层，都落成评测用例；分成两批不是按判据分的，是按解释器的状态分的——装不装引擎只能整批配一次，配在批次那一层，一批里每条用例都会跟着做一遍，所以「没装引擎」那一条只能单独成批。
