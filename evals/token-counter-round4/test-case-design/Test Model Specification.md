# 测试模型规格说明

三门技术各建一个模型，下面分三节列出。文档末尾是「依据 → 模型」对应表。

## TM-1 输入取值与报数口径的等价类划分模型

- **唯一标识符**：TM-1
- **英文名**：input_and_reporting_partitions
- **目标**：技能收哪几种输入、按哪条道取到要数的文本、报回来的是哪几样。数得准不准不在这里，那归词表与引擎那一组。
- **风险等级**：高。风险信息点名了输入边界与异常这一处。
- **测试策略摘要**：等价类划分。与 TM-2、TM-3 各建各的模型，不互相喂数据——TM-1 管输入怎么进来、报什么回去，TM-2 管什么条件下该报哪几样，TM-3 管一次请求走多远。测试完成准则是等价类划分覆盖率 100%，覆盖全部等价类。
- **测试模型**：等价类清单如下，按输入处理、内部处理、输出处理三组列，类别编号沿用 `PART-`。

输入处理：调用方式

- PART-1 有效：命令行上直接给一段文本
- PART-2 有效：给一个存在的 UTF-8 文本文件路径
- PART-3 有效：把内容用管道从标准输入喂进来
- PART-4 无效：三条调用方式一条都没给
- PART-5 无效：给的文件路径不存在
- PART-6 无效：给的路径指向一个目录
- PART-7 无效：文件存在，但不是 UTF-8 文本

输入处理：文本内容

- PART-8 有效：纯 ASCII 文本
- PART-9 有效：含中文的文本
- PART-10 有效：中英混排、含空格的文本
- PART-11 有效：空文本（0 个字符）
- PART-12 特殊：含特殊 token 字面形的文本

内部处理：词表与引擎

- PART-13 有效：按官方词表的规范语义加载随技能分发的那份词表
- PART-14 无效功能：改用另一条兼容加载路径读同一份词表
- PART-15 有效：目标机上没装引擎，脚本先装上随技能打包的那一份
- PART-16 有效：平台不符时改走联网安装那条道
- PART-17 有效：目标机上已装引擎，不触发安装

输出处理：报回来的东西

- PART-18 有效：报出 token 数与 UTF-8 字符数两样
- PART-19 有效：用户只要 token 量时，报出 token 数（依据说的是「只问 token 量时，报告 `N` 即可」——那是允许，多报一样字符数不算没做到）
- PART-20 有效：用户问调用成本时，给出估算并点明离线算不出缓存命中
- PART-21 有效：用户点名当前官方词表时，照常给精确数
- PART-22 有效：用户点名别的模型时，明确说明不覆盖
- PART-23 无效功能：给出别的模型的近似 token 数

PART-14 与 PART-23 是无效功能：依据里明令不许出现，测试项若真这么做了，缺陷在测试项那一侧。PART-14 那条另有可查的痕迹——改用兼容加载路径之后，纯中文开头的文本会数出 0，那个数一眼看得出来不对。

## TM-2 报数口径的判定表模型

- **唯一标识符**：TM-2
- **英文名**：answer_scope_decision_table
- **目标**：一句请求进来之后该报哪几样、哪几样必须点明。至于数出来的值对不对，归 TM-1。
- **风险等级**：中。风险信息点名的是输入边界与首次运行装依赖两处，不在这一个模型上。
- **测试策略摘要**：判定表测试。与 TM-1、TM-3 各建各的模型。测试完成准则是判定表测试覆盖率 100%，只算可行的判定规则——这张表里五条规则都可行，没有不可行的。
- **测试模型**：用判定表表示，见下表；表后是逐条规则清单。

| 条件与动作 | 规则 1 | 规则 2 | 规则 3 | 规则 4 | 规则 5 |
|:---|:---|:---|:---|:---|:---|
| 条件 C1：用户点名的是别的模型 | F | F | F | F | T |
| 条件 C2：用户问的是这次调用的成本或预算 | F | F | T | T | — |
| 条件 C3：用户只要 token 量，没问字符数 | T | F | T | F | — |
| 动作 A1：报出精确 token 数 | T | T | T | T | — |
| 动作 A2：报出 UTF-8 字符数 | — | T | — | T | — |
| 动作 A3：点明缓存命中算不出、计费以用量为准 | F | F | T | T | F |
| 动作 A4：点明不覆盖该模型、不给近似数 | F | F | F | F | T |

逐条规则读出来：

- 规则 1：C1＝F、C2＝F、C3＝T——报出精确 token 数。A2 与 A3 在这一列都写成「—」：依据只说「用户只问 token 量时，报告 `N` 即可」，那是允许，不是「只许报 `N`」——顺带报一样字符数不算没做到。A3 在这个条件下本来也不触发（没问成本）。
- 规则 2：C1＝F、C2＝F、C3＝F——报 token 数与字符数两样。
- 规则 3：C1＝F、C2＝T、C3＝T——报 token 数，并点明缓存命中算不出、计费以用量为准。A2 同规则 1，写成「—」。
- 规则 4：C1＝F、C2＝T、C3＝F——报 token 数与字符数两样，并点明缓存命中算不出、计费以用量为准。
- 规则 5：C1＝T——只点明不覆盖该模型、不给近似数。C2 与 C3 在这一列都写成「—」，它管的是四种条件组合：C2＝T 配 C3＝T、C2＝T 配 C3＝F、C2＝F 配 C3＝T、C2＝F 配 C3＝F。合并的理由是 C1＝T 时该报的只有「点明不覆盖、不给近似数」这一样，后面两个条件管不到该报哪几样了。A1 也写成「—」：依据禁的是绕开本技能另找一个数顶上、以及给近似估算法，没说报出 DeepSeek 这个精确数本身违规——报了但标明是 DeepSeek 的、不当成点名那个模型的数，不算违规。

## TM-3 一次计数请求的交互序列模型

- **唯一标识符**：TM-3
- **英文名**：counting_request_scenarios
- **目标**：一句请求从进来到结果报回，中间走过哪些步；以及这条序列在哪几处会分岔。
- **风险等级**：中。风险信息点名的两处里，只有「首次运行自动装依赖」那一处在这条序列上，且已在 TM-1 里判为高。
- **测试策略摘要**：场景测试。等价类划分导出的调用方式与文本取值，用来给这一门的用例挑输入参数（见 TM-1）；场景本身照 TM-3 走。测试完成准则是覆盖主场景与全部备选场景。
- **测试模型**：用交互序列表表示。每个动作用一个标识符表示，`U` 打头的是用户那侧的动作，`S` 打头的是测试项这一侧的动作。

公共的几步先列在这里，各场景用标识符引用：

- U1：用户提出一句算 token 的请求
- S1：技能按名唤起，读到自己那份说明正文
- S2：定位到计数脚本所在的目录
- S3：用绝对路径把脚本调起来，按调用方式把要数的文本交过去
- S4：脚本按官方词表的规范语义加载随技能分发的那份词表，数出 token 数
- S5：脚本数出 UTF-8 字符数，把两样打成两行
- S6：技能把数报回给用户

各场景如下：

| 场景 | 类型 | 交互序列 |
|:---|:---|:---|
| 一次计数请求走完 | 主场景 | U1、S1、S2、S3、S4、S5、S6 |
| 点名的是别的模型 | 备选场景 | U1、S1、S1.1、S6.1 |
| 问的是调用成本 | 备选场景 | U1、S1、S2、S3、S4、S5、S6.2 |
| 文本要喂进完整对话请求 | 备选场景 | U1、S1、S2、S3.1、S4、S5、S6 |
| 目标机是干净的、没装引擎 | 备选场景 | U1、S1、S2、S3、S4.1、S5、S6 |
| 用户只要 token 量 | 备选场景 | U1、S1、S2、S3、S4、S5、S6.3 |

序列里那几步的差别：

- S1.1：技能读到的说明正文里写着「只覆盖当前官方词表；点名别的模型时明确说明不覆盖，不给近似估算」这一条，序列就此分岔，不走脚本。
- S6.1：只说明本技能不覆盖该模型、不给近似数，一个数都不报。
- S6.2：在报数之外多一步，点明离线算不出缓存命中、计费以接口返回的用量为准。
- S3.1：在把文本交过去之前多一步，先按对话模板把这段文本拼装成一次完整请求，再交给脚本数。
- S4.1：脚本发现目标机上没装引擎，先装上随技能打包的那一份，再加载词表计数。
- S6.3：只把 token 数报回，不报字符数。
