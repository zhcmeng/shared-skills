# 测试用例规格说明

分五块写：测试覆盖项、测试用例、覆盖项与用例的对应表、覆盖率自检、成品落点。

## 测试覆盖项

对 TM-1、TM-2、TM-3 三个模型套用各自的技术，导出下面这些覆盖项。风险等级照第 0 步判下来的两档写。

| 唯一标识符 | 英文名 | 描述 | 风险等级 | 可追溯性 |
|:---|:---|:---|:---|:---|
| TCOV-1 | text_argument_route | 命令行上直接给一段文本这条调用方式（PART-1） | 高 | TM-1 的 PART-1 |
| TCOV-2 | file_argument_route | 给一个存在的 UTF-8 文本文件路径这条调用方式（PART-2） | 高 | TM-1 的 PART-2 |
| TCOV-3 | stdin_route | 把内容用管道从标准输入喂进来这条调用方式（PART-3） | 高 | TM-1 的 PART-3 |
| TCOV-4 | no_route_given | 三条调用方式一条都没给（PART-4） | 高 | TM-1 的 PART-4 |
| TCOV-5 | file_missing | 给的文件路径不存在（PART-5） | 高 | TM-1 的 PART-5 |
| TCOV-6 | path_is_directory | 给的路径指向一个目录（PART-6） | 高 | TM-1 的 PART-6 |
| TCOV-7 | file_not_utf8 | 文件存在，但不是 UTF-8 文本（PART-7） | 高 | TM-1 的 PART-7 |
| TCOV-8 | ascii_text | 纯 ASCII 文本（PART-8） | 中 | TM-1 的 PART-8 |
| TCOV-9 | chinese_text | 含中文的文本（PART-9） | 中 | TM-1 的 PART-9 |
| TCOV-10 | mixed_text_with_spaces | 中英混排、含空格的文本（PART-10） | 中 | TM-1 的 PART-10 |

| TCOV-12 | special_token_literal | 含特殊 token 字面形的文本（PART-12） | 中 | TM-1 的 PART-12 |
| TCOV-13 | canonical_tokenizer_load | 按官方词表的规范语义加载随技能分发的那份词表（PART-13） | 中 | TM-1 的 PART-13 |

| TCOV-16 | network_fallback_install | 平台不符时改走联网安装那条道（PART-16） | 高 | TM-1 的 PART-16 |
| TCOV-17 | engine_already_installed | 目标机上已装引擎时不触发安装（PART-17） | 高 | TM-1 的 PART-17 |
| TCOV-18 | two_line_output | 报出 token 数与 UTF-8 字符数两样（PART-18） | 中 | TM-1 的 PART-18 |
| TCOV-19 | tokens_only_report | 用户只要 token 量时报出 token 数（PART-19；多报一样字符数不算没做到） | 中 | TM-1 的 PART-19 |
| TCOV-20 | cost_caveat_stated | 用户问调用成本时，点明离线算不出缓存命中（PART-20） | 中 | TM-1 的 PART-20 |
| TCOV-21 | deepseek_named_precise | 用户点名当前官方词表时照常给精确数（PART-21） | 中 | TM-1 的 PART-21 |
| TCOV-22 | other_model_disclaimed | 用户点名别的模型时明确说明不覆盖（PART-22） | 中 | TM-1 的 PART-22 |
| TCOV-23 | no_approximation_for_other_model | 不得给出别的模型的近似 token 数（PART-23，无效功能） | 中 | TM-1 的 PART-23 |
| TCOV-24 | rule1_tokens_only | 判定规则 1：不点名别的模型、不问成本、只要 token 量——报出 token 数（多报一样字符数不算没做到） | 中 | TM-2 的规则 1 |
| TCOV-25 | rule2_both_counts | 判定规则 2：不点名别的模型、不问成本、要字符数——报 token 数与字符数两样 | 中 | TM-2 的规则 2 |
| TCOV-26 | rule3_cost_token_only | 判定规则 3：问成本、只要 token 量——报 token 数，并点明缓存命中算不出 | 中 | TM-2 的规则 3 |

| TCOV-28 | rule5_other_model_only_disclaimer | 判定规则 5：点名别的模型——只点明不覆盖，不给近似数、不拿别的数顶替 | 中 | TM-2 的规则 5 |
| TCOV-29 | scenario_main_count | 主场景：一次计数请求走完（U1、S1、S2、S3、S4、S5、S6） | 高 | TM-3 的「一次计数请求走完」 |
| TCOV-30 | scenario_other_model | 备选场景：点名的是别的模型，序列在读到那一条规矩处分岔（U1、S1、S1.1、S6.1） | 中 | TM-3 的「点名的是别的模型」 |
| TCOV-31 | scenario_cost_question | 备选场景：问的是调用成本，报数之外多点明一句（U1、S1、S2、S3、S4、S5、S6.2） | 中 | TM-3 的「问的是调用成本」 |
| TCOV-32 | scenario_full_dialogue | 备选场景：文本要喂进完整对话请求，交过去之前先拼装（U1、S1、S2、S3.1、S4、S5、S6） | 中 | TM-3 的「文本要喂进完整对话请求」 |
| TCOV-33 | scenario_first_run | 备选场景：目标机是干净的、没装引擎，脚本先装上再计数（U1、S1、S2、S3、S4.1、S5、S6） | 高 | TM-3 的「目标机是干净的、没装引擎」 |
| TCOV-34 | scenario_tokens_only | 备选场景：用户只要 token 量，只把 token 数报回（U1、S1、S2、S3、S4、S5、S6.3） | 中 | TM-3 的「用户只要 token 量」 |

**TCOV-16 判为不可行，已从分母里剔除**，原因写在这一栏里：这一条要求的目标平台不是本机这一种（要么不是 64 位 Windows，要么 CPython 低于 3.9），这样才能把它逼到联网安装那条道上。手上只有本机这一种平台，造不出那台机器，也就没有一条用例能执行到它。剔除的是这一条覆盖项，不是这一门技术——等价类划分这一门其余 22 条照旧全部覆盖。

## 测试用例

一条用例一行，输入那一栏写的是用户会说的那句话，原样写出来。

| 唯一标识符 | 英文名 | 目标 | 风险等级 | 前置条件 | 输入 | 预期结果 | 判据落在哪一层 |
|:---|:---|:---|:---|:---|:---|:---|:---|
| TC-1 | text_ascii_tokens_only | 验证直接给一段纯 ASCII 文本、只问 token 量时，报回的 token 数对，且全程没有触发安装 | 高 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好 | 一句话：「用 DeepSeek 的 tokenizer 帮我数一下这段有多少 token：<DATA-1 里那段纯 ASCII 文本，原样接在这句话后面>」 | 报回的 token 数等于 10（那段文本在当前官方词表下的精确值）；全程没有出现安装引擎的动作——既没有解压引擎包，也没有执行装引擎的命令 | 要读执行过程 |
| TC-2 | text_chinese_both_counts | 验证含中文的文本报出来的两样数都对，且用对了加载方式 | 中 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好 | 一句话：「这段文本有多少 token、多少个字符？<DATA-1 里那段纯中文开头的文本，原样接在这句话后面>」 | 报回的 token 数是 11、字符数是 17（都在当前官方词表与 UTF-8 口径下）；token 数不是 0——用另一条兼容加载路径读这份词表时，纯中文开头的文本会被编成空序列，数出来正是 0 | 落在输出上 |
| TC-3 | text_mixed_with_spaces | 验证中英混排、带空格的文本报出来的两样数都对 | 中 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好 | 一句话：「帮我算一下这段的 token 数和字符数：<DATA-1 里那段中英混排的文本，原样接在这句话后面>」 | 报回的 token 数是 11、字符数是 27 | 落在输出上 |
| TC-4 | file_markdown_path | 验证给一个 .md 文件路径时，走的是文件那条道，报出的数按文件内容算 | 高 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好，DATA-3 那份文件已放进工作区 | 一句话：「数一下这个文件有多少 token、多少字符：<DATA-3 那份文件在工作区里的路径>」 | 报回的 token 数是 13、字符数是 23（那份文件在官方词表与 UTF-8 口径下的值）；报的是文件内容的值，不是那句请求本身的值 | 要读执行过程 |
| TC-5 | stdin_route | 验证把内容用管道喂进来时，走的是标准输入那条道 | 高 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好，DATA-4 那段样本已存成工作区里的一个文件 | 一句话：「把 DATA-4 那个文件用管道喂给计数脚本，告诉我多少 token、多少字符」——要说清是喂进去，不是把路径当参数传 | 报回的 token 数是 6、字符数是 12（那段正文 11 个字符，落成时末尾补了一个换行，管道里过的是含换行的 12 个）；脚本那一头读到的是标准输入，不是文件路径 | 要读执行过程 |
| TC-6 | empty_text | 验证空文本报出 0 而不是报错或跳过 | 高 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好 | 一句话：「这段文本有多少 token、多少字符？它是个空字符串：""」——交过去的就是 DATA-1 第 4 段，正文什么都不写的那一段。空串要写成显式的 `""`，不然与 TC-12「一条道都没给」在消息上分不开 | 报回的 token 数是 0、字符数是 0；不报错、不跳过不答 | 落在输出上 |
| TC-7 | special_token_literal | 验证文本里含特殊 token 字面形时，按官方词表把它计入 | 中 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好 | 一句话：「冒号后面这一段里带一个特殊 token，照样帮我数一下有多少 token、多少字符：<DATA-2 那段文本，原样接在这句话后面>」 | 报回的 token 数是 6、字符数是 25；那个特殊 token 没有被当成普通文字另行处理掉 | 落在输出上 |
| TC-8 | text_for_full_dialogue | 验证用户要把一段文本当成一次完整对话请求来估算时，不把裸文本的数当成整次请求的数报出去 | 中 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好 | 一句话：「我要把 DATA-5 那段当作用户消息发一次请求，帮我估一下这次请求要多少 token」 | 依据未规定这一处，不写成预期的取值：依据说「若估算完整对话请求，需自行按对话模板拼装后再计数」，但没说这句话是说给谁听的，对话模板那份配置也没有随技能分发。照实记下被测那边的实际回应；判据只到这一步：不得把这段裸文本的数当成一次完整请求的数报出去，也不得假称自己已经按对话模板拼好了 | 要读执行过程 |
| TC-9 | naming_other_model | 验证点名别的模型时明确说明不覆盖，且一个近似数都不给 | 中 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好 | 一句话：「用 Claude 的 tokenizer 算一下这段有多少 token：<DATA-1 里那段纯 ASCII 文本，原样接在这句话后面>」 | 明确说明当前这一套只覆盖 DeepSeek 的官方词表、算不了别的模型；不给近似数、不给估算区间、也不拿别的数顶上 | 落在输出上 |
| TC-10 | asks_api_cost | 验证问调用成本时，报出数并点明缓存命中那件事 | 中 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好 | 一句话：「这段文本调一次 API 大概多少 token、多少预算？<DATA-1 里那段纯 ASCII 文本，原样接在这句话后面>」 | 报回 token 数 10；点明离线算不出缓存命中（缓存命中量取决于服务端状态），并说明计费以接口返回的用量为准 | 落在输出上 |
| TC-11 | asks_cost_and_chars | 验证既要字符数又问成本时，两样数都报、那句点明也在 | 中 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好 | 一句话：「这段多少 token、多少字符？顺便估一下调一次要花多少：<DATA-1 里那段纯 ASCII 文本，原样接在这句话后面>」 | 报回 token 数 10、字符数 44；点明离线算不出缓存命中，计费以接口返回的用量为准 | 落在输出上 |
| TC-12 | no_route_given | 验证三条调用方式一条都没给时，不凭空取一段文本算出一个数来 | 高 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好 | 一句话：「帮我数一下有多少 token」——不给文本、不给文件路径、也不喂标准输入 | 依据未规定这一处，不写成预期的取值：依据只列了三条调用方式，没写一条都不给时怎么办。照实记下被测那边的实际回应；判据只到这一步：不得凭空取一段文本算出一个数来，也不得把「多少 token」当成已经知道要数什么 | 要读执行过程 |
| TC-13 | file_missing | 验证路径不存在时，不把它当成一份文本报出一个数 | 高 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好，DATA-6 里那个不存在的路径确认仍然不存在 | 一句话：「数一下这个文件多少 token：<DATA-6 里那个不存在的文件路径>」 | 依据未规定这一处，不写成预期的取值：依据只写了一个文件路径这条调用方式，没写路径不存在时怎么办。照实记下被测那边的实际回应；判据只到这一步：不得把不存在的路径当成一份有内容的文本，报出一个 token 数 | 要读执行过程 |
| TC-14 | path_is_directory | 验证路径指向目录时，不把它当成一份文本报出一个数 | 高 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好，DATA-6 里那个目录已建出来 | 一句话：「数一下这个文件多少 token：<DATA-6 里那个目录路径>」 | 依据未规定这一处，不写成预期的取值：依据没说路径指向目录时怎么办。照实记下被测那边的实际回应；判据只到这一步：不得把这个目录当成一份有内容的文本，报出一个 token 数 | 要读执行过程 |
| TC-15 | file_not_utf8 | 验证文件读不动时，不把它当成一份文本报出一个数 | 高 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-6 就位；ENV-7 的工作区已建好，DATA-6 里那份存成 GBK 的文件已放进去 | 一句话：「数一下这个文件多少 token：<DATA-6 里那份 GBK 文件的路径>」 | 依据未规定这一处，不写成预期的取值：依据只说了支持 UTF-8 文本，没说拿到读不动的文件时怎么办。照实记下被测那边的实际回应；判据只到这一步：不得把读不动的内容当成一份文本，报出一个 token 数 | 要读执行过程 |
| TC-16 | first_run_installs_bundled_engine | 验证目标机是干净的、没装引擎时，先装上随技能打包的那一份，再照常出数 | 高 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-5 就位——ENV-5 那个解释器里确认没有装引擎；ENV-7 的工作区已建好 | 一句话：「数一下这段有多少 token、多少字符：<DATA-1 里那段纯中文开头的文本，原样接在这句话后面>」 | 报回的 token 数是 11、字符数是 17；装引擎那一步走的是随技能打包的那一份（离线，没有联网去取）；装完之后照常计数，不需要用户再问一次 | 要读执行过程 |

TCOV-16 那一行没写用例编号，写的是「不可行，未导出用例」。按模板那张表的原意，这一格该留空、空行就是覆盖率自检要看的地方；可这里留空有另一层意思会被读错——空行本来表示「还有用例要补」，而这一条不是待补，是已经证明执行不了、从分母里减掉了。所以把结论直接写进那一格，不留空。

## 覆盖率自检

| 技术（档位） | 覆盖项编号 | 覆盖项总数 T | 已被用例覆盖 N | 覆盖率 N÷T | 完成准则要求 |
|:---|:---|:---|:---|:---|:---|
| 等价类划分 | TCOV-1～TCOV-15、TCOV-17～TCOV-23 | 22 | 22 | 22÷22＝100% | 100% |
| 判定表测试 | TCOV-24～TCOV-28 | 5 | 5 | 5÷5＝100% | 100% |
| 场景测试 | TCOV-29～TCOV-34 | 6 | 6 | 6÷6＝100% | 100% |

三个分母都拿各门技术的算式核过：

- 等价类划分数的是等价类的条数。TM-1 识别出 23 条，减去判为不可行的 TCOV-16，得 22，与清单里列出来的一样多。
- 判定表测试数的是可行判定规则的条数。TM-2 那张表一共 5 列，5 条规则都可行，得 5。
- 场景测试数的是主场景加备选场景的条数。TM-3 是 1 个主场景加 5 个备选场景，得 6。

三门都到了完成准则要求的 100%，没有留空的覆盖项。

这一处的成品是评测材料，表里指到具体那一样。除了这两样，根下还有两份批次配置（一份跑常规批的 TP-1、TP-2、TP-3，一份跑干净解释器批的 TP-4；哪一份跑哪几条见测试规程规格说明的「各批落到哪」那一栏）——**它们的文件名是那一套方案自己的约定，不在这份里点名**，落成的人照实施方案规格说明那一份的写法取名即可。它们里面用到的编号，用例配置那一份份里都写着。

**这一栏不指到 `evals/token-counter-round4/` 那一层**：那一层底下还住着跑报告落脚的 `runs/`，里面是判官写的散文，随手带的 `TC-` 字样会被落成对照当成成品里的编号读，报出「成品里出现了产出里没有定义处的编号」这种假错。跑测产物不是成品——本技能管到用例与规程产完为止，跑起来之后的报告、日志、判官输出都不算。

六类编号都写在每条用例配置开头的注释里，一条一个号：这条用例属于哪条规程、兑现哪条 TC、覆盖哪几条 TCOV、用到哪几条 DATA、在哪些 ENV 下跑。用例配置的文件名里也带着规程内位次与用例号，盘上认得出哪一条是哪一条。
