# 测试数据需求

执行这批测试规程要用到的数据，一条一行。不是文件、而是一段要接进消息里的文字那几条，描述栏写「正文见下面」，正文另起一段写在表下面。

| 唯一标识符 | 英文名 | 描述 | 重置需求 |
|:---|:---|:---|:---|
| DATA-1 | count_samples | 四段要数的文本：一段纯 ASCII、一段纯中文开头、一段中英混排含空格、一段空文本。正文见下面 | 不需要 |
| DATA-2 | special_token_sample | 一段含特殊 token 字面形的文本。正文见下面 | 不需要 |
| DATA-3 | markdown_sample | 一份 .md 文件样本，文件名 `sample.md`，正文三段：`# 计数样本`、一个空行、`这是一份用来试计数的小文件。`，末尾带一个换行，存成不带字节顺序标记的 UTF-8 | 不需要 |
| DATA-4 | pipe_sample | 从标准输入喂进去的那段文本。落成时存成一个文件，末尾带一个换行——管道里过的是正文 11 个字符加这个换行，共 12 个。正文见下面 | 不需要 |
| DATA-5 | dialogue_sample | 要当成一次完整对话请求里的用户消息的那段文本。正文见下面 | 不需要 |
| DATA-6 | unusable_paths | 三个走不通的路径：一个不存在的文件路径 `not-here.md`；一个目录 `a-directory`；一份文件 `gbk-sample.txt`，正文是「计数的样本」五个字按 GBK 编码写出的十个字节，有意不存成 UTF-8 | 不需要 |
| DATA-7 | engine_install_state | 解释器里装没装引擎这件事的状态。跑完首次运行那条用例之后，那个解释器里就装上引擎了 | 要：跑完 TC-16 之后把那个干净解释器整个丢掉，不逐个卸包；下一批开跑之前确认解释器里没有引擎 |

## 表下正文

**DATA-1**，四段，逐段原样使用——行尾不带多余空格，正文末尾不带换行：

1. 纯 ASCII：`The quick brown fox jumps over the lazy dog.`
2. 纯中文开头：`你好，世界。这是一段纯中文的文本。`
3. 中英混排含空格：`Hello 世界，this is a test 测试。`
4. 空文本：0 个字符，正文什么都不写，交过去时是一个空串

**DATA-2**：

`计到 <｜end▁of▁sentence｜> 为止`

**DATA-4**：

`管道喂进来的一段中文。`

**DATA-5**：

`帮我看看这段话多少 token。`

## 这几条数在用例与规程里怎么被引用

- 三段要数的文本（DATA-1 的第 1、2、3 段）分别接在 TC-1、TC-2、TC-3、TC-9、TC-10、TC-11 的请求后面，第 4 段那段空文本接在 TC-6 的请求后面；TC-16 用的是第 2 段。都不重述正文，只说编号。
- DATA-2 接在 TC-7 的请求后面；DATA-3 与 DATA-6 的三条路径按编号指代，路径里那一段工作区前缀由规程的「启动」栏摆。
- DATA-5 是 TC-8 要估的那段用户消息。
- DATA-7 是环境状态，不是要交过去的输入：TP-1、TP-2、TP-3 三条规程跑之前按它确认解释器里已经装有引擎，TP-4 按它确认没有。
