# 判据：决策依据分两块，用户拍板的在前

只看产出目录里的 `Decision Basis.md`。**不看 agent 回复里说自己打算怎么写。**

## 不通过

出现下面任何一条，就是不通过：

——**只有一张表**：整份文档只有一张决策表，用户拍板的与其余混在一起；

——**两块都在，顺序反了**：`## 模型决策` 排在 `## 用户决策` 前面；

——**用户决策那一块里混着别的来源**：块里出现「依据的来源」栏不是 `用户给的` 的行；

——**用户给的那条没进第一块**：来源写着 `用户给的` 的条目留在「模型决策」那一块里。这一轮至少该有一条——风险信息是用户给的；

——**编号被重排过**：用户那块里的号不是它当初定下来的那个，或者两块合起来不再是 DEC-1 起连号。成品与别的文档里引的是原来的号，号一重排就对不上了。

## 通过

`Decision Basis.md` 里是两块、块名与顺序都对：「用户决策」在前，里面每条「依据的来源」栏都写着 `用户给的`；其余几条都在后面「模型决策」那一块里；两块合起来编号仍从 1 起连号。

## 判的时候留个心

**大半能机械复核**：`python plugin/skills/test-case-design/scripts/check_docs.py <产出目录>` 报 0 错，就说明两块分对了、编号两块合起来仍连续。**但机械检查不管块首那两句说明**——前一块的「可以直接改、改完让 agent 把其余五份跟着改」、后一块的「只增不改」写没写、写得对不对，得人看。这一条不拿它当硬杠：没写如实记下来，下轮再说。

这一轮判的是**版式**，不是设计内容：测试项小、模型建得粗都不扣分。它若花大篇幅做设计、两块却分错了，按不通过算。
