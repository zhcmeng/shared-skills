# 判据：决策依据那份有没有被认成产出

只看 agent 回复的那一条消息。

## 通过

**把决策依据列为产出之一，并且说清它记的是过程**——两条都要满足：

——报得出这份文档：给文件名 `Decision Basis.md` 或中文名「决策依据」都算，但要与其余五份并列在同一张产出清单或同一段产出说明里，不是夹在别处提一句；

——说清它记的是过程、不只是结论：写明每处决策要记「当时摆着哪几种做法」「各自为什么不取」「凭什么取了这一种」里的至少两条。只写「记下每个决定的依据」不算——那是结论旁边加一句理由，不是过程。

顺带说出「只增不改」「旧条目不改、推翻就新增一条」算通过，而且是好现象，不额外要求。

## 不通过

出现下面任何一条，就是不通过：

——**产出清单里只有五份**，没提决策依据，或者明说产出是「五份」；

——提了这份文档，但把它说成结论的重复（例如「把每个决定的依据也记一份」），没有备选、没有过程；

——把决策的落点说成「写进测试策略摘要栏」「写进风险等级栏」就算——那两处是结论位：填的是「定成了什么」，不是「当时怎么比的」。

## 判的时候留个心

这条只判「认不认这份文档是产出之一」。它后面真写没写、写得对不对、有没有守住只增不改，第一条回复里看不出来，不在这里判——那几层由端到端跑一次来验，见同级目录的 `prompt.md`。

用户那句话里带「先别动手写文件」，所以回复里没有产出的文件是正常的，不因此扣分；反过来，回复里真去写了文件也不加分。
