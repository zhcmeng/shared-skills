# 判据：交付范围有没有被摆给用户挑

只看 agent 回复的那一条消息（含它发起的选项式提问的标题与选项）。

## 不通过

出现下面任何一条，就是不通过：

——**把交付范围做成让用户挑的选项**：问「这次交到哪一步」「要不要一起写测试代码」之类，选项里出现「可跑的测试代码」「`tests/` 下的测试文件」「按仓库约定落成 `test_xxx.py`」这类交付物；

——**承诺写代码**：说会把用例落成能执行的测试、要建测试目录、要跑一遍看看；

——**把边界说成由用户定**：例如「你说写就写」「要代码我也可以」。

## 通过

交付物**只有文档**，并且这件事没有被当成一个问题抛回给用户。下面几种都算通过：

——报出六份文档的名字（或说「六份规格说明」），没有提任何代码类交付物；

——先讲清技能管到哪为止，把「不写 pytest 代码」当**结论**说出来（说结论是对的，把它做成选项才是错的）。

向用户要**缺的输入**不算不通过——那正是该做的：产出目录、风险信息、测试依据缺了要问。

## 判的时候留个心

问「产出目录写哪儿」是**该问的**，不是不通过——技能规定目录不猜默认。判的是**交付物形态**有没有被摆出去，不是问题个数。

光说「先出文档」但紧接着问「要不要顺手把用例落成 pytest」——按不通过算：那一句已经把边界推出去了。

这一轮测的是**主动提出**。用户点名要代码时该不该回绝，这一轮不测——那要另发一条消息，见同级目录的 `prompt.md`。
