# 评测用例：三样开工输入的来路各归各位

## 这条用例防的是什么

`test-case-design` 第 0 步要三样开工输入：测试依据、风险信息、测试完成准则（要求的覆盖率）。三样来路不同，混成一样就出错：

| 开工输入 | 该谁来 | 弄错长什么样 |
|:---|:---|:---|
| 测试依据 | 用户给 | 不问，自己猜要测什么 |
| 风险信息 | **用户给，问了等回答** | ① 反过来把定级推给用户：「风险定几级」「哪些算高风险，你判」；② 干脆不问，按测试项自己编一套风险出来 |
| 测试完成准则 | **技能自己定** | 反问用户「覆盖率要多少」，或做成选项卡让用户挑 |

**风险信息为什么必须问**：它是「这个项目怕什么」——最近改过哪里、出过什么故障、哪一块最怕出错。测试项本身看不出来，只有项目里的人知道。**完成准则为什么不该问**：技能自己就声明了默认口径（100%，有档位的三门按风险选档），判得出来。

这条用例是**两轮修**修出来的，两轮的失败都被记在下面——第一轮修对了完成准则、同时把风险信息也一并改成自己编，那是修过头，第二轮扳回来。

## 怎么跑

1. 把 `plugin/skills/test-case-design/` 整套（`SKILL.md` 与它按需打开的 `references/`）当作被测技能的上下文交给 agent，与它平时装了这门技能时一样。
2. 发下面这条用户消息——**三样里只给测试依据的线索**（测试项路径与产出目录）。
3. 只取 agent 回复的那一条消息，按 `graders/` 下两份判据各判一次（同一跑、同一消息，两个维度分开判）。

用户消息：

```
给 plugin/skills/token-counter 这个技能写测试用例。产出目录 evals/token-counter/test-case-design/。
```

## 附带的一个变体

同一条消息把完成准则**照项目测试计划给全**：

```
给 plugin/skills/token-counter 这个技能写测试用例。产出目录 evals/token-counter/test-case-design/。

项目测试计划里的口径：等价类划分与边界值分析覆盖率 100%，判定表测试只覆盖首次运行装依赖那几条可行规则。
```

这个变体防的是**修过头**：技能自己判完成准则，不等于用户给了也当没看见。该有的行为是照给的取——写进「测试策略摘要」栏，一个字不改地按它做。

## 基线证据

### 第一代失败（2026-09-24，1.19.1）：完成准则与风险信息都反问用户

同一场景跑三次，三次都停下来要这两样：

——「测试完成准则（要求的覆盖率）——完全没有。**这条我不自己编**：模型建到多细、覆盖项取全还是按风险取子集、用例导多少条，全由它定。」（还追问「是否要求用例执行结果全部『通过』」）

——「风险信息——完全没有。哪些部分风险高、风险等级怎么划。」同一条消息里它自己已经列出五处看得见的边界（首次运行装引擎 wheel 的联网兜底、特殊 token 是否计入、中文与空格文本的口径、离线算不出缓存命中、只覆盖 DeepSeek 一个模型），结论仍是要用户判：「**哪几处算高风险、哪些可以放过，你判**」；

——「另外两样得你给——**缺哪样我说哪样，不替你编**，也不硬开工」，并把「选型要权衡的四项实际因素」一并列进索要清单。

三次都做对的地方：**技术选型没推出去**（原话「**选哪几门技术不摆给你挑**：那四个决定（选哪几门、怎么组合、各建什么模型、做到什么程度）连同依据由我来定」）。那是更早一条用例 `technique-choice-not-delegated` 修完的效果，这条不能把它带坏。

**一次真实会话里的形态**（2026-09-24，用户在装好技能的环境里跑同一条消息）：agent 直接把完成准则做成选项框摆给用户，三个实质选项是「等价类 + 边界值 各 100%」「再加判定表测试 100%」「再加场景测试全覆盖」（另两个是选项框自带的「其他」「聊聊这个」）。三个选项里混的是**选哪几门技术**，说明它连第 1 步的选型也一并推了出去。

### 第二代失败（2026-09-24，1.19.2）：扳完完成准则，把风险信息也一并扳成了自己编

第一轮修把两样一起改成「按测试项自己判」。同一场景复跑五次，五次全过第一轮的判据，但五次也**全部不再问风险**——它改成自己编一套：

——「**风险信息（我判的，不向你要）**。」

——「第 0 步另外两样我按测试项自己判，判完落进产出，不摆回来问你。」

五次都判成同一个样子：计数准确性、首次运行装引擎的不可回退副作用、边界与异常输入排高位，措辞与格式一类排低位。看着合理，但那是**推测**——这个项目最近改过哪里、出过什么故障，测试项里没有，编不出来。用户当场指出：「现在模型不再询问重点风险了，这也不对吧？」

第一轮修对的部分保留：五次都没再反问完成准则，都写明「没有测试计划，按技能默认口径取 100%」。

## 修完后的结果（2026-09-24，1.19.3）

同一场景复跑五次，五次两条判据都过；变体复跑两次，两次也全过。

**完成准则那一侧：五次都自己定了，一次也没摆回去。**

——「**测试完成准则我按测试项自己定，不用你给。** 这个仓库里没有 token-counter 的测试计划，按技能的默认口径取：选定技术识别出的测试覆盖项全部取全、全部要有用例覆盖，覆盖率按 100% 要求。……定完写进测试模型规格说明的「测试策略摘要」栏。」

——「测试完成准则：我按测试项自己定，不用你给。这个技能没有测试计划可依（目录里只有 SKILL.md、脚本、词表与 wheel），所以取默认口径……判完写进「测试模型规格说明」的「测试策略摘要」栏。」

——「**我自己定的，不问你**：· 测试完成准则：这个测试项没有测试计划，按技能默认口径取 100%……」

——「**测试完成准则。** ……我按技能的默认口径定：选定技术识别出的测试覆盖项全部取全、全部要有用例覆盖，即覆盖率按 100% 要求……定完写进「测试模型规格说明」的「测试策略摘要」栏，这条不问你要。」

——「**完成准则我按测试项自己定，不用你给**：token-counter 这边没有测试计划，就取技能的默认口径……」

**风险那一侧：五次都问了，五次都明说等回答。**

——「**有一件得问你要：风险信息。** 这个只有项目里的人知道，我从测试项本身看不出来，所以拿到再开工——这个测试项最近改过哪里、出过什么故障、哪一块最怕出错？」

——「风险信息：只有你那边有，**等你答完我再开工**。」

——「**等你回风险信息再开工。**」

——「风险那块你答了，我接着从第 1 步往下做。」

——「**拿到我就开工**，产出五份规格说明到 `evals/token-counter/test-case-design/`。不猜也不编，等你回。」

**定级没被推回去**（这是这一轮新加的那条「不通过」）。五次都在问信息的同时挑明等级由自己判：

——「你答完我按出错代价与可回退性自己判风险等级、落进产出的「风险等级」栏——等级不摆回来让你划。」

——「等级由我按你答的内容判，落进产出的「风险等级」栏，不用你定级。」

——「（要的是信息，等级不用你定——拿到你答的内容我自己判）」

**上一轮修对的部分没被带坏。** 五次的技术选型仍然不摆给用户挑：

——「第 1 步那四个决定——选哪几门技术、怎么组合、各建什么模型、做到什么程度——连同依据也由我来定，不摆给你挑。」

——「**同样不摆给你挑的**：选哪几门技术、怎么组合、各建什么模型、做到什么程度，这四项连依据一起由我定，结论写进「测试策略摘要」栏。」

**变体（完成准则照项目测试计划给全）复跑两次，两次都照给的取、风险照问。** 这一路防的是修过头——技能自己判完成准则，不等于用户给了也当没看见：

——「测试完成准则照项目测试计划取，不另判、不改动：等价类划分与边界值分析覆盖率按 100%……判定表测试只做「首次运行装依赖」那几条可行规则，其他判定规则不进这门技术的范围」＋「**风险信息得你给**，测试项里看不出来，我不编，**拿到才开工**」。

——「测试完成准则（照项目测试计划取，已定）：等价类划分、边界值分析各按 100%……判定表测试按计划只覆盖「首次运行装依赖」那条链上的可行规则」＋「**风险信息（等你回答再开工）**：风险等级由我按你答的内容判」。

**附带记一处观察，不在两份判据范围内**：五次主跑里有四次（两个变体两次也都有）主动指出产出目录里已经躺着上一轮的五份文档，并按技能里「手上已经有一组用例」那条路走——先算覆盖率、缺哪补哪，不推倒重来。这个动作是对的，但按这条用例的设定，场景里那个目录本该是空的；它说明这条用例的现场与预期不完全一致，判的时候不必因此扣分。要复现这条用例，先把产出目录清空。
