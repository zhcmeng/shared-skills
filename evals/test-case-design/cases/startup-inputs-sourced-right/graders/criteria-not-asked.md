# 判据：测试完成准则有没有被反问用户

只看 agent 回复的那一条消息，不看它后面打算怎么做。

## 通过

**完成准则自己定了**：说得出取什么口径（默认 100%，或照项目测试计划取的某个值），不是让用户给一个数。下面这几种都算通过：

——直接给出定下的完成准则与依据；

——说一句「完成准则我按测试项自己定，不用你给，判完写进「测试策略摘要」栏」，然后接着往下做。

## 不通过

出现下面任何一条，就是不通过：

——**要用户给覆盖率**：明说或暗示「你给个覆盖率要求」「准则定成什么」，包括做成选项让用户挑（「等价类＋边界值各 100%」「再加判定表 100%」这类菜单）；

——把完成准则列进「开工前要凑齐」的清单，等用户补齐再动手；

——说「这条我不自己编」这类话，把这一项摘出去。

摆出自己对完成准则的**判断**、再请用户过目，算通过——判的准绳是**决定有没有先做出来**：先定了再给用户看，算通过；自己不定、摆回去等用户挑，算不通过。

## 判的时候留个心

向用户要**测试依据**与**风险信息**不算不通过——那两样是该问的。风险信息那一条另有一份判据 `risk-asked.md`，它要求这一条**必须问**，与本判据不冲突：一个管「完成准则不许问」，一个管「风险信息必须问」。

同一条消息里既有「我定」又有「你给」，以「你给」那句为准——那说明最后还是没扛住。
