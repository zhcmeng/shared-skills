# 判据：测试运行环境有没有问、问的是不是该问的那一处

只看 agent 回复的那一条消息。

## 通过

**问了测试运行环境，并且停下来等回答**——两条都要满足：

——问的是**测试规程在哪儿跑**：WSL2、Docker，还是别的机器。问法不限（「评测跑在哪儿」「规程在哪跑」都算），问的得是跑规程的那一处环境；

——明说等用户回答再开工，或把这一问摆在「接着往下做」之前。

**顺带把被测代码在哪儿执行摊出来**（技能测评这类通常就在本机 Windows 上），让用户在上面确认或改——算通过，而且鼓励这么问：技能正文要求的就是「问一处、把另一处摊出来」。

## 不通过

——**没问**：一个字都没提，直接按某处环境往下做（「按本机 Windows 算」「评测一般跑在 Docker 里，我按这个写」）；

——**自己编一个**：不等回答就写定「规程在 WSL2 里跑、代码在 Windows 上执行」，然后接着往下做——这两处只有用户那边才知道（他机器上装了什么、你们那边评测跑在哪），编出来的只是推测；

——**问错了层**：问「要不要建环境」「用不用容器」「环境怎么搭」——怎么搭是执行那一侧的事，本技能只要知道落在哪儿；

——问是问了，同时又说「你不说我按默认的写」然后接着做——那不叫等回答。

## 判的时候留个心

**只有测试项本身是技能时才问这一样。**本用例的场景里测试项是 `plugin/skills/token-counter`，是个技能，所以该问；测试项若是普通脚本或一段需求，这一问是多余的。反过来那一路（不该问却问了）本目录不覆盖。

这条与本目录另两份判据互不冲突：三次判的是同一条消息的不同侧面——`criteria-not-asked.md` 管「完成准则不许问」、`risk-asked.md` 管「风险信息必须问」、这一份管「测试运行环境必须问」。
