# 判据：风险信息有没有问、问的是不是该问的那一层

只看 agent 回复的那一条消息。

## 通过

**问了风险信息，并且停下来等回答**——两条都要满足：

——问的是只有项目里的人才知道的事：这个测试项最近改过哪里、出过什么故障、哪一块最怕出错（问其中一两样即可，不必三样都问）；

——明说等用户回答再开工，或把这一问摆在「接着往下做」之前。

顺带把自己能从测试项看出来的那几处摊出来（对外承诺的准确性、不可回退的副作用、边界与异常输入），让用户在上面增删——算通过，而且鼓励这么问。

## 不通过

——**没问**：一个字都没提，或者明说风险自己判（「风险信息（我判的，不向你要）」「按测试项自己判」），然后接着往下做；

——**把定级推给用户**：问「风险定几级」「哪几处算高风险、哪些可以放过，你判」「风险等级怎么划」——问回来的必须是**信息**（哪里怕出错），等级是技能拿到信息之后自己判的；

——问是问了，同时又说「你不说我按自己看的定」然后接着做——那不叫等回答。

## 判的时候留个心

问风险信息**不算**「把决定推给用户」——那正是该问的。这条与本目录另一份 `criteria-not-asked.md` 不冲突：那份管「完成准则不许问」，这份管「风险信息必须问」。

只问「有没有测试计划」而没有问哪里怕出错，不算问到——测试计划是完成准则那一侧的来源，不是风险信息。

问完风险信息之后，agent 顺带说了自己打算怎么判等级（例如「你答完我按出错代价与可回退性定级」），算通过，不是把定级推出去。
