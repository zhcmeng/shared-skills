# 评测用例：评测用例的目录名按规程的执行顺序排

## 这条用例防的是什么

评测工具按**用例目录名的字母序**跑，`--case` 接的也是目录名。而用例编号是导出时按写下来的先后发的，规程顺序是另排的——两个顺序各来各的。目录名只写 `tpN-TC-M` 的话，字母序先在编号那段分出胜负：一条规程里若有 12 条用例，排出来是 `TC-1、TC-10、TC-11、TC-12、TC-2、…`；规程数一过 9 同理（`tp10-` 排在 `tp2-` 前面）。2026-09-29 在本仓库核查过：改动前技能里没有哪句话把「字符串序」与「执行顺序」挂上关系，唯一沾到这件事的那一条还把排序推给了工具。

技能该有的行为：落成评测用例的那一批，在「各批落到哪」表里按规程列出**用例目录名**，形制是 `tp<规程号两位>-<规程内执行位次两位>-TC-<用例编号>-<英文名>`。两段位次各两位，字母序才等于「先规程号、再规程内位次」；位次写的是这条用例在该规程「有序执行测试用例」栏里排第几；位次与整条名字由 `issue_ids.py --case-dirs` 打出来，不靠手数。

顺序不影响任何一条用例的结果（每次运行拿一份一次性的 home、工作目录与配置），买到的是「报告读起来与规程一致、文档与盘上对得上」。

## 怎么跑

1. 把 `plugin/skills/test-case-design/` 整套（`SKILL.md` 与它按需打开的 `references/`）当作被测技能的上下文交给 agent，与它平时装了这门技能时一样。
2. 把 `fixture/` 下的两个文件拷到一个临时目录当测试项：`slug.py` 是要设计用例的脚本，`SPEC.md` 是测试依据。**这份需求里同时有脚本行为（第 1–4 条）与技能行为（第 5–7 条）**，所以两批都该出得来——只出一批的话，落成评测用例的那一行就不会有，这一条判不了。
3. 发下面这条用户消息。开工输入都给全（否则 agent 会停下来问），产出目录指向一个空目录。
4. 跑完看产出目录里的 `Test Procedure Specification.md`，按 `graders/case-dir-names.md` 判。**不看 agent 说自己打算怎么写。**

用户消息：

```

手上的输入（第 0 步要的都在这里，不必再问）：

做完报告：这一轮往磁盘写过哪些文件（完整路径），以及产出目录里那份测试规程规格说明的「各批落到哪」那一节写了什么。
```
