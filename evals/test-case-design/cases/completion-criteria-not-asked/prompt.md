# 评测用例：完成准则与风险信息自己判，不反问用户

## 这条用例防的是什么

`test-case-design` 第 0 步要三样开工输入：测试依据、测试完成准则（要求的覆盖率）、风险信息。修之前，技能把后两样写成「先向用户要」——`SKILL.md` 原文是「尤其不要自己编一个完成准则」「取不到就问用户，不自己编一个」。

于是一句「给 plugin/skills/token-counter 写测试用例」，agent 读完技能就停在门口：把测试依据认下来，回头要完成准则与风险信息。用户手上根本没有这两样——他就是因为不知道才来调技能的。

技能该有的行为：**测试依据向用户要**（三样里只有这一样长在用户那边），**完成准则与风险信息按测试项的特点自己判**——完成准则默认取 100%（选定技术识别出的覆盖项全部要有用例覆盖，有档位的三门按风险选档），风险信息按「出了什么错、谁会受影响、代价多大、能不能回退」判；判完写进产出的「测试策略摘要」栏与「风险等级」栏，在回复里说一句定了什么、依据是什么，然后接着往下做。被测项目已有测试计划的，照计划取，不另判。

## 怎么跑

1. 把 `plugin/skills/test-case-design/` 整套（`SKILL.md` 与它按需打开的 `references/`）当作被测技能的上下文交给 agent，与它平时装了这门技能时一样。
2. 发下面这条用户消息——**三样里只给测试依据的线索**（测试项路径与产出目录）。
3. 只取 agent 回复的那一条消息，按 `graders/criteria-not-asked.md` 判。

用户消息：

```
给 plugin/skills/token-counter 这个技能写测试用例。产出目录 evals/token-counter/test-case-design/。
```

## 附带的一个变体

同一条消息把两样**给全**（照项目测试计划的口径给）：

```
给 plugin/skills/token-counter 这个技能写测试用例。产出目录 evals/token-counter/test-case-design/。

项目测试计划里的口径：等价类划分与边界值分析覆盖率 100%，判定表测试只覆盖首次运行装依赖那几条可行规则；风险上，计数准确性最高，输入来源与编码处理次之，其余常规。
```

这个变体防的是**修过头**：判据从「不许反问用户」变成「用户给了也不听，一律套自己的 100% 与自己的风险分级」。技能该有的行为是照给的取——完成准则写进「测试策略摘要」栏、风险等级写进「风险等级」栏，一个字不改地按它做。

## 基线证据（2026-09-24，修之前，1.19.1）

同一场景跑三次，三次都停下来要这两样：

——「测试完成准则（要求的覆盖率）——完全没有。**这条我不自己编**：模型建到多细、覆盖项取全还是按风险取子集、用例导多少条，全由它定。」（还追问「是否要求用例执行结果全部『通过』」）

——「风险信息——完全没有。哪些部分风险高、风险等级怎么划。」同一条消息里它自己已经列出五处看得见的边界（首次运行装引擎 wheel 的联网兜底、特殊 token 是否计入、中文与空格文本的口径、离线算不出缓存命中、只覆盖 DeepSeek 一个模型），结论仍是要用户判：「**哪几处算高风险、哪些可以放过，你判**」；

——「另外两样得你给——**缺哪样我说哪样，不替你编**，也不硬开工」，并把「选型要权衡的四项实际因素」一并列进索要清单。

三次都做对的地方：**技术选型没推出去**（原话「**选哪几门技术不摆给你挑**：那四个决定（选哪几门、怎么组合、各建什么模型、做到什么程度）连同依据由我来定」）。那是上一条用例 `technique-choice-not-delegated` 修完的效果，这条用例不能把它带坏。

**一次真实会话里的形态**（2026-09-24，用户在装好技能的环境里跑同一条消息）：agent 直接把完成准则做成选项框摆给用户，三个实质选项是「等价类 + 边界值 各 100%」「再加判定表测试 100%」「再加场景测试全覆盖」（另两个是选项框自带的「其他」「聊聊这个」）。三个选项里混的是**选哪几门技术**，说明它连第 1 步的选型也一并推了出去——同一个病，症状更重。

## 修完后的结果（2026-09-24，1.19.2）

同一场景复跑五次，**五次全过**，且收敛到同一个形态：都先说明「这两样我按测试项自己判，不向你要」，再各自给出判断与依据，然后接着往下做。原话摘五处：

——「开工输入的两样——测试完成准则与风险信息——我按测试项自己判完了……三样里只有测试依据长在你那边。」

——「第 0 步另外两样我按测试项自己判，判完落进产出，不摆回来问你。」

——「**测试完成准则（我定的，不向你要）**」「**风险信息（我判的，不向你要）**。」

——「判完即写进产出：「测试策略摘要」栏收完成准则，覆盖项与用例的「风险等级」栏收风险分级，**不用你给**。」

——「上面哪条口径要改，随时说；没说我就从建模型那一步开始往下做。」（先定完、再请用户过目——判据里算通过的那一种）

五次的判断内容也收敛了：完成准则一律 100%（都写明「没有测试计划，按技能默认口径取」）；风险一律把计数准确性、首次运行装引擎的不可回退副作用、边界与异常输入排在高位，措辞与格式一类排低位。**技术选型照旧没被带坏**：五次都自己选了技术并写明依据，还都按技能要求只告知不代做地提了一句结构那一侧该用分支测试。

用词那一侧也落地了：五次里没有一次出现「你给个覆盖率」「哪些算高风险你判」，也没有一次把这两样列进开工前要凑齐的清单。

**变体（用户把两样给全）复跑两次，两次全过**：都照给的取，没有一跑套技能默认的 100%。原话摘两处：

——「**测试完成准则**——照项目测试计划取，**不另判，也不套技能默认的 100%**……判定表那门低于全覆盖，其余可行规则按「放弃的覆盖项」处理——放弃哪几条、为什么放弃（按低风险暴露写），逐条记进覆盖项清单的「描述」栏。」

——「**风险信息**——同样照计划取。」

两跑都在**定完之后**才说「若你的本意是……说一声我改过来」，没有一跑把决定推回去重问——判据里「先定了再给用户看」那一档。
