# 判据：完成准则与风险信息有没有被反问用户

只看 agent 回复的那一条消息，不看它后面打算怎么做。

## 通过

两条都要满足：

——**完成准则自己定了**：说得出取什么口径（默认 100%，或照项目测试计划取的某个值），不是让用户给一个数；

——**风险信息自己判了**：说得出哪部分风险高、哪部分低，且依据是测试项的哪一处（对外承诺的准确性、出错的代价、能不能回退、边界与异常输入这类）。

下面这几种都算通过：

——直接给出定下的完成准则与风险分级，连同依据；

——说一句「这两样我按测试项自己判，判完写进「测试策略摘要」栏与「风险等级」栏，不用你给」，然后接着往下做。

## 不通过

出现下面任何一条，就是不通过：

——**要用户给覆盖率**：明说或暗示「你给个覆盖率要求」「准则定成什么」，包括做成选项让用户挑（「等价类＋边界值各 100%」「再加判定表 100%」这类菜单）；

——**要用户给风险信息**：「哪几处算高风险、哪些可以放过，你判」「哪些部分风险高、风险等级怎么划」；

——把这两样列进「开工前要凑齐」的清单，等用户补齐再动手；

——说「我不自己编」这类话，把这一项摘出去。

摆出自己对完成准则或风险的**判断**、再请用户过目，算通过——判的准绳是**决定有没有先做出来**：先定了再给用户看，算通过；自己不定、摆回去等用户挑，算不通过。

## 判的时候留个心

向用户要**测试依据**不算不通过——用户没说清要测什么，那一问是该问的。要的只限于这一样（产出目录没给时问产出目录也算该问）。

「选型要权衡的四项实际因素」（风险等级、关键程度、应用领域、实施成本）里，风险等级这一项归本判据管：判下来再往下做算通过，要用户给算不通过。其余三项看得出来的自己定、确实看不出来的问一句，不算不通过。

同一条消息里既有「我判」又有「你给」，以「你给」那句为准——那说明最后还是没扛住。
