# 判据：两栏与「各批落到哪」都在，而且列全了

只看产出目录里的 `Test Procedure Specification.md`（那一份的正文）。**不看 agent 回复里说自己打算怎么写。**

## 不通过

出现下面任何一条，就是不通过：

——**某条规程缺「执行器」栏**：这条规程没有这一栏，或者栏是空的，或者取值不是 `脚本`、`控制器`、`子代理` 三者之一（后面带一句括号说明不算错，比如「脚本（跑命令，比退出码与盘上文件）」）；

——**某条规程缺「改动文件」栏**：同上，取值只能是 `只读` 或 `会写`；

——**没有「各批落到哪」这一块**：文末没有这一块（标题不叫这个也行，得是一块讲「规程按落点分成几批、各批落到哪」的表）；

——**那一块是空的**：有标题、表里一行没有，或者「规程」那一栏空着。只落一类时也要写一行，写明全部规程落同一处；

——**表里没把规程列全**：文档里定义的每条规程，都要在那一块里出现（写在「规程」栏里，形如 `TP-1`、`TP-1、TP-2`）；漏一条即不通过；

——**表里的落点与执行器对不上**：执行器写着「脚本」的那一批，「落到哪」该是能跑的测试代码那一类（`tests/` 下的路径）；写着「控制器」或「子代理」的那一批，该是评测用例那一类（`evals/` 下的路径）。两边对不上的，不通过。

## 通过

上面六条一条不犯，即通过。

## 判的时候留个心

**光在回复里说「这条规程由脚本跑」不算通过**——判的是产出目录里那份文件里有没有这两栏。

**六份文档要齐**，顺带确认一条：`python plugin/skills/test-case-design/scripts/check_docs.py <产出目录>` 报 0 错。这两栏与那一块本身就在检查范围内（缺栏、取值超范围、那一块不在、表里漏规程，`check_docs.py` 会各报一处错），所以这一条能机械复核——但机械检查过了不等于这一条过了：**分得对不对它判不了**，脚本认不出「把一条规程劈成两半分给两处」这种事。

**这条用例的测试项是照「两类判据都要有」造的**（`SPEC.md` 里第 1–4 条落脚本、第 5–7 条落模型）。产出里只出现一批、表里只有一行，按不通过算——不是因为它少写了表，是因为它没看出这份需求里有要起模型才判得了的东西。
