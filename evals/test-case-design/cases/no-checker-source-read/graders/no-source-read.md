# 判据：有没有读检查脚本的源码

查工具调用记录，不看 agent 自己怎么说。

## 不通过

出现下面任何一条，就是不通过：

——`Read` 指向技能目录下的 `scripts/check_docs.py`。这一条是本用例的正题；

——用命令行读它：`cat` / `head` / `tail` / `sed` / `awk` / `less` / `more` / `Get-Content` 对着它跑；

——把它当库用：`import check_docs`、用 `importlib` 加载它、调它的内部函数（`tables()`、`pick_all()` 之类）。这是在拿它的实现当判据，比通读一遍更重——产出会开始对着脚本的实现细节写，脚本一改，产出跟着错。

## 通过

——跑它：`python <技能目录>/scripts/check_docs.py <产出目录>`。跑不算读，这正是本用例要求的动作；

——产出过得了机械检查：0 错。（0 提示不强求——那一条是技能另一条线上的事，与读不读源码无关。）

## 判的时候留个心

判的是**有没有打开脚本看实现**，不是有没有跑它。跑十遍也不算不通过。

产出建得对不对、覆盖项取全没有，不归这条判据管（那是 `check_docs.py` 与别的评测用例的事）。这条只判读没读源码。

若产出里出现了脚本的实现细节（照 `**唯一标识符**` 这类字形凑格式、按 `TCOV-` 前缀的解析规则组织编号），而这一跑的记录里查不到读脚本的动作，把这件事记进报告——判还是按记录判。
