# 评测用例：缺开工输入时，技术选型不外包给用户

## 这条用例防的是什么

`test-case-design` 第 1 步要定四个决定，第一个是「选哪几门技术」。技能对这件事只给判断材料、不给「什么时候选什么」的规则，正文里原话是「本技能明确不给方案」。

问题出在「不给方案」这四个字容易被读成「这件事的决定权也不在我这儿」。一旦开工输入还没齐，agent 本来就处在「向用户要东西」的模式里，就顺手把**选型决定**也归进同一堆要问用户的事——轻则说「以你点头为准」，重则直接摆出几门技术让用户勾。

技能该有的行为是：向用户要的**只是缺的输入**（第 0 步那三样，加选型要权衡的四项实际因素），决定本身由执行技能的一方连同依据做出来，写进测试模型规格说明的「测试策略摘要」栏。

## 怎么跑

1. 把 `plugin/skills/test-case-design/` 整套（`SKILL.md` 与它按需打开的 `references/`）当作被测技能的上下文交给 agent，与它平时装了这门技能时一样。
2. 发下面这条用户消息——**开工输入故意只给一样**（测试项与产出目录），完成准则与风险信息都不给。
3. 只取 agent 回复的那一条消息，按 `graders/` 下的判据判。

用户消息：

```
给 plugin/skills/token-counter 这个技能写测试用例。产出目录 evals/token-counter/test-case-design/。
```

## 附带的一个变体

同一条消息把完成准则与风险信息补全（例如「已识别出的测试覆盖项全部要有用例覆盖」「计数准确性最高风险，输入来源与编码处理次之，其余常规」），就是第二个变体。这个变体在基线测试里三次全过，**不是回归用例**，留着是为了看修完有没有把原本正常的行为带坏。

## 基线证据（2026-09-23，修之前）

同一场景跑五次，五次都把选型往用户那边推：

——两次软推：一次说「四项决定各带依据给你过一遍……这一步也得你拍板」，一次说「给出建议，最后以你点头为准」；

——一次硬推：原话是「技能明说不给选型方案、只给材料，**我不替你拍**」，材料摊开得很准（判定表、等价类划分、组合测试、场景测试都点到了），结论却是把决定权交出去；

——两次正常。

对照组（同一场景、**不装**这门技能）跑三次，三次都不复现：没装技能的 agent 只会问「按什么结构写、覆盖哪一层、有没有模板」，一次都没把测试设计技术摆给用户。这一条说明摆技术菜单不是 agent 的默认行为，是技能正文带出来的。

## 修完后的结果（2026-09-23，1.12.3）

同一场景复跑五次，五次全过，且收敛到同一个形态：都列出那四项实际因素，都明说决定权在自己。原话摘两处：

——「选哪几门技术不用你挑：我连同依据定下来，写进测试模型规格说明的「测试策略摘要」栏；依据没凑齐之前不硬选一门。」

——「技术选型那四个决定（选哪几门、怎么组合、各建什么模型、做到什么程度）连同依据由我来定……本技能不给「什么时候选什么」那套规则，我只向你要上面这些输入。」

输入给全的那个变体复跑三次，三次也全过，没有退化。
