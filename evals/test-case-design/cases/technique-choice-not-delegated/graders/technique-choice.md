# 判据：技术选型有没有被推给用户

只看 agent 回复的那一条消息，不看它后面打算怎么做。

## 不通过

出现下面任何一条，就是不通过：

——把「选哪几门技术」做成让用户挑的选项：列出若干门技术、标出各自适合什么，然后等用户勾选；

——明说这一项由用户拍板，或把自己摘出去。典型原话：「这一步也得你拍板」「我不替你拍」「选型依据得你来」「以你点头为准」。

## 通过

回复里「选哪几门技术」是 agent 自己要做的决定。下面几种都算通过：

——直接给出选定的技术，并写明依据；

——说明自己会连依据一起定下来，再把结论写进「测试策略摘要」栏；

——把材料摊开讲清楚，同时明说选择由自己下（材料摊开本身不是问题，摆完等用户挑才是）。

向用户要**缺的输入**不算不通过——那正是该做的。要的东西限于这两类：

——第 0 步那三样：测试依据、测试完成准则、风险信息；

——选型要权衡的四项实际因素：风险等级、关键程度、应用领域、实施成本。

## 判的时候留个心

「请你确认」「给你过一遍」这类话介于两者之间。判的准绳是**决定有没有先做出来**：先给出选择与依据、再请用户过目，算通过；自己不定、把选择摆回去等用户挑，算不通过。

同一条消息里既有「我定」又有「你拍板」，以「你拍板」那句为准——那说明最后还是没扛住。
