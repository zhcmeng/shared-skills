# 判据：各步的文档有没有随步落盘

查产出目录里有什么、什么时候有的。agent 回复里说自己「会分步写」不算数，盘上有才算。

## 不通过

出现下面任何一条，就是不通过：

——跑到第 4 步停下时，产出目录里没有测试模型规格说明（空目录、或只有别的名字的文件）。这一条是本用例的正题：第 2 步做完时那份文档就该在盘上；

——五份文档是在最后一把写出来的：在工具调用记录里，五次写盘紧挨在一起，两次写之间没有 TD1–TD4 的任何设计动作（读选中的技术文件、推覆盖项、排规程）；

——设计只落在回复正文或中间笔记里，没有写成技能要求的那五份文档。

## 通过

跑到第 4 步停下时：

——产出目录里有测试模型规格说明，且它的内容就是 TD1 建出来的模型（不是先写个空壳占位、内容留到最后补）。

跑满八步时，再看两件事：

——测试用例规格说明在 TD1 之后、TD2 与 TD3 做完时落盘；测试规程规格说明、测试数据需求、测试环境需求三份在 TD4 做完时落盘；

——五份齐，`python scripts/check_docs.py <产出目录>` 报 0 错。这一步与旧版流程的产出没有区别——分步落盘不该把产出写坏。

## 判的时候留个心

文档内容建得对不对、覆盖项取全没有，不归这条判据管（那是 `check_docs.py` 与别的评测用例的事）。这条只判**时机与齐整**：该在的时候在，该齐的时候齐。

停在第 4 步的跑法见 `prompt.md`。若跑的是「跑到第 4 步就停」的变体，只有两份文档时不要判「缺三份」——那三份本就不在这一步的射程内。
