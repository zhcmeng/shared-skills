# 测试环境需求

测试规程要在什么环境上跑、被测那侧在哪儿执行，逐项列出。

| 唯一标识符 | 英文名 | 测试环境项 | 描述 |
|:---|:---|:---|:---|
| ENV-1 | runner_machine | 设备：跑测试规程的那台机器 | 本机。技能、样本、脚本都在这一台上，命令在宿主机上直接跑，不起容器、不连远端 |
| ENV-2 | network_egress | 网络：能访问包索引的出口 | 只有联网兜底那条用例用得上。要能解析包索引的域名并下载 wheel；下载不下来时那条用例的判据不成立 |
| ENV-3 | interpreter_with_engine | 解释器：已装好引擎的 CPython | 本机那个 3.13 的解释器，`tokenizers` 已经装在里面且可导入。规则 1 与脚本层的取值类用例都在它上面跑 |
| ENV-4 | packaged_assets | 资源：随包分发的两份东西 | 技能目录下的 `tokenizer.json`（官方词表）与 `wheels/`（打包好的引擎 wheel）。两样都在技能目录里，装技能时整棵子树一起进工作区 |
| ENV-5 | clean_interpreter | 解释器：没装引擎的干净 CPython | 现建一个空环境，里面不装 `tokenizers`。规则 2、规则 3 与首次运行那三条用例要在它上面跑——它们的判据正是「从没装到装上」这一步 |
| ENV-6 | network_blocked | 网络：断网状态 | 只有「首次运行无需联网」那条用例用得上。断网之后跑，脚本仍要报出数——它在 ENV-2 之外，两个不同时成立 |
| ENV-7 | subject_runtime | 执行环境：被测那侧跑起来的地方 | 技能被调用时，模型那一侧在哪儿执行、在哪儿读工作区。它的执行结果与它写下的过程能被读回来，交互序列那一组用例才判得了 |
| ENV-8 | subprocess_capable_runner | 执行环境：能起子进程并读回结果 | 跑测试的那一侧要能起子进程执行脚本，并把标准输出、标准错误与退出码原样读回来。脚本层那一组用例的判据全落在它读回来的东西上 |

**与生产环境的偏离**：这个技能没有独立的生产环境，它跑在用户自己的机器上。ENV-1、ENV-3 就是本机，与用户那边的差别只在于解释器版本与已装包的不同——ENV-5 那一条正是拿这一点当判据的，不算偏离。
