# 测试模型规格说明

测试项是 `token-counter` 这个技能：把一段文本或一个文件交给它，报回 DeepSeek 官方 tokenizer 数出来的 token 数。测试依据是技能自己的 `SKILL.md`——它写死了三种输入来路、两行输出、三处承诺（离线自包含、首次运行自动装引擎、只覆盖 DeepSeek）。

## TM-1 输入来路与输出的等价类划分模型

- **唯一标识符**：TM-1
- **英文名**：input_path_partitions
- **目标**：技能收不收这次输入、按哪条路收、收下之后吐什么。三个处理环节——输入源、文件与编码、文本内容——加上输出这一环。数准不准不在这个模型里。
- **风险等级**：中。取值分组错一处，表现是某类输入被拒或走错路，不是数错；数错归 TM-2。
- **测试策略摘要**：等价类划分。与 TM-2 各建各的模型，不互相喂数据——TM-1 管收不收、吐出什么形状，TM-2 管数得对不对。测试完成准则是等价类划分覆盖率 100%。
- **测试模型**：等价类表。三个处理环节分开列，环节之间不交叉。

**输入源**

| 编号 | 类 | 取值 |
|:---|:---|:---|
| E1 | 有效 | `--text` 给出一段非空文本 |
| E2 | 有效 | 位置参数给一个存在的文件路径 |
| E3 | 有效 | 标准输入有非空数据，不给位置参数 |
| E4 | 未规定 | 三种来路一个都不给，标准输入也为空——依据没写这一情形算不算错 |
| E5 | 无效 | 文件路径在盘上不存在 |
| E6 | 无效 | 文件路径指向一个目录 |
| E7 | 未规定 | `--text` 与文件路径同时给出——依据没写听谁的 |

**文件与编码**

| 编号 | 类 | 取值 |
|:---|:---|:---|
| E8 | 有效 | 不带字节顺序标记的 UTF-8 文件 |
| E9 | 有效 | 带字节顺序标记的 UTF-8 文件 |
| E10 | 无效 | 文件不是 UTF-8 的字节序列 |

**文本内容**

| 编号 | 类 | 取值 |
|:---|:---|:---|
| E11 | 有效 | 纯 ASCII 字符 |
| E12 | 有效 | 纯中文 |
| E13 | 有效 | 含基本平面之外的字符（emoji 这类） |
| E14 | 有效 | 含 DeepSeek 特殊 token 的字面量 |
| E15 | 有效 | 只由空白字符组成 |
| E16 | 有效 | 零字符的空文本 |

**输出**

| 编号 | 类 | 取值 |
|:---|:---|:---|
| E17 | 有效 | 标准输出打印 `tokens:` 与 `chars:` 两行，退出码 0 |
| E18 | 无效 | 不打印这两行，以非零退出码结束 |

## TM-2 计数的边界值模型

- **唯一标识符**：TM-2
- **英文名**：count_boundaries
- **目标**：三个有序集各自的下边界——文本字符数、文件字节数、带标记文件里标记之后的字符数。这三处决定报出来的数是几。
- **风险等级**：高。这三处报错一个，用户拿去估预算的数就是错的，而这个技能的全部价值就是那个数。
- **测试策略摘要**：边界值分析。在 TM-1 划出的取值上取三个有序集，各取边界点与内侧相邻点。测试完成准则是边界值覆盖率 100%。
- **测试模型**：三个有序集，每个两个取值。

| 有序集 | 边界上的值 | 相邻类里的值 |
|:---|:---|:---|
| A 文本字符数 | 0 个字符 | 1 个字符 |
| B 文件字节数 | 0 个字节 | 1 个字节 |
| C 带标记文件里标记之后的字符数 | 0 个字符 | 1 个字符 |

## TM-3 引擎获取路径的判定表模型

- **唯一标识符**：TM-3
- **英文名**：engine_acquisition_rules
- **目标**：脚本发现引擎时走哪条路。两个条件——引擎能不能导入、打包的 wheel 与这台机器对不对得上——组合出三条规则。
- **风险等级**：高。这是用户点名的高风险之一（「首次运行自动装依赖」）：三条规则走错一条，表现是用户那边根本跑不起来，而不是数错。
- **测试策略摘要**：判定表测试。条件只有两个、取值都是布尔，组合有限，摊成判定表最清楚。测试完成准则是判定表规则覆盖率 100%——三条规则各有用例。
- **测试模型**：判定表。

| 规则 | C1 引擎可导入 | C2 打包 wheel 与平台相符 | 动作 |
|:---|:---|:---|:---|
| R1 | 是 | — | 直接用已装的引擎，不装任何东西 |
| R2 | 否 | 是 | 装打包的 wheel：离线、`--no-deps` |
| R3 | 否 | 否 | 联网兜底：装写死版本的 `tokenizers` |

R1 那一行 C2 不参与判定（引擎已经能用，装不装得上无意义），这一格合并。

## TM-4 技能被调用时的交互序列模型

- **唯一标识符**：TM-4
- **英文名**：usage_interaction_scenarios
- **目标**：用户说一句话到技能给出回话这一整条交互。判的是回话里说了什么——数报没报出来、该说明的说明了没有。脚本层的取值与边界不在这里。
- **风险等级**：高。技能是靠模型跑起来的，回话这一层没有第二道闸：脚本报对了数，回话里说错了口径，用户照样被误导。
- **测试策略摘要**：场景测试。输入值从前三个模型导出的覆盖项里取——取值照 TM-1 那几组，条件组合照 TM-3 那三条规则，边界照 TM-2。测试完成准则是场景覆盖率 100%——一条主场景加八条备选场景，各有用例。
- **测试模型**：交互序列。一条主场景，八条备选。

| 编号 | 场景 | 序列 |
|:---|:---|:---|
| S0 | 主场景：算一段文本或一个文件的 token 量 | 用户给出文本或文件路径并问 token 数 → 技能跑脚本 → 回话里报出那个数 |
| S1 | 只问 token 量 | 用户只问 token 数 → 技能把 token 数报出来（依据说「报告 N 即可」，那是允许，没说不许附带别的；所以这一条只判数报出来没有） |
| S2 | 问别的模型的 token 数 | 用户点名 Claude 这类别的模型 → 技能说明本技能不覆盖，不给近似数、不拿别的数顶替 |
| S3 | 要估算调用成本 | 用户问「这段大概多少钱」 → 技能给出数，并说明缓存命中那部分离线算不出来 |
| S4 | 文本里带特殊标记 | 用户给的文本含 `<｜end▁of▁sentence｜>` → 技能按官方词表把它计进去 |
| S5 | 算一整轮对话请求 | 用户要给一整轮对话估 token → 技能说明光算消息正文不够，得先按对话模板拼装成请求再计数 |
| S6 | 输入没法解码 | 用户给的文件含非 UTF-8 字节 → 技能把这一情况报出来、指认是哪个文件，没把它当成 0 |
| S7 | 一次给多个文件 | 用户给多个文件问合计 → 技能逐个报出并给合计 |
| S8 | 首次运行（引擎还没装） | 用户在没装引擎的机器上直接问 → 脚本自行装好引擎，技能不要求用户额外动手 |

## 依据 → 模型

| 依据的出处 | 模型编号 | 说明 |
|:---|:---|:---|
| `SKILL.md` 用法一节的三种调用方式 | TM-1 | `--text`、文件参数、管道三条来路，以及两行输出 |
| `SKILL.md` 用法一节「首次运行无需联网」与两种安装 | TM-3 | 打包 wheel 优先、联网兜底；行得通与否是条件组合，不是状态迁移 |
| `SKILL.md` 口径与边界一节的四条 | TM-1、TM-4 | 口径、计费以线上 `usage` 为准、缓存命中不可离线算、只覆盖 DeepSeek |
| `SKILL.md` 描述栏的触发语与两种输入 | TM-4 | 用户会怎么问、技能该怎么答 |
| 用户点名的两处高风险：输入边界与异常、首次运行自动装依赖 | TM-2、TM-3 | 前者落在三个有序集上，后者落在三条规则上 |
