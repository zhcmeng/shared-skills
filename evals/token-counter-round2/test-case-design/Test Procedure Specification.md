# 测试规程规格说明

三条规程，按盘上状态会不会被改动排序：只读的 TP-1 排最前，会写盘上文件的 TP-2 居中，靠模型跑的 TP-3 排最后。

## TP-1 取值、边界与异常

| 唯一标识符 | TP-1 |
|:---|:---|
| 英文名 | values_boundaries_and_errors |
| 目标 | 把 TM-1 与 TM-2 导出的取值、边界与异常路径按顺序跑一遍。 |
| 风险等级 | 高 |
| 执行器 | 脚本 |
| 改动文件 | 只读 |
| 启动 | ENV-1、ENV-3、ENV-4、ENV-8 就位；按 DATA-1 至 DATA-12、DATA-15 把样本备好。 |
| 有序执行测试用例 | TC-1、TC-2、TC-3、TC-4、TC-5、TC-6、TC-7、TC-8、TC-9、TC-10、TC-11、TC-12、TC-13、TC-14、TC-15、TC-16、TC-17、TC-18、TC-19 |
| 与其他规程的关系 | 无。这条规程只读，排在最前，跑完再跑 TP-2。 |
| 停止与结束 | 无收尾动作——这条规程不改动测试项，也不留状态。 |

## TP-2 引擎获取的三条规则

| 唯一标识符 | TP-2 |
|:---|:---|
| 英文名 | engine_acquisition_paths |
| 目标 | 把 TM-3 那三条规则各跑一遍：已装引擎直接用、没装时离线装打包 wheel、wheel 用不上时联网兜底。 |
| 风险等级 | 高 |
| 执行器 | 脚本 |
| 改动文件 | 会写 |
| 启动 | 先跑完 TP-1；ENV-1、ENV-3、ENV-4 就位；按 ENV-5 现建一个没装引擎的干净解释器。 |
| 有序执行测试用例 | TC-20、TC-21、TC-22、TC-23 |
| 与其他规程的关系 | 在 TP-1 之后执行——TP-1 要用 ENV-3 那个已装引擎的解释器，先跑免得被这条规程搅了。TP-3 排在这条之后。 |
| 停止与结束 | 把挪开的 `wheels/` 恢复原位，确认与挪动前逐字节一致；删掉那个干净解释器。 |

## TP-3 技能被调用时的交互序列

| 唯一标识符 | TP-3 |
|:---|:---|
| 英文名 | usage_interaction_sequences |
| 目标 | 把 TM-4 那九条场景各跑一轮：用户说一句话，看技能回话里说了什么。 |
| 风险等级 | 高 |
| 执行器 | 控制器 |
| 改动文件 | 只读 |
| 启动 | 先跑完 TP-1 与 TP-2；ENV-1、ENV-3、ENV-4、ENV-7、ENV-8 就位；按 DATA-6、DATA-12、DATA-13 把样本摆进工作区；按 ENV-5 另建一个没装引擎的干净解释器，留给首次运行那一条。 |
| 有序执行测试用例 | TC-24、TC-25、TC-26、TC-27、TC-28、TC-29、TC-30、TC-31、TC-32 |
| 与其他规程的关系 | 在 TP-1 与 TP-2 之后执行。这一条要读一轮模型的表现，与那两条落在不同层上。 |
| 停止与结束 | 删掉那个干净解释器。技能目录本身没被动过，没有别的复位动作。 |

## 各批落到哪

分批准则是判据落在哪：TP-1 与 TP-2 的判据全落在命令、退出码与盘上的文件上，跑一遍就有结论，归一批；TP-3 的判据要读一轮技能被调用时的表现，归另一批。分界落在规程边界上，没有把哪条规程劈开。

| 批次 | 规程 | 执行器 | 落到哪 | 用例目录名 | 说明 |
|:---|:---|:---|:---|:---|:---|
| 批一 | TP-1 | 脚本 | `tests/token-counter/` 下的测试代码 |  | 判据落在命令、退出码与盘上的文件上 |
| 批一 | TP-2 | 脚本 | `tests/token-counter/` 下的测试代码 |  | 这条会挪动 `wheels/` 并在干净解释器里装引擎，落成的测试要把挪动与恢复一并写进去 |
| 批二 | TP-3 | 控制器 | `evals/token-counter-round2/cases/` 下的用例配置 | tp03-01-TC-24-usage_count_file_tokens、tp03-02-TC-25-usage_report_tokens_only、tp03-03-TC-26-usage_other_model_declined、tp03-04-TC-27-usage_cost_estimate_caveat、tp03-05-TC-28-usage_special_token_counted、tp03-06-TC-29-usage_full_chat_request、tp03-07-TC-30-usage_undecodable_input、tp03-08-TC-31-usage_multiple_files_total、tp03-09-TC-32-usage_first_run_no_extra_step | 判据要读一轮技能被调用时的表现。这一批的用例按规程号加规程内位次编目录名，字母序就是执行顺序 |

**这两批落在不同的树上，编号各按同一套写**：批一落进本仓库的 `tests/token-counter/`，批二落进评测材料根下。两处的文件名与注释都照「落成约定」带编号，一条一个号。
