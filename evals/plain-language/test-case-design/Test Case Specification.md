# 测试用例规格说明

测试项：`plugin/skills/plain-language/` 整门技能。它没有脚本，两份文件就是全部——`SKILL.md` 是技能正文，管两档事后用法（无参数时重说最近一条回答、给一个文件路径时逐句审并直接改原文件）；同目录的 `rules.md` 是那份写作规则本身，既由 SessionStart hook 注进上下文（写东西时按它写），也是这两档用法改文字时的判据。全部判据都落在 agent 手里的文字上，属本体层。

三门选定的技术共导出 38 个测试覆盖项：等价类划分 22 个（文字内容的各类形态）、逐处处理判定表 5 个（TM-2 的规则）、产出判定表 6 个（TM-3 的规则）、使用场景 5 个（TM-4 的主场景与备选场景），导出 8 条测试用例。

风险等级照开工输入的风险信息判：用户点名的两处——「改文件时动了不该动的」「硬凑改动／该重说没说」——落在哪几条覆盖项上，那几条判高；其余判中。逐条看：K 组（规则明列照原样写的七类）、Q 组（引文）、S 组里不审的两条、U1（依据未规定的代码块）、O2（K 组一个字没动），以及 TM-2 的规则 1、2、3、5 与 TM-3 的规则 1、2、4，判高；F 组、S 组里要审的两条、O1、TM-2 的规则 4、TM-3 的规则 3、5、6、TM-4 的五条场景，判中。TM-4 的五条判中，是因为这一层把 TM-2 与 TM-3 已经判过的判定放回完整链里再走一遍，不引入新的判点。

判定看两样：agent 当轮的产出文本（改了哪几处、哪几处一个字没动、回复里说了什么），以及盘上那个文件有没有被动过。措辞不限，判的是那几件事有没有做到。

### （一）逐处处置：该改的与不该动的

三条说明：

——TC-1 一条覆盖 20 条覆盖项（TCOV-1 至 TCOV-13、TCOV-21、TCOV-22、TCOV-25 至 TCOV-27、TCOV-32、TCOV-35）。这是有意合到一次执行里的：该改的与不该动的必须在同一份文档里同时在场，「只动该动的」才判得出来；拆成几条只是把同一份文档跑几遍，而本体层跑一次就是几分钟、有花费（见决策依据 DEC-10）。

——「有没有动到不该动的」按盘上那份文档跑前跑后的差别判，不按 agent 自己在回复里怎么说判（ENV-2）。回复里写「只改了三处」不算数。

——TC-8 是这批里唯一不经 skill 的一条，判的是「`rules.md` 注进上下文之后，落笔时按不按它写」。技能会不会被唤起不在这批用例里判，理由见测试模型规格说明 TM-4 的说明。
