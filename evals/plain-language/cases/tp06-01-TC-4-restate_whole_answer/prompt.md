# 评测用例：无参数时把上一条回答整条重讲

## 这条用例防的是什么

`SKILL.md` 的「重说」那一档：无参数收到「这段看不懂」时，把最近产出的那条回答**整条重讲一遍**——换掉黑话与中英文混合，补上英文的中文。三条要求：**只给重讲的那段正文**（不附改动说明、不列拿不准的地方）、**信息不增不减**（不加原文没有的判断，不漏原文有的内容）、问题不再出现。

要防的三种走偏：只改了几个词就交回去（问题还在）、顺手加了原文没有的判断（比如「这样改完会更清楚」）、或者重讲完再附一段「我把 A 改成了 B，把 C 改成了 D」（要求里明说了不附改动说明）。

这一条钉三件事：问题不再出现、信息不增不减、只给正文。

## 怎么跑

1. 按 ENV-1 把 `plugin/skills/plain-language/` 整套（`SKILL.md` 与 `rules.md`）当作使用者机器上装好的这门技能交给 agent。本批用的是 skill-up：它把技能装到工作区的 `.claude/skills/plain-language/`，工作区根就是 ENV-6 那处临时目录。
2. 发下面那条用户消息（DATA-10，见下面的保真度折扣）。
3. 按 ENV-2 取这一轮的回复；按 `graders/restated-and-complete.md`（ENV-3）判。

用户消息（DATA-10 加上 DATA-5 的全文。**这里有一步保真度折扣**：`DATA-10` 原样是 `/shared-skills:plain-language 你上一条回答我读不懂，重讲一遍`，而 DATA-5 该作为 agent 的上一条回答在上下文里；本批用的是 skill-up，它的多轮只收 `user` 角色，塞不进一条 `assistant` 消息，所以把 DATA-5 的全文接在了这条用户消息里。见实施方案 2.1 第 5 小节第 3 条）：

```
/plain-language 你上一条回答我读不懂：

我把这次改动梳理了一下。整件事的思路是上层认知扩口、下层收割：先让读者知道现在这套检查有个盲区，再给出补上的办法。

具体做法是在 `checks/verify.d/` 下面加一个模块，名字叫 `30-tables.sh`。这个模块的心智物理很简单：把文档里所有表格的行列数对一遍，对不上的就报出来。这样整条链路的 decision journey 会更顺一些。

另外我们 align 一下这个 approach 的边界：新模块只管表格，链接和标题层级还是原来的 `10-links.sh` 与 `20-headings.sh` 管。跑的时候用 `bash checks/verify.sh`，一次全跑。

重讲一遍
```

## 基线证据

跑过一次（`batch3-full` 运行一，2026-09-29）：**1 次 1 过**（判 6/6）。

回复原话（全文三段）：

> 我把这次改动梳理了一下。整件事的思路分两步：先说明现在这套检查有个盲区，再给出补上的办法。
>
> 具体做法是在 `checks/verify.d/` 下面加一个模块，名字叫 `30-tables.sh`。这个模块做的事很简单：把文档里所有表格的行列数对一遍，对不上的就报出来。这样整个流程走下来会更顺一些。
>
> 另外把范围也说清楚：新模块只管表格，链接和标题层级还是原来的 `10-links.sh` 与 `20-headings.sh` 管。跑的时候用 `bash checks/verify.sh`，一次全跑。

三处问题都换掉了：「上层认知扩口、下层收割」→「分两步：先说明……再给出……」；「心智物理」→「做的事」；「我们 align 一下这个 approach 的边界」→「把范围也说清楚」。`decision journey` 那半句换成「整个流程走下来」，意思留着、比喻去掉。信息没增没减：三层意思（为什么这么做、新模块做什么、边界在哪、怎么跑）都在，没有加原文没有的判断。只有正文，没有改动说明、没有拿不准的清单。

照原样写的四处（`checks/verify.d/`、`30-tables.sh`、`10-links.sh`／`20-headings.sh`、`bash checks/verify.sh`）逐字保留。
