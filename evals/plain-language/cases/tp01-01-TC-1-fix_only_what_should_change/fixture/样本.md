# 项目说明

这份文档写给刚加入的同学，读一遍就能上手。

## 一、我们怎么做内容

我们做内容的思路是上层认知扩口、下层收割：先让读者意识到问题，再给出我们的方案。

判断一段话好不好，看它的心智物理对不对——读者脑子里那个模型，有没有被我们说动。

第一条约定叫「先给结论」：把结论放在开头，理由放后面。

## 二、几条常见毛病

第一种是把话说得太满。写完先放一天再看，多半能删掉三成。

第二种是几个人一起写，术语各叫各的。我们 align 一下这个 approach：同一样东西，全篇只用一个叫法。

第三种是让读者自己去猜。上一版就是这样，读者读完三段才知道我们要说什么。

## 三、工程上的约定

前面说的「先给结论」这条，在工程文档里同样适用。

写接口文档时注意图案的复用，同一段描述尽量只写一次；每个接口的判定形状也要写全，参数和返回值一个都不能少。

代码从 `main()` 进去，配置读同目录的 `settings.json`。

动笔之前先读 `plugin/skills/plain-language/rules.md`，那份文件是唯一的判据来源。

提交前跑一遍 `bash checks/verify.sh`，它会查链接和标题层级。

仓库里所有文档用 UTF-8 存盘。

这套东西在 Claude Code 里跑，跟别的工具链不冲突。

## 四、市场这一面

做内容这一行，护城河不是辞藻，是持续产出的能力；天花板不是预算，是有没有人看；这条赛道比的是谁更早想明白读者要什么。

## 五、Asymmetric Information

这一节讲信息不对称：卖家知道底细，买家不知道，价格就是这么被推上去的。

## 六、写完之后

把这段注入 context，让模型下次写东西时看得见；要找旧记录，再去 memory 里翻。
