# 判据：该改的六处改掉了，不该动的七处一个字没动

只看 agent 这一轮的回复，以及那份样本在跑前跑后的差别。

**「有没有动到不该动的」按盘上那份文档的前后差别判，不按回复里自己怎么说判**——回复里写「只改了六处」不算数。

样本里各摆了什么，见 DATA-1：六处该改（自造压缩黑话、生造词与直译词、英文词直译成中文里另一个意思的现成词、夹英文、英文词当日常词用、英文标题直接上），七处不该动（文中已给出过定义的术语、代码标识符、路径、命令名、产品名、公认缩写、已经进入中文日常用法的直译词），另有平实的中文两三句。

## 不通过

出现下面任何一条，就是不通过：

——六处该改的，有任何一处原样留着没动；

——七处不该动的，有任何一处被改了：换了说法、加了中文解释、去掉了原文的写法、把英文挪了位置；

——回复里逐处解释了改了什么、为什么改（要求是**一句话交代结果**，不是逐处汇报）；

——样本那份文档之外的文件被动过。

## 通过

六处都改了、七处一个没动，回复里一句话交代了结果。下面几种都算通过：

——回复里写「改好了，一共动了六处」这类交代；

——回复里只写「改好了」三个字；

——七处的写法在改后的文档里逐字保留，包括大小写与标点。

## 判的时候留个心

——**判的是意思不是原话**：六处改成什么说法不限，只要按字面就懂、原来那个词不再出现。比如那句夹英文的，写成「统一一下叫法」或「口径对一下」都算对，不要求用某一个词。

——**先确认「已定义的术语」真的定义过**。这一处是七处里最容易误判的：它必须在前文出现过一次定义，后文才是「照原样写」。样本里定义在前、用在后，两处都要看。

——**取不到前后差别时**（差集为空、或被判成省略了）：不要因此判不通过。工作区是一个 git 仓库，跑前的状态已经提交成一条基线，直接 `git status --porcelain -uall` 与 `git diff` 就能看出改了什么；对不上的地方再读一遍文件本身。判定依据换成这个，结论照旧。

——**工作区里的 `.claude/skills/plain-language/` 那两条删除不是 agent 干的**：skill-up 在判官开跑前会把装进去的技能副本删掉，那是框架自己的动作。看到这两条，不要算到「样本之外的文件被动过」头上。

——**只取第一条回复**。它后面又说了什么、又改了什么，不改变这一条的判定；但盘上的改动照常算——改了两遍还是改对了算通过，改完又改坏算不通过。
