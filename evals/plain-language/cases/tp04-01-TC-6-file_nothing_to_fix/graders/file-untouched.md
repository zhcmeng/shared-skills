# 判据：那份文件逐字节没变，回复里说了不用改

只看 agent 这一轮的回复，以及那份样本在跑前跑后的差别。

**「动没动」按盘上那份文档的前后差别判，不按回复里自己怎么说判。**

样本按 DATA-4 造：通篇平实的中文，一处那几类问题都没有。里面有代码标识符、路径、命令名这类照原样写的——按规则本来就该照贴，它们不是问题。

## 不通过

出现下面任何一条，就是不通过：

——那份文件被改了哪怕一个字节：换了说法、调了语序、加了或删了标点、改了标题层级、补了空行、动了行尾换行；

——回复里没有说出「没有需要改的地方」这个意思——比如只说「看过了」、只复述了一遍文档内容、只列了几处「可以更顺一点」的地方；

——那份文件之外的文件被动过。

## 通过

那份文件跑完与跑前逐字节相同，回复里说出了「这份没有需要改的地方」这个意思。下面几种都算通过：

——「这份没有需要改的地方。」；

——「通读了一遍，一处要改的都没找到。」；

——「文档写得挺清楚，我没有改动。」

## 判的时候留个心

——**「逐字节相同」按改动差别判**：取不出前后差别时不要因此判不通过。工作区是一个 git 仓库，跑前的状态已经提交成一条基线，直接 `git status --porcelain -uall` 与 `git diff` 就能看出改了什么；对不上的地方再读一遍文件本身比对。判定依据换成这个，结论照旧。

——**回复里可以顺带说别的**：说了一句「文档里那几处代码和路径我照原样留着」不影响通过。「没有需要改的地方」这个意思在，就不算漏说。

——**「改了又改回来」也算没改**：只要最终盘上那份与跑前逐字节相同，中间动过不算。

——**不许把原文重抄一遍当成产出**：回复里贴一遍全文、或贴一遍「润色后」的全文，都不算说出了「不用改」，按不通过算——用户看不出你到底改没改。

——**「愿意帮别的忙」不算没说出**：说了「没有需要改的地方」之后又加一句「要不要我再看别的文档」，照旧通过。

——**工作区里的 `.claude/skills/plain-language/` 那两条删除不是 agent 干的**：skill-up 在判官开跑前会把装进去的技能副本删掉。看到这两条，不要算到「样本之外的文件被动过」头上。

——**只取第一条回复**。它后面又说了什么，不改变这一条的判定；但盘上的改动照常算。
