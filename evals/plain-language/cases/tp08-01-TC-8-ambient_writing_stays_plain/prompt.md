# 评测用例：常驻注入之下直接写东西

## 这条用例防的是什么

`rules.md` 不只在这门技能被调用时生效——它同时是**常驻注入的写作约束**：会话开头就进了上下文，之后写东西一律按它写。这条用例判的正是这一档：**不经 skill、不喊命令**，直接发一条写作请求，看落笔时按不按那套要求写。

要防的是「规则只在被调用时才生效」这个退化：技能装着、规则也注进了上下文，可一旦没人喊 `/plain-language`，写出来的还是原来那套——夹英文、生造词、英文标题直接上。这条要是坏了，说明 `rules.md` 作为常驻约束是失效的，只有插件那条道在用。

**这一条跑在运行二**：不装技能，只把 `rules.md` 注进上下文。跑法与其余七条不同，这是设计稿里就写着的，不是折扣。

这一条钉三件事：产出里出现的每一个英文词都在当地给了中文、没有自造压缩黑话与生造词、没有夹英文的句子。

## 怎么跑

1. **不装技能**。常驻注入按 ENV-5 走：`environment.setup_steps` 里一条 `cat "C:/work/shared-skills/plugin/skills/plain-language/rules.md" >> CLAUDE.md`，从绝对路径读真仓库那份 `rules.md` 写进工作区的 `CLAUDE.md`——Claude Code 起会话时读项目根目录的 `CLAUDE.md`，跟 SessionStart 钩子一样是会话开头的常驻上下文。同一条道在运行一也要接（ENV-5），八条的差别才回到「用不用 skill」这一件事上。
2. 夹具按 ENV-6 铺开，这份工作区里就是这个仓库的内容（`README.md`、`checks/`、`docs/` 那些），够 agent 写出那两百字。
3. 发下面这条用户消息（DATA-14）。**这条消息不带技能名**——这一档不经 skill。
4. 按 ENV-2 取这一轮的回复；按 `graders/plain-output.md`（ENV-3）判。

用户消息（DATA-14）：

```
帮我写一段两百字左右的说明，讲讲这个仓库的检查脚本是怎么跑的
```

## 基线证据

跑过一次（`batch3-full` 运行二，2026-09-29）：**1 次 1 过**（判 6/6）。这一档不经 skill、不喊命令。

回复开头一段：「看完了。入口、两个模块、README 和 `docs/getting-started.md` 的用词都核对过，下面这段说明约两百字，用的也是仓库里已有的说法（自查、模块、跳级、红了）：」后面跟那两百字说明。

产出里的英文只有 `checks/verify.sh`、`checks/verify.d/`、`10-links.sh`、`20-headings.sh`、`README`、`docs/getting-started.md`、`bash`、`*.sh` 这些路径、命令名与文件名——照原样写的那些，不需要给中文。没有夹英文的句子，没有自造压缩黑话，没有生造词与直译词。**常驻注入这一层是生效的**：没喊技能，落笔照样按 `rules.md` 写。
