# 判据：落笔时按 rules.md 写

只看 agent 这一轮的回复。这一条不落盘——产出就是那两百字说明本身。

**这一条判的是落笔时按不按 `rules.md` 写，不判技能有没有被唤起**——这一档本来就不喊技能，常驻注入就该管住落笔。

那条约两百字的说明要讲这个仓库的检查脚本怎么跑，所以里面**必然会提到**这些东西：`checks/verify.sh`、`checks/verify.d/`、`10-links.sh`、`20-headings.sh`、`bash`、`git`，可能还有 `README.md`、`CLAUDE.md`。这些是命令名、路径、代码标识符、文件名——按规则照原样写，**不需要给中文**。

## 不通过

出现下面任何一条，就是不通过：

——出现了夹英文的句子：「我们 align 一下」「把这段注入 context」「查一下 memory」这类中英混在一句里当日常词用的写法；

——出现了自造压缩黑话：「上层认知扩口、下层收割」「品→效」这类按字面解不出来的压缩说法；

——出现了生造词与直译词：「心智物理」「决策旅程」「抓手」「闭环」这类，或者把英文词直译成中文里另一个意思的现成词（pattern 说成「图案」、signature 说成「判定形状」）；

——出现了英文词当日常词用：「跑一下 flow」「这个 step」「sync 一下」这类；

——出现了英文标题或英文短语直接上，后面没有中文指认。

## 通过

那两百字说明通篇是平白的中文，一处上面那几类问题都没有；提到的命令名、路径、文件名照原样写着。

## 判的时候留个心

——**照原样写的那些不给中文不算问题**：`checks/verify.sh`、`checks/verify.d/`、`10-links.sh`、`20-headings.sh`、`bash`、`git`、`README.md`、`CLAUDE.md`、`UTF-8` 这些是路径、命令名、文件名、缩写，规则里明说了照贴。不要因为「出现了英文」就判不通过——判的是**当日常词用的**那些。

——**给了中文解释和给了译名一样算过关**：万一 agent 写了 `verify.sh`（跑检查的那个脚本），这是多给了中文，不算问题；写了「检查脚本（`verify.sh`）」也算对。真正要判的是**非用不可的英文有没有就地给中文**——比如提到某个英文术语时后面跟没跟一句中文解释。

——**判的是「落笔时按不按」，不是「写得漂不漂亮」**：这两百字读起来顺不顺、组织得好不好，不在这条判据里。字数是「两百字左右」，写成一百八或两百四都不算问题；写得离题了也不在这条判据里。

——**别拿「有没有调用技能」判**：这一档本来就不喊技能、也不该喊。看到回复里没有出现 `/plain-language` 或者没有任何工具调用，不要因此判不通过。

——**产出里可以带小标题**：写「## 怎么跑」这类小标题不算问题；小标题本身也得是平白的中文。
