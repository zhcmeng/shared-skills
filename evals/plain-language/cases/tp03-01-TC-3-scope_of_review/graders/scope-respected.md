# 判据（一）：该审的三处改掉了，frontmatter 一个字没动

只看 agent 这一轮的回复，以及那份样本在跑前跑后的差别。

**「动没动」按盘上那份文档的前后差别判，不按回复里自己怎么说判。**

样本里各摆了什么，见 DATA-3：一处图注、一处脚注说明、一个 mermaid 图里的文字——这三处有该改的；一段 YAML frontmatter——不该动。另有正文若干。

## 不通过

出现下面任何一条，就是不通过：

——图注里那几类问题原样留着没动；

——脚注说明里那几类问题原样留着没动；

——mermaid 图里的文字有问题没动（图里的节点标签、连线上写的话算文字，要审；图本身的结构不算）；

——YAML frontmatter 被动过：字段名被译成中文、字段值被改写、格式被重排、被删掉或补了字段；

——那份文档副本之外的任何文件被动过。

## 通过

图注、脚注说明、mermaid 图里的文字这三处的该改之处都改掉了，frontmatter 逐字节没动。

## 判的时候留个心

——**改法不限**：这三处改成什么说法都行，只要按字面就懂、原来那个词不再出现。要求的是「按意思判」，不是「按某个指定的词判」。

——**mermaid 图改了之后还得是能画的图**：改了节点标签里的中文算对；把 `flowchart LR` 这类图类型关键字、箭头写法、节点 id 一起改了，改到画不出来，那也算动了不该动的——这一条只要求改里面的文字。

——**frontmatter 与其他内容一样要逐字节比**：分隔线 `---`、字段顺序、缩进、冒号后的空格，全算在里面。只改了一个字段值也是不通过。

——**取不到前后差别时**（差集为空、或被判成省略了）：不要因此判不通过。工作区是一个 git 仓库，跑前的状态已经提交成一条基线，直接 `git status --porcelain -uall` 与 `git diff` 就能看出改了什么；对不上的地方再读一遍文件本身。

——**工作区里的 `.claude/skills/plain-language/` 那两条删除不是 agent 干的**：skill-up 在判官开跑前会把装进去的技能副本删掉。看到这两条，不要算到「样本之外的文件被动过」头上。

——**这一条与「代码块那一处」分开判**：代码块里的中文算不算要审的，依据里没规定，所以那一处**不在这条判据的范围内**，改了不扣分、没改也不扣分，由 `code-block-unspecified.md` 单独判。
