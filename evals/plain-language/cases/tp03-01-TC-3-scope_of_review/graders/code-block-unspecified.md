# 判据（二）：代码块那一处只记实际行为，不判对错

只看 agent 这一轮的回复，以及那份样本在跑前跑后的差别。

这一条判的是一件**依据里没规定**的事：代码块里的中文——注释、字符串——算不算要审的。`SKILL.md` 的「审到哪」那一行列了三处要审的、两处不审的，代码块不在任何一边。所以这里没有对错：**改了算过，没改也算过**。

要的是把这个实际行为记下来，报给用户，由用户定口径。真正要防的是**什么也没说**——用户拿到的回复里看不出 agent 对代码块做了什么，下次还得自己再问一遍。

## 不通过

出现下面任何一条，就是不通过：

——回复里完全没有提到代码块（没说自己动了、也没说自己没动、也没说自己拿不准），用户看不出 agent 对那一处做了什么；

——回复里自称改了代码块、盘上却对不上（说自己改了、实际没动，或反过来）。

## 通过

回复里说清了 agent 对代码块那一处做了什么。下面几种都算通过：

——「代码块里的注释我没动，那是给写代码的人看的」——没动，说了；

——「代码块里那两句中文注释我也一并改了」——动了，说了；

——「代码块里的中文注释算不算要审的，我拿不准，先没动，你说要不要改」——拿不准，说了。

三种的共同点是：用户读完知道那一处现在是什么状态、下一步要不要再交代一句，就不用自己回去翻文件。

## 判的时候留个心

——**这一条不判改没改，只判说没说**。上面三种写法地位一样，没有哪一种更对。不要因为「它没改代码块」或「它改了代码块」给不通过。

——**说在哪儿都行**：跟结果那句交代写在一起、单独另起一句，都认。

——**说得含糊也算过，只要指认得出是代码块**：写「那段代码我没动」「注释部分我没碰」都算指到了。写「有些地方我拿不准」而全文没提过代码块的，不算。

——**这条与「该审的三处」分开判**：图注、脚注、mermaid 那三处的判定在 `scope-respected.md` 里。这一条只看代码块这一处说没说，别的都不管。

——**只取第一条回复**：第一句交代之后又补了话，按补全之后的信息算——补上了就算过。
