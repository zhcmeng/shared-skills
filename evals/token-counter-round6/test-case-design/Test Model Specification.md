# 测试模型规格说明

四门技术各建一个模型，下面分四节列出。文档末尾是「依据 → 模型」对应表。

## TM-1 输入道与报数口径的等价类划分模型

- **唯一标识符**：TM-1
- **英文名**：input_route_and_reporting_partitions
- **目标**：技能收哪几种输入、按哪条道把要数的文本取到手、报回来的有哪几样、答话的口径是什么。数得准不准由 TM-2、TM-3 那两组管，这里只管输入怎么进来、话怎么说回去。
- **风险等级**：高。风险信息点名了「输入边界与异常」这一处，这一组等价类正是它落地的第一处——输入从哪条道进来、进来的是哪一类，都归这里。
- **测试策略摘要**：等价类划分。与 TM-2、TM-3、TM-4 各建各的模型，不互相喂数据——TM-1 管输入怎么进来、话怎么答回去，TM-2 管边界上的取值，TM-3 管什么条件下走哪条安装道，TM-4 管一句请求走多远。它另有一处往外供料：本模型导出的调用方式与文本取值那几类，用来给 TM-4 的用例挑输入参数（谁给谁供料：等价类划分 → 场景测试）。四门技术全在基于规格说明这一类，擅长检出的是遗漏型缺陷；多余型缺陷那一侧要换成基于结构的技术才补得上，这一套里没有它。测试完成准则是等价类划分覆盖率 100%，全部等价类都要有用例覆盖。
- **测试模型**：等价类清单如下，按输入处理、内部处理、输出处理三组列，类别编号沿用 `PART-`。

输入处理：调用方式

- PART-1 有效：在命令行上用 `--text` 直接给一段文本
- PART-2 有效：给一个存在的 UTF-8 文本文件的路径
- PART-3 有效：把要数的内容用管道从标准输入喂进来
- PART-4 无效：给的文件路径不存在
- PART-5 无效：给的路径指向一个目录
- PART-6 无效：文件在，但不是合法的 UTF-8 字节

输入处理：交到脚本手里的那段文本

- PART-7 有效：纯 ASCII 文本
- PART-8 有效：纯中文文本
- PART-9 有效：中英混排、含空格与换行的文本
- PART-10 有效：一个字符都没有的空文本
- PART-11 有效：开头带一个完整字节顺序标记的文本
- PART-12 特殊：含 DeepSeek 特殊 token 字面形的文本

内部处理：词表怎么读

- PART-13 有效：按随技能分发那份词表的规范语义加载它
- PART-14 无效功能：改用另一条兼容加载路径读同一份词表

输出处理：报回来的东西

- PART-15 有效：报出 token 数与 UTF-8 字符数两行
- PART-16 有效：用户只要 token 量时，答话里报出 token 数
- PART-17 有效：用户问调用成本时，点明离线算不出缓存命中、计费以接口返回的用量为准
- PART-18 有效：用户点名别的模型时，说明本技能不覆盖那个模型、不给近似数
- PART-19 无效功能：绕开本技能另去找一个数顶上，给出别的模型的近似 token 数
- PART-20 有效：要估一次完整对话请求时，先按对话模板把请求拼装起来再计数

PART-4、PART-5、PART-6 这三类走不通的输入，依据里只说了输入应当是 UTF-8 文本，没说走不通时该怎么办——这几处的预期结果按「依据未规定这一处」记，不写成依据撑不起的取值；原因与另两条同类的决定一并记在决策依据里。PART-14 与 PART-19 是无效功能：依据里明令不许这么做，测试项若真这么做了，缺陷在测试项那一侧。PART-14 有一条查得到的痕迹——改用兼容加载路径之后，以中文开头的文本会被编成空序列，数出来正是 0，那个数一眼看得出来不对。

## TM-2 输入边界的带边界等价类模型

- **唯一标识符**：TM-2
- **英文名**：input_boundary_values
- **目标**：交过去的那段文本落在边界上的几个取值——字符个数是 0 还是 1、一个字符在 UTF-8 里占几个字节、开头那一段属于字节顺序标记的字节有几个。落在区间中间的取值归 TM-1，这一门只管边界。
- **风险等级**：高。风险信息里「输入边界与异常」这一处，后半截「边界」正落在这个模型上。
- **测试策略摘要**：边界值分析，取二值边界测试——每个边界识别两个覆盖项，分别是边界上的值与边界外一个增量距离的值，增量距离取所考虑数据类型的最小有效值（字符数增 1 个字符，字节数增 1 个字节）。它以 TM-1 划出的等价类为起点：先有等价类，再把其中有边界的几类挑出来标上边界（谁给谁供料：等价类划分 → 边界值分析）。取二值还是取三值宜记下来，这一处记在决策依据里。测试完成准则是边界值覆盖率 100%，覆盖全部已识别且可行的边界值。
- **测试模型**：带边界的等价类如下。三个有序集，每个集里的元素都能从最低到最高无间断地排。

| 有序集 | 区间 | 下边界 | 上边界 |
|:---|:---|:---|:---|
| 甲：一次调用交过去的文本的字符个数 | 0 起，无上界 | 0 | 无。上界由承载它的解释器定，依据里没有可识别的取值 |
| 乙：一个字符在 UTF-8 里占的字节个数 | 1 到 4 | 1 | 4 |
| 丙：文本开头属于字节顺序标记的字节个数 | 1 到 3 | 不取，理由见决策依据 | 3——一个完整的字节顺序标记恰好占 3 个字节 |

甲、乙、丙三个集在二值边界测试下识别出的边界值见测试用例规格说明的覆盖项清单。乙那一集的两个区间外取值（占 0 个字节、占 5 个字节）在 UTF-8 里造不出来，判为不可行，剔除原因写在那条覆盖项的描述栏里。

## TM-3 首次运行装依赖的判定表模型

- **唯一标识符**：TM-3
- **英文名**：first_run_install_decision_table
- **目标**：目标解释器里能不能导入那份引擎、随技能打包的那份包在不在、装不装得上，这三件事凑在一起时脚本走哪条安装道。装完之后照常计数那一截归 TM-4。
- **风险等级**：高。风险信息里「首次运行自动装依赖」这一处正落在这个模型上。
- **测试策略摘要**：判定表测试。与其余三个模型各建各的模型，不互相喂数据。四门里只有这一门管安装道那一侧，别的三门都碰不到它。测试完成准则是判定表测试覆盖率 100%，只算可行的判定规则——下表四条都可行，没有不可行的规则。
- **测试模型**：用判定表表示，见下表；表后是逐条规则清单。

| 条件与动作 | 规则 1 | 规则 2 | 规则 3 | 规则 4 |
|:---|:---|:---|:---|:---|
| 条件 C1：目标解释器里已经能导入那份引擎 | T | F | F | F |
| 条件 C2：随技能打包的那份包在（`wheels/` 下有一个包文件） | — | T | T | F |
| 条件 C3：打包那份在当前平台上装得上 | — | T | F | — |
| 动作 A1：直接用现成的引擎，一个字节都不装 | T | F | F | F |
| 动作 A2：先装上随技能打包的那份（离线、不带依赖） | F | T | F | F |
| 动作 A3：改从包索引联网装钉住的版本 | F | F | T | T |

逐条规则读出来：

- 规则 1：C1＝T——直接用现成的引擎，不装、不联网。C2、C3 在这一列写成「—」：C1 已经为真时，打包那份在不在、装不装得上，都管不到该做什么。
- 规则 2：C1＝F、C2＝T、C3＝T——先装上随技能打包的那份，装法上带 `--no-deps`，全程不联网。
- 规则 3：C1＝F、C2＝T、C3＝F——打包那份在，可它装不上，改从包索引联网装钉住的版本。
- 规则 4：C1＝F、C2＝F——打包那份压根不在，直接走联网那条道。C3 在这一列写成「—」：没有包可装，「装不装得上」无从谈起。

C3 取假有两种成因，都落在规则 3 上：当前平台与随技能打包的那份对不上（非 Windows x64，或 CPython 低于 3.9）；或者平台对得上、装的动作本身没成。两种成因下脚本的动作一样，都是改走联网那条道——按规矩，这一条规则配两条用例，各走一种成因，写在决策依据里。脚本里钉住的版本号是 0.22.2，规则 3 与规则 4 装的就是它。

## TM-4 一次计数请求的交互序列模型

- **唯一标识符**：TM-4
- **英文名**：counting_request_scenarios
- **目标**：一句请求从进来到结果报回，中间走过哪些步；以及这条序列在哪几处会分岔。
- **风险等级**：中。风险信息点名的两处里，「首次运行自动装依赖」那一处在这条序列上有一步（下面序列里的 S4.1），但它在 TM-3 已经判为高，这里不重复加高；「输入边界与异常」那一处落在 TM-1、TM-2 上。
- **测试策略摘要**：场景测试（用例测试归在这一门里）。TM-1 导出的调用方式与文本取值用来给这一门的用例挑输入参数（谁给谁供料：等价类划分 → 场景测试）——场景本身照下面这条序列走，走的时候用哪段文本、走哪条调用方式，从 TM-1 那几个等价类里取。测试完成准则是覆盖主场景与全部备选场景。
- **测试模型**：用交互序列表表示。每个动作用一个标识符表示，`U` 打头的是用户那侧的动作，`S` 打头的是测试项这一侧的动作。

公共的几步先列在这里，各场景用标识符引用：

- U1：用户提出一句算 token 的请求
- S1：技能按名唤起，读到自己那份说明正文
- S2：定位到计数脚本所在的目录
- S3：把要数的文本按调用方式交给脚本，用绝对路径把脚本调起来
- S4：脚本按规范语义加载随技能分发的那份词表，数出 token 数
- S5：脚本数出 UTF-8 字符数，把两样打成两行
- S6：技能把数报回给用户

各场景如下：

| 场景 | 类型 | 交互序列 |
|:---|:---|:---|
| 一次计数请求走完 | 主场景 | U1、S1、S2、S3、S4、S5、S6 |
| 点名的是别的模型 | 备选场景 | U1、S1、S1.1、S6.1 |
| 问的是调用成本 | 备选场景 | U1、S1、S2、S3、S4、S5、S6.2 |
| 文本要喂进一次完整对话请求 | 备选场景 | U1、S1、S2、S3.1、S4、S5、S6 |
| 目标机是干净的、没装引擎 | 备选场景 | U1、S1、S2、S3、S4.1、S5、S6 |
| 用户只要 token 量 | 备选场景 | U1、S1、S2、S3、S4、S5、S6.3 |
| 文本里含特殊 token 的字面形 | 备选场景 | U1、S1、S2、S3.2、S4、S5、S6 |
| 用户给的输入走不通 | 备选场景 | U1、S1、S2、S3.3、S6.4 |

序列里那几步的差别：

- S1.1：技能读到的说明正文里写着「只覆盖 DeepSeek 当前官方词表；点名别的模型时明确说明不覆盖，不给近似估算」这一条，序列就此分岔，脚本一条都不跑。
- S6.1：说明本技能不覆盖那个模型、一个数都不报；不绕开本技能另找一个数顶上。
- S6.2：在报数之外多一句，点明离线算不出缓存命中、计费以接口返回的用量为准。
- S3.1：把文本交给脚本之前多一步，先按对话模板把这段文本拼装成一次完整请求，再交给脚本数。
- S4.1：脚本发现目标机上没装引擎，先装上随技能打包的那一份，再加载词表计数。
- S6.3：答话里报出 token 数。
- S3.2：交过去的是原样的文本，含特殊 token 字面形的那一段不转义、不拆开、不剥离。
- S3.3：用户那侧没有可数的东西交过来，或者给的那条道走不通（路径不存在、路径指向目录、内容不是合法 UTF-8）；脚本这一头以非零退出码收场，两行都不打。
- S6.4：照实把「这个输入数不了」说给用户，不报出任何 token 数、也不拿别的数顶上。

| 依据的出处 | 模型编号 | 说明 |
|:---|:---|:---|
| `token-counter` 技能说明 `SKILL.md`·描述一节 | TM-1 | 触发语、支持一段文本与一个文件两种输入 |
| `token-counter` 技能说明 `SKILL.md`·用法一节 | TM-1 | 三条调用方式、脚本所在目录、报回来的是 token 数与字符数两行 |

| `count_tokens.py`·`read_source` 与 `main` | TM-1 | 三条调用方式的先后，以及读到读不动的内容时以非零退出码收场、两行都不打 |

| `token-counter` 技能说明 `SKILL.md`·开头一段 | TM-3 | 词表随技能分发、引擎包随技能打包、首次运行自动装依赖，以及两条安装道各自的触发条件 |

| `token-counter` 技能说明 `SKILL.md`·口径与边界一节 | TM-4 | 点名别的模型、问调用成本、完整对话请求、走不通的输入这几处分岔该报什么 |
