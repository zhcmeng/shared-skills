# 测试环境需求

一项环境项一行，写这四栏。头两项是测试运行环境——测试规程在哪儿跑、被测那侧在哪儿执行，两条都由技能定下，不是向用户要来的；其余各条按用例与规程的需要往外补。

| 唯一标识符 | 英文名 | 测试环境项 | 描述 |
|:---|:---|:---|:---|
| ENV-1 | test_run_host | 测试规程在哪儿跑 | 本机。命令直接在宿主机上跑，不起容器、不进虚拟机。这一条是技能判定的，来源记「技能定的」。 |
| ENV-2 | target_host | 被测那侧在哪儿执行 | 本机——与 ENV-1 是同一台机器。跑这个技能的会话也起在这台机器上，用的是本机装着的那个命令行工具。这一条是技能判定的，来源记「技能定的」。 |
| ENV-3 | host_python | 宿主机的 CPython | 版本不低于 3.9，且是 64 位。版本与位数由宿主机决定，配置里不写死，跑之前确认一次。低于 3.9 或者不是 64 位时，随技能打包的那份引擎包装不上，会掉进包索引那条道，几条安装道的走法就与 TM-3 那张表对不上了。 |
| ENV-4 | bundled_assets | 技能目录里随技能分发的两份东西 | 官方词表 `tokenizer.json`，以及打包好的引擎包 `wheels/tokenizers-0.22.2-cp39-abi3-win_amd64.whl`。两份都在技能目录下，装技能时跟着技能一起进工作区；跑之前确认两份都在、都读得动。 |
| ENV-5 | engine_installed_interpreter | 装了引擎的解释器 | 就是 ENV-3 那个解释器，里面已经装好了那份引擎，版本不低于打包的那一份。脚本那一批的常规前提都落在这一条上；TC-17 更是直接看这个状态——引擎已在位时一个字节都不许装。 |
| ENV-6 | clean_interpreter | 没装引擎的解释器 | 由 ENV-3 那个解释器现建出来——另起一个空的虚拟环境那种；建完确认里面对那份引擎是导入不了的。它回答的是「首次运行」那件事：引擎压根不在位。跑完整个丢掉，下次再跑这一批之前重新建一个空的。TP-4 要三个、TP-7 要一个，各用各的，不共用一个。 |
| ENV-7 | skill_copies_with_tampered_wheels | 两份动过 `wheels/` 的技能副本 | 把整份技能目录复制到临时目录下，复制两份：一份把 `wheels/` 下原来的包挪走、只留 DATA-12 那份装不上的包；另一份把 `wheels/` 清空。两份都放在临时目录下，跑完整个丢掉，技能本体一个字节不动。 |
| ENV-8 | per_case_workspace | 每条用例各起的一个空工作区 | 每条用例开跑前新建一个空目录当工作区，跑完删掉；上一轮留下的东西不进下一轮。工作区由跑测那一侧自己建，用例配置里不指定路径。 |
| ENV-9 | skill_installed_in_workspace | 技能装进工作区的位置 | 被测技能整个目录装到工作区的 `.claude/skills/token-counter/` 下，随技能分发的 `tokenizer.json` 与 `wheels/` 跟着一起进去。技能按名唤起，不带插件名前缀。 |
| ENV-10 | package_index_reachable | 从包索引联网装包那条道 | 宿主机连着包索引，钉住的版本（0.22.2）装得上。只有 TC-19、TC-20 用得着这一条：它们要看的正是「打包的那份用不上或者不在时改走包索引那条道」。这一条不满足时这两条用例跑不了，其余各条不受影响。 |
