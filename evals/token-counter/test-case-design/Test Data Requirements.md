# 测试数据需求

执行三条测试规程所需的样本与输入数据，逐条列出。表里给出的 token 数与字符数都是官方词表（`tokenizer.json`）的规范语义，用例拿它当预期结果。

表里带「LF」的样本文件要按写明的字节数逐字节生成：**行尾一律是单个换行符（LF，字节 `0A`）**，不要用编辑器或脚本的默认写法在 Windows 上生成（那样会变成 CRLF，每行多一个字节，`chars` 与 `tokens` 都会跟着变，预期结果就不成立了）。生成后先核对字节数再执行用例。

| 唯一标识符 | 描述 |
|:---|:---|
| DATA-1 | 正文样本「你好，世界」：5 个字符，UTF-8 占 15 字节；官方口径为 3 个 token |
| DATA-2 | 正文样本「hello world」：11 个字符，正好 11 字节，结尾不带换行；官方口径为 2 个 token |
| DATA-3 | 正文样本「中文开头 abc」：8 个字符，UTF-8 占 16 字节；官方口径为 3 个 token |
| DATA-4 | 正文样本「<｜end▁of▁sentence｜>」：19 个字符，UTF-8 占 27 字节；在官方词表里整串是一个特殊 token，官方口径为 1 个 token |
| DATA-5 | 空白样本：两个空格、一个制表符、两个换行，共 5 个字符；官方口径为 2 个 token |
| DATA-6 | 正文样本「🎉」：1 个字符，UTF-8 占 4 字节；官方口径为 2 个 token |
| DATA-7 | 样本文件「样本.md」（LF）：内容依次为「# 标题」、一个空行、「正文 hello world」、结尾一个换行；共 21 个字符，UTF-8 占 29 字节；官方口径为 8 个 token |
| DATA-8 | 样本文件「代码样本.py」（LF）：两行内容，「def add(a, b):」与缩进四格的「return a + b」，结尾一个换行；共 32 个字符、32 字节；官方口径为 12 个 token |
| DATA-9 | 样本文件「bom.md」（LF）：开头三个字节是 UTF-8 的 BOM（EF BB BF），后面是「你好」；整份 9 字节；官方口径为 1 个 token，正文按 2 个字符计 |
| DATA-10 | 样本文件「空文件.md」：0 字节 |

| DATA-13 | 一个目录路径，例如样本文件所在的那一级目录本身 |
| DATA-14 | 送到标准输入的一串字节：与 DATA-11 相同的六个字节 FF FE 00 61 62 63，结尾不带换行 |
| DATA-15 | 样本文件「长文本.md」（LF）：把「DeepSeek 的离线 tokenizer 让 API 调用前的预算估算不必联网。」加一个换行，重复 2000 次；共 86000 个字符，UTF-8 占 154000 字节；官方口径为 38000 个 token |
| DATA-16 | 一份坏掉的打包 wheel：文件名与技能目录里那份相同（tokenizers-0.22.2-cp39-abi3-win_amd64.whl），内容是坏的（例如 0 字节的文件），用来让离线安装这一步失败 |
| DATA-17 | 正文样本「你好」：2 个字符，UTF-8 占 6 字节；官方口径为 1 个 token。用作 DATA-9 的对照 |
