# 测试用例规格说明

测试项：`plugin/skills/token-counter/scripts/count_tokens.py`。四门选定的技术共导出 36 个测试覆盖项（判定表测试 6 个、等价类划分 17 个、状态转移测试 7 个、场景测试 6 个），导出 21 条测试用例。

用到样本文件的几条（TC-2、TC-11、TC-13、TC-15、TC-21）另有一条共同前置条件：文件按测试数据需求里写明的字节数逐字节生成，行尾是 LF。换行符换成 CRLF，这几条的预期结果就不成立。

优先级按这样定：正文落在高风险的四类里（含空格、含中文、以汉字开头、含官方特殊 token），或用例专门用来钉计数口径的，为高；其余为中。一条用例顺带验证到的其他覆盖项不抬高它的等级。

## 二、测试用例

### （一）命令行与输入来源（TM-1 的判定规则）

这几条共用的前置条件：测试项与随技能分发的词表文件在位；机器上已经装好引擎（`tokenizers` 可以导入），因此这几条与安装无关。样本见测试数据需求。

| 唯一标识符 | 目标 | 优先级 | 前置条件 | 输入 | 预期结果 |
|:---|:---|:---|:---|:---|:---|
| TC-1 | 命令行直接给一段文本时按文本计数，中文文本的 token 数与官方词表一致 | 高 | 见上文共用前置条件 | 执行 `python count_tokens.py --text "你好，世界"`（样本 DATA-1） | 标准输出两行：`tokens: 3`、`chars: 5`；标准错误为空；退出码 0。这段正文在 UTF-8 里占 15 字节，`chars` 给的是 5，不是字节数 |
| TC-2 | 按文件计数，多行 Markdown 的 `tokens` 与 `chars` 与官方词表一致 | 高 | 见上文共用前置条件 | 执行 `python count_tokens.py 样本.md`（样本 DATA-7） | 标准输出两行：`tokens: 8`、`chars: 21`；标准错误为空；退出码 0 |
| TC-3 | 文件的字节不是合法 UTF-8 时不给计数结果 | 中 | 见上文共用前置条件 | 执行 `python count_tokens.py 坏字节.md`（样本 DATA-11） | 不出现计数行；标准错误上给出提示（措辞依据未规定，记录实际输出）；退出码非 0。若把这份文件当作空正文数出 `tokens: 0`，判为缺陷 |
| TC-4 | 文件路径不存在时不给计数结果 | 中 | 见上文共用前置条件 | 执行 `python count_tokens.py ./不存在的文件.md`（样本 DATA-12） | 不出现计数行；退出码非 0。若当作空正文数出 `tokens: 0`，判为缺陷 |
| TC-5 | 路径指向一个目录时不给计数结果 | 中 | 见上文共用前置条件 | 执行 `python count_tokens.py ./样本目录`（样本 DATA-13） | 同 TC-4：不出现计数行；退出码非 0 |
| TC-6 | 按标准输入计数，含空格的纯 ASCII 文本与官方词表一致 | 高 | 见上文共用前置条件；命令行能接管道 | 把恰好 11 个字节的 `hello world`（不带换行）接到标准输入（样本 DATA-2）：`printf 'hello world' \| python count_tokens.py` | 标准输出两行：`tokens: 2`、`chars: 11`；退出码 0 |
| TC-7 | 标准输入为空时给出 0，不报错 | 中 | 同 TC-6 | 把 0 个字节接到标准输入：`printf '' \| python count_tokens.py` | 标准输出两行：`tokens: 0`、`chars: 0`；标准错误为空；退出码 0 |
| TC-8 | 标准输入里的字节不是合法 UTF-8 时不给计数结果 | 中 | 同 TC-6 | 把样本 DATA-14 的字节序列接到标准输入 | 不出现计数行；标准错误上给出提示；退出码非 0 |
