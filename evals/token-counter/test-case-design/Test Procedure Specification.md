# 测试规程规格说明

三条规程，按落点分成两批：前两条判据落在命令、退出码与盘上的文件上，第三条要读一轮技能被调用时的表现。规程之间的先后照前置与后置条件排，排在下面各条的「与其他规程的关系」栏与文末那张表里。

## TP-1 脚本层常规路径

| 栏目 | 内容 |
|:---|:---|
| 唯一标识符 | TP-1 |
| 英文名 | script_layer_happy_path |
| 目标 | 把脚本那一层的来路、编码、文本内容、边界与异常一次跑完，判据全落在命令、标准输出与退出码上 |
| 风险等级 | 高 |
| 执行器 | 脚本（跑命令、比标准输出与退出码就有结论，不用模型） |
| 改动文件 | 只读（规程执行当中只读测试项与样本，不改它们） |
| 启动 | ENV-1、ENV-3、ENV-4、ENV-7 就位；按 DATA-6 至 DATA-12 把七个样本文件摆在同一个临时目录里；按 DATA-13 取一个不存在的路径、按 DATA-14 取技能目录本身；DATA-1 至 DATA-5 那五段文字按正文取用 |
| 有序执行测试用例 | TC-1、TC-2、TC-3、TC-4、TC-5、TC-6、TC-7、TC-8、TC-9、TC-10、TC-11、TC-12、TC-13、TC-14、TC-15、TC-16、TC-17、TC-18、TC-19 |
| 与其他规程的关系 | 要在 TP-2 与 TP-3 之前跑：它靠 ENV-4 那个已装好的引擎，跑的时候盘上还没有被别的规程动过。可以调换顺序的只有 TC-1 至 TC-14 这一段——这几条彼此没有依赖，谁先谁后都行；TC-15 至 TC-19 是异常与空档那几条，排在正常路径之后，出了问题好认是哪一类 |
| 停止与结束 | 把按 DATA-6 至 DATA-12 造的七个样本文件与那个临时目录清掉；测试项本身不动，盘上不留改动 |

## TP-2 引擎获取路径

| 栏目 | 内容 |
|:---|:---|
| 唯一标识符 | TP-2 |
| 英文名 | engine_acquire_paths |
| 目标 | 把判定表那三条规则各跑一遍：已装时不装、装不上打包 wheel 时离线装、打包 wheel 不可用时联网回落 |
| 风险等级 | 高 |
| 执行器 | 脚本（判据落在命令、标准输出、退出码，加上盘上装没装上引擎） |
| 改动文件 | 会写（规程执行当中会改目标机的 Python 环境：往干净环境里装引擎、动 `wheels/` 目录里的文件） |
| 启动 | ENV-1、ENV-3、ENV-7 就位；按 ENV-5 现建一个干净环境并确认它导入不了引擎；先记下 ENV-4 那个环境里引擎的版本号与安装位置，供 TC-20 比对；按 DATA-15 把那个假 wheel 备在 `wheels/` 外面——TC-22 那一步会自己把它放进去、跑完再挪出来 |
| 有序执行测试用例 | TC-20、TC-21、TC-22、TC-23 |
| 与其他规程的关系 | 要在 TP-1 之后跑：这一条会动 `wheels/` 与干净环境，排在只读的 TP-1 后面，省得两边互相扰。要在 TP-3 之前跑完并把盘上恢复原样。TP-2 与 TP-3 内部各条用例之间，除 TC-22 那一步的挪动之外没有依赖 |
| 停止与结束 | 把 DATA-15 那个假 wheel 从 `wheels/` 拿掉、把原来那个真的 wheel 放回去，恢复成启动之前的样子；删掉按 ENV-5 建的干净环境；确认 ENV-4 那个环境的引擎版本与安装位置仍是启动时记下的那个 |

## TP-3 技能被调用时的用法场景

| 栏目 | 内容 |
|:---|:---|
| 唯一标识符 | TP-3 |
| 英文名 | skill_usage_scenarios |
| 目标 | 把九条交互序列各走一遍，看技能被调用时怎么接、回话里有没有该有的那几句 |
| 风险等级 | 中 |
| 执行器 | 控制器（要模型跑，但模型只照判据读盘上的东西、按规则分流，不派子代理；整条规程在同一轮对话里跑完） |
| 改动文件 | 只读（规程执行当中只读测试项，不改它；TC-32 里脚本自己往干净环境装引擎那一步算搭场子，不动测试项本身） |
| 启动 | ENV-1、ENV-2、ENV-3、ENV-4、ENV-7、ENV-8 就位；按 DATA-6、DATA-8、DATA-12 备好样本；按 ENV-5 另建一个干净环境供 TC-32 用；DATA-1 与 DATA-5 那两段文字按正文取用 |
| 有序执行测试用例 | TC-24、TC-25、TC-26、TC-27、TC-28、TC-29、TC-30、TC-31、TC-32 |
| 与其他规程的关系 | 要在 TP-1 与 TP-2 都跑完之后跑：它要一个引擎可用、`wheels/` 未被挪动的环境，那两样由前两条规程摆好并恢复。规程内部 TC-24 至 TC-31 彼此没有依赖，可调换；TC-32 要在干净环境里跑，排在最后，免得它把环境弄脏影响前面几条 |
| 停止与结束 | 把按 DATA-6、DATA-8、DATA-12 备的样本清掉；删掉按 ENV-5 建的那个干净环境；测试项本身不动 |

## 各批落到哪

分批准则是判据落在哪：TP-1 与 TP-2 的判据全落在命令、退出码与盘上的文件上，跑一遍就有结论，归一批，落成能跑的测试代码；TP-3 的判据要读一轮技能被调用时的表现，归另一批，落成评测用例。分界落在规程边界上，没有把哪条规程劈开。

| 批次 | 规程 | 执行器 | 落到哪 | 用例目录名 | 说明 |
|:---|:---|:---|:---|:---|:---|
| 批一 | TP-1、TP-2 | 脚本 | `tests/token-counter/` 下的测试代码 |  | 判据落在命令、退出码与盘上的文件上。TP-2 那几条会改盘，落成的测试要把干净环境与 `wheels/` 的挪动与恢复一并写进去 |
| 批二 | TP-3 | 控制器 | `evals/token-counter/cases/` 下的用例配置 | tp03-01-TC-24-usage_count_file_tokens、tp03-02-TC-25-usage_report_tokens_only、tp03-03-TC-26-usage_other_model_declined、tp03-04-TC-27-usage_cost_estimate_caveat、tp03-05-TC-28-usage_special_token_counted、tp03-06-TC-29-usage_full_chat_request、tp03-07-TC-30-usage_undecodable_input、tp03-08-TC-31-usage_multiple_files_total、tp03-09-TC-32-usage_first_run_no_extra_step | 判据要读一轮技能被调用时的表现。这一批的用例按规程号加规程内位次编目录名，字母序就是执行顺序 |
