# 测试环境需求

测试环境项如下。头两条是测试运行环境——测试规程在哪儿跑、被测那侧在哪儿执行，都按默认口径取本机。

| 唯一标识符 | 英文名 | 测试环境项 | 描述 |
|:---|:---|:---|:---|
| ENV-1 | test_run_on_local | 测试运行环境：本机 | 测试规程在本机跑。测试项是一支离线脚本加一份技能正文，没有对外服务要连，不必另换机器或容器 |
| ENV-2 | system_under_test_host | 被测环境：本机 | 被测那侧（技能正文、计数脚本、随包分发的那份词表与引擎包）在本机执行，与 ENV-1 同一台。口径同 ENV-1 |
| ENV-3 | skill_copy | 技能副本 | `plugin/skills/token-counter/` 整套——`SKILL.md`、`scripts/count_tokens.py`、`tokenizer.json`、`wheels/tokenizers-0.22.2-cp39-abi3-win_amd64.whl`——按使用者机器上装好的样子摆在盘上，一字不改。脚本层用例从这份副本上跑；技能层用例把它按技能形态交给会话 |
| ENV-4 | interpreter_with_engine | 装了引擎的解释器 | 本机解释器：Python 3.13，能 `import tokenizers` 即可（版本不必是 0.22.2）。除另写明用 ENV-5 的几条以外，用例都用它 |
| ENV-5 | clean_interpreter | 干净解释器 | 一个没装那份引擎的解释器：在 `evals/token-counter/.clean-venv/` 下新建的虚拟环境（Python 3.13），开跑前确认 `import tokenizers` 失败。判定表规则 2、3、4 那几条用例、以及技能层干净机器那一轮用它；跑完删掉重建（见测试规程的「停止与结束」栏） |
| ENV-6 | package_index | 包索引可达 | 联网能取到钉住版本 0.22.2 的包索引。只有判定表规则 3、4 那两条用例用得着；开跑前拿 `pip download tokenizers==0.22.2 --no-deps` 试一次，能取到再开跑 |
| ENV-7 | run_records | 执行过程记录 | 技能层用例跑的时候，能拿到模型当轮的完整回复、它执行过的命令、以及它写下的文件——那一批的判据全落在「要读执行过程」上，拿不到记录就判不了 |
| ENV-8 | scratch_workspace | 临时工作区 | 一个可写的目录：按测试数据需求摆样本文件、放技能副本的拷贝（规则 3、4 那两条用）。跑完清掉，不留在库里 |

注：判定表里「打包那份装不上」这一条（规则 3）在脚本里有两个成因——目标平台与打包那份对不上，或者装的动作本身没成。本轮的运行平台与打包那份的目标平台一致（同一套 x64 的 CPython 3.13），平台对不上那一路在这一轮造不出来；测试用例用「装的动作没成」那一路（把包换成同名的坏文件）来代表规则 3，判定表里另注的那一路留待换到别的平台时再补。
