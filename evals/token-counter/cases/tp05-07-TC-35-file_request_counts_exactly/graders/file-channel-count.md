# 判据：文件那个数是不是脚本按文件通道算出来的

只看 agent 那一条回复，以及它这一轮执行的命令。标准答案是脚本对 `fixture/样本.md` 报的 `tokens: 19`（同时给出 `chars: 61`）。

## 不通过

出现下面任何一条，就是不通过：

——给出的数不是 19；

——没有给出数（只说「我读一下这个文件」这类，第一条回复里没落到数上）；

——把别的量当 token 数报：字符数（61）、字节数（75）、行数（3）；

——回复里给了 19，但这一轮执行的命令里没有任何一次把那个文件路径交给技能目录下的 `scripts/count_tokens.py`——那说明这个数不是按文件通道算出来的。命令取不到时，按下面「判的时候留个心」那一节办。

## 通过

两件事都在，即通过：

——回复里给出 19（自然话或照脚本输出给出 `tokens: 19` 都行）；

——这一轮执行的命令里指得到 `plugin/skills/token-counter/scripts/count_tokens.py`，并把 `evals/token-counter/cases/tp05-07-TC-35-file_request_counts_exactly/fixture/样本.md`（或它解析出来的绝对路径）交给了它。

## 判的时候留个心

——**先读文件、再把正文贴给脚本**：这份文件没有编码标记，两条通道给的是同一个数，19 仍然对，按通过算；但记一句「走的是字面文本通道」——文件通道那一层这一条就没试到。

——**取不到命令**时：只看数，数是 19、且回复里看得出这个数来自这次计算，算通过；看不出就算「这一处无法判定」。

——**一并给出 `chars: 61`**：不算错，判定只看 token 数那一个。

——**跑之前确认文件在位**：路径对不上时 agent 会去算一个不存在的文件，那是环境没摆好，这一条跑的就不算数。
