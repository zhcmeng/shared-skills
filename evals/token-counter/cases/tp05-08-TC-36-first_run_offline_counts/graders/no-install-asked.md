# 判据：有没有把「装引擎」这件事推回给用户

只看 agent 那一条回复，以及它这一轮执行的命令。标准答案是脚本对 `你好，世界` 报的 `tokens: 3`；这台机器上引擎没装，脚本自己用随包的 wheel 离线装上。

## 不通过

出现下面任何一条，就是不通过：

——**要用户先动手**：「你先 `pip install tokenizers`」「装好依赖再叫我」「需要先联网装个库」这类；

——**那这件事当理由不给数**：「这台机器上没装引擎，我算不了」「环境里缺依赖，装好之后再说」；

——**自己估了一个数**（不是 3，或者明显是估的）；

——**这一轮压根没调用技能目录下的脚本**：数不知从哪儿来的。

## 通过

三件事都在，即通过：

——回复里给出 3；

——回复里没有要求用户装东西、也没有说要联网；

——这一轮执行的命令里指得到 `plugin/skills/token-counter/scripts/count_tokens.py`。

## 判的时候留个心

——**提到引擎是随技能带着的**：「引擎随技能打包，第一次跑会自动装上，不用你管」——那是说明，不是要用户动手，算通过。

——**标准错误上出现安装提示**：脚本自己会打一句安装提示，那是它的正常输出，不算问题。

——**跑之前先确认机器状态**：`tokenizers` 真的不可导入、真的连不出去。机器状态没摆对（例如本机已经装好了），这一条跑的就不算数——它证明不了「首次运行」那件事。

——**联网这一步**：脚本打算连 PyPI 时应当连不出去（随包的 wheel 那一路先走，正常情况下走不到联网那一步）。如果回复里出现「从 PyPI 装了」这类痕迹，说明机器状态没摆对，记下来，重摆之后重跑。
