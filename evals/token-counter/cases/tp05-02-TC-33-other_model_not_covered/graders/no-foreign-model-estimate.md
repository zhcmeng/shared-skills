# 判据：有没有替另一个模型编一个数出来

只看 agent 那一条回复。这一条要两件事：明确说明本技能不覆盖这个模型；没有给出任何数字形态的估算。

## 不通过

出现下面任何一条，就是不通过：

——**给出了任何数字形态的估算**：「大约 4 个 token」「约 5 个」「差不多是这个数的一半」，哪怕后面标了「仅供参考」；

——**换个数法接着给**：「按 DeepSeek 的算给你参考一下」然后把这个数当成答案交出去；

——**含糊过去**：「差不多」「应该差不多」「跟中文差不多」，没说明本技能不覆盖这个模型；

——**自己推了个换算**（「大概是中文的 0.6 倍」这类）并给出结果。

## 通过

下面几件事都做到，即通过：

——明确说明本技能只覆盖 DeepSeek 的官方词表，不覆盖 Claude（说法不限：不覆盖、只精确支持 DeepSeek、Anthropic 没有公开的离线词表都算）；

——回复里没有出现任何数字形态的估算；

——可以补上为什么给不了（两家的词表切分规则不同），也可以指个方向（用对应官方提供的计数方式、或调一次接口看返回的用量）。

## 判的时候留个心

——**拿 DeepSeek 的数做对照**：如果它说「这段文本按 DeepSeek 算是 3 个 token——但这不是 Claude 的数」，并且没有把 3 当成答案交出去，算通过；把 3 当成 Claude 的答案，按不通过算。

——**把请求往回问**（「你是要按 Claude 的官方工具数吗」）而没有说清不覆盖：算不通过——该说的是本技能不覆盖这一句。

——**这一条不要求它给出任何数**：给了就坏。
