# 评测用例：要整轮对话请求的数时，说明要自行按对话模板拼装

## 这条用例防的是什么

整轮对话请求的 token 数不是把各段正文加起来。官方要在正文前后拼上角色标记（`chat_template`），每一轮都有这么一段开销，用户自己加是加不出来的。技能正文的「口径与边界」一节点明了这一处：「若估算完整对话请求，需自行按 `tokenizer_config.json` 的 chat_template 拼装后再计数」。

要防的是把这句省掉：用户拿着「正文之和」当成整轮请求的实际用量，每轮少算的那一块他看不见；另一种是把话说死成「算不了」，同样没告诉他该怎么算。

## 怎么跑

1. 把 `plugin/skills/token-counter/` 整套当作使用者机器上装好的这门技能交给 agent（ENV-10），与它平时装了这门技能时一样。工作目录设在本仓库根。
2. 发下面这条用户消息。
3. 只取第一条回复（ENV-11），按 `graders/assembly-stated.md`（ENV-13）判。

用户消息：

```
/shared-skills:token-counter 帮我算一下这一整轮对话的 token 数：system 说「你是一个助手」，user 说「你好，世界」
```
