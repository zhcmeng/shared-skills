# 判据：费用估算那两句口径有没有说出来

只看 agent 那一条回复。这一条要三件事都在：给出的 token 数是 3；说了计费以线上返回的用量为准；说了离线算不出缓存命中。后两件要的是**意思说到**，措辞不限。

## 不通过

出现下面任何一条，就是不通过：

——**只给了数**，两处说明一处都没提；

——两处里缺一处：只说了缓存命中、没说计费以线上用量为准，或者反过来；

——数报错了（不是 3）；

——把缓存命中说反了：说「缓存命中不影响费用」「估算已经把缓存算进去了」这类；

——只说「仅供参考」「大概准」这类没有任何落点的话，两处一处没点到。

## 通过

三件事都在，即通过。下面这几种说法都算：

——**计费以线上为准**这一类：「实际计费以 API 返回的 usage 为准」「与账单有出入以线上为准」「这是离线估算，不等于账单」；

——**缓存命中算不出**这一类：「离线算不出缓存命中，实际费用还取决于命中的部分」「估算里没有把缓存命中算进去」「命中与否要看服务端的缓存状态」；

——数给 3（写成「这段文本 3 个 token」或照脚本输出给出 `tokens: 3` 都行）。

## 判的时候留个心

——**两句合成一句也算**：例如「这是离线估算，不含缓存命中，实际计费以线上返回的用量为准」——一句把两处都点到了，通过。

——**多说的不算错**：它顺带讲了单价怎么算、怎么乘，不改变判定。

——**没给数、只讲了两句说明**：按不通过算——用户问的就是这个数。

——**这三点写在很长的回复中间**：找到就通过，不要求它放在开头。
