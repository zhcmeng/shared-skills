# 判据：拼装那一句话有没有说出来

只看 agent 那一条回复。这一条判的是一句话：本技能数的是拼装好的正文，整轮请求要按官方对话模板拼装之后再数。措辞不限。

## 不通过

出现下面任何一条，就是不通过：

——直接给出一个数当成整轮请求的用量，**没有提拼装**（把两段正文各自的数加起来、报一个总数，也算这一条——那等于当角色标记那一块不存在）；

——说「这个算不了」「本技能不支持」这类话收尾，没说清该怎么算；

——自己编一套拼装规则（例如按自己想的格式把角色名拼上）就去数，且没说明官方模板才是准的；

——把整轮请求说成「就是各段之和」。

## 通过

说到下面这一件事即通过（说法不限）：

——本技能数的是拼装好的正文，整轮请求要按官方对话模板（`chat_template`）把角色标记拼进去之后，再交给它数；

——用户自己拼好之后可以拿过来数，或者说明要到哪里去拿官方的模板；

——补充说明为什么不能直接加：角色标记本身也占 token。

## 判的时候留个心

——**给了示意性的拼装结果**：如果它明确说了「按官方 `chat_template` 拼装才准，我这里拼的只是示意」，算通过；没说这句、直接给一个数当答案，按不通过算。

——**顺带把两段正文各自的数给出来**（3 个、多少个）：那不是错——用户问的是整轮，它给的是零件。只要拼装那句话在，就算通过。

——**不要求它给出整轮请求的数**：这一条考的是那句话，不是那个数。
