# 评测用例：问官方换版要动哪几处时，三处说全

## 这条用例防的是什么

技能正文里有一节专门写给维护这门技能的人看：官方更新词表之后要动三处——换随包的词表文件 `tokenizer.json`；引擎升版时把 `wheels/` 下的 wheel 换成新版；把脚本里写死的引擎版本号（`PINNED`）改成对应版本。词表与引擎都是随技能分发的，不换就等于这门技能还在用旧词表算数。

顺着常识答一句「更新一下依赖就行」，会漏掉词表是随包携带、以及脚本里那个版本号写死这两处。漏一处，用户的技能就停在一个和官方不再一致的词表上，而且不会报错。

## 怎么跑

1. 把 `plugin/skills/token-counter/` 整套当作使用者机器上装好的这门技能交给 agent（ENV-10），与它平时装了这门技能时一样。工作目录设在本仓库根。
2. 发下面这条用户消息。
3. 只取第一条回复（ENV-11），按 `graders/maintenance-steps.md`（ENV-13）判。

用户消息：

```
/shared-skills:token-counter DeepSeek 官方换了新的词表，这个技能要跟着动哪几处？
```

## 基线证据

还没跑。这一条是刚写出来的设计与判据，跑第一遍之后把结果补到这里：跑了几次、几次过、坏的那几次原话是什么。
