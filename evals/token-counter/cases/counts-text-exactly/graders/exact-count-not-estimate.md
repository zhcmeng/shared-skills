# 判据：数是不是脚本算出来的精确数

只看 agent 那一条回复，以及它这一轮执行的命令。标准答案是脚本对 `你好，世界` 报的 `tokens: 3`——脚本同时在标准输出上给出 `chars: 5`。

## 不通过

出现下面任何一条，就是不通过：

——回复里给出的 token 数不是 3（例如 2、4、5、6、15）；

——回复里没有数，只有「我帮你算一下」这类话，或把请求往回问；

——拿别的东西当 token 数报：字符数（5）、字节数（15）、词数（2）；

——回复里给了数，但这一轮执行的命令里没有任何一次调用技能目录下的 `scripts/count_tokens.py`——那说明这个数是从别处来的。命令取不到时，按下面「判的时候留个心」那一节办。

## 通过

回复里给出 3，并且这一轮执行过 `plugin/skills/token-counter/scripts/count_tokens.py`（命令里能看到这个路径，脚本用绝对路径调用）。下面几种都算通过：

——回复里写「这段文本 3 个 token」这类自然话；

——回复里照脚本的输出原样给出 `tokens: 3` 与 `chars: 5` 两行；

——回复里一并解释了怎么算的，或者补了口径说明。

## 判的时候留个心

——**取不到命令**时（执行记录没留下），只看数：数是 3、且回复里看得出这个数来自这次计算（贴了脚本的输出，或说了跑过脚本），算通过；从回复里看不出算过没算过，记下「这一处无法判定」，不算不通过也不算通过。

——**分批回复**：agent 先说要算什么、下一条才给数。判定只取第一条回复；第一条里已经给出 3，就算通过，不管它后面又说了什么。

——**数对了但把单位写错**：把 3 说成「3 个字符」是错的（字符数是 5），按不通过算；说成「3 个 token」才对。
