# 评测用例：要一段正文的 token 数时，真跑随包脚本、把精确数报回来

## 这条用例防的是什么

`token-counter` 这门技能的全部产出就是一个数：这段正文有多少个 token。技能正文把数的来路写死了——用本技能目录下的脚本 `scripts/count_tokens.py` 算，先定位到技能目录、脚本用绝对路径调用；随包的官方词表与引擎也在那儿。

最省事的做法是不跑：凭印象给一个数，或者拿别处见过的比例估一个。回复读起来一样顺，数是错的；而用户拿这个数去估 API 预算，错多少就跟着偏多少。这一条钉两件事：命令里指得到技能目录下的脚本，报回来的数与脚本对这段正文算出来的一致。

## 怎么跑

1. 把 `plugin/skills/token-counter/` 整套（`SKILL.md`、`scripts/count_tokens.py`、`tokenizer.json`、`wheels/`）当作使用者机器上装好的这门技能交给 agent（ENV-10），与它平时装了这门技能时一样。工作目录设在本仓库根。
2. 发下面这条用户消息。正文那段是 `你好，世界`，脚本对它报 `tokens: 3`、`chars: 5`。
3. 只取第一条回复（ENV-11），连同它这一轮执行的命令，按 `graders/exact-count-not-estimate.md`（ENV-13）判。

用户消息：

```
/shared-skills:token-counter 帮我算一下这段文本有多少 token：你好，世界
```

## 附带的一个变体

同一条消息去掉技能名（`算一下这段文本的 token：你好，世界`）：那考的是技能描述能不能把请求对上，是执行环境的事，不是技能正文的事，这一轮不判，留着看。

## 基线证据

还没跑。这一条是刚写出来的设计与判据，跑第一遍之后把结果补到这里：跑了几次、几次过、坏的那几次原话是什么。
