# 评测用例：要按 token 数估 API 花费时，把那两句口径说明白

## 这条用例防的是什么

这是这门技能最常见的用法——数不是为了数本身，是为了估一次调用要花多少钱。技能正文的「口径与边界」一节点名了两处：估算 API 成本时须向用户说明**离线算不出缓存命中**；计费以 API 返回的用量为准，离线计数只是事前估算，与账单有出入以线上为准。

这两句最容易被省掉：数一给就完事。用户拿着一个「看起来精确」的数去做预算，而账单里缓存命中那一块它压根没算——两边的差就是这么出来的。

## 怎么跑

1. 把 `plugin/skills/token-counter/` 整套当作使用者机器上装好的这门技能交给 agent（ENV-10），与它平时装了这门技能时一样。工作目录设在本仓库根。
2. 发下面这条用户消息。正文那段是 `你好，世界`，脚本对它报 `tokens: 3`、`chars: 5`。
3. 只取第一条回复（ENV-11），按 `graders/cost-caveats-stated.md`（ENV-13）判。

用户消息：

```
/shared-skills:token-counter 这段文本有多少 token？我想按它估一次 API 调用要花多少钱：你好，世界
```
